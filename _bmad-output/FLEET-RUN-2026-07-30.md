## Findings this run produced

### 1. Implementations die at escalation, and only transcripts survive

mason 1.2 escalated after a full green implementation (36/36 tests). The revert left
**nothing in git**: reflog held only the worktree-creation entry, the story branch was
0 commits ahead, `restore_patch: null`. Recovery came from **Claude Code session
transcripts** — and the parent transcript alone was misleading: it showed 17 Write/Edit
calls, *all to the spec*. The implementation was in the **subagent** transcripts
(`<session-id>/subagents/*.jsonl`), because a subagent's writes land in its own file.
Replaying Writes then Edits in timestamp order reconstructed 407 lines across 3 files,
verified genuine by finding the exact disputed `print_help()`/`EXIT_USAGE` pair in it.

This is the warden spec-loss lesson one layer down: not "specs die at teardown" but
**"implementations die at escalation."**

The recovery is now **superseded** — mason re-implemented 1.2 against the corrected
contract and it merged as `11ccfd2b11` (3 files, +475/-24). Verified the amendment landed
exactly as scoped, and *only* as scoped:

```python
if not ns.noun:                          # true bare invocation
    parser.print_help()                  #   -> stdout, EXIT_OK      (unchanged)
    return EXIT_OK
...
if not getattr(ns, "verb", None):        # noun with no verb
    ns._noun_parser.print_help(file=sys.stderr)   # -> stderr, EXIT_USAGE  (amended)
    return EXIT_USAGE
```

So the recovery's value was diagnostic, not restorative: it proved the reverted work had
been real and complete, and it gave a reference to diff the re-implementation against. The
4.28M weighted tokens of the first attempt were genuinely re-spent (7.88M for the clean
pass) — `--restore-patch` could not save them.

`--restore-patch` cannot help: bmad-loop refuses it under `scm.isolation = "worktree"`
("the re-drive discards and re-mounts the unit's worktree, so an in-place restore has
nothing durable to land on"), which is the config the whole fleet runs. So the recovery
path for any escalation or crash is transcript reconstruction, full stop.

### 2. A shipped feature stalled the next story, invisibly

scribe 1.2 wired `CLAUDE.md` to import `.claude/memory/MEMORY.md`. It merged; 1.3's fresh
worktree was seeded from that branch; the new session hit the Claude CLI's
**"Allow external CLAUDE.md file imports?"** consent prompt and sat there **74 minutes**.

- `bmad-loop status` read `dev-running` the entire time.
- The supervisor's stall ladder (`dev_stall_grace_s = 600`, `dev_stall_nudges = 2`) never
  fired — 74 minutes is seven grace periods.
- The **only** signal was log mtime going cold while five sibling stations wrote every second.

Cleared by hand with `tmux send-keys 1 Enter`. It will recur on every story in any station
whose `CLAUDE.md` imports team memory. Same family as the folder-trust prompt, and the
same blind spot: an interactive prompt is indistinguishable from work in progress.

### 3. Two silent dev-session crashes in the concurrent-launch window

herald 1.3 (both attempts) and scribe 1.2 (attempt 1) died mid-thinking with **no error
text**, logs ending on a spinner frame. Ruled out: OOM (39 GiB free, no kernel records),
timeout (~6-7 min against a 180-min ceiling), environment fault (`env_fault: false`).
Both occurred while six fleets were starting simultaneously; 27 `claude` processes were
live. Suggestive, not proven.

Worth flagging separately: herald's attempt 2 shelled out to a **nested `claude -p`** to
reach the `claude-design` MCP, still reporting `Running…` at **6m22s under a `timeout 90`**
that never fired. Bad pattern regardless of whether it caused the crash — it burns budget
invisibly and outlived its own kill switch. herald is the deck station, so it is the one
station whose stories pull on Claude Design.

### 4. The token ceiling is advisory, confirmed by observation

scribe's journal carries `token-budget-exceeded` for 1.2 at **2,485,489 weighted against
the 2,000,000 cap** — the event fires and `session_budget_mode = "warn"` means it only
logs. Nothing stops. Marshal 1.4 alone reached 14.18M.

### 5. The review is doing real work

Eight of nine merged stories needed a second or third review round; only scribe 1.2 passed
on the first. Review is roughly half the token spend. mason 1.2 is the strongest evidence:
the reviewer found the **intent contract itself** was wrong (an I/O matrix row specifying
a usage error print to stdout, contradicting the same command's sibling usage-error path
and the spec's own stream-discipline rule), and the harness **refused to let the agent
amend its own contract** — routing it as `intent_gap` requiring human confirmation. That
is AD-27's narrowing principle enforced in the harness rather than merely written down.

## Operator note

**Never wrap a bmad-loop driver command in `timeout`.** `resolve --resume` *is* the engine
driver; a `timeout 300` SIGTERM'd mason's run mid-re-arm, rolling state back to
`escalated`/`rearmed: False` and costing ~15 minutes. `timeout` is safe only for commands
that return on their own (`status`, `--dry-run`, `--help`). Detached tmux for everything else.
