## Intent

**Problem:** Story 27.1's site groups pages by quadrant, with Starlight's alphabetical autogenerate. The shelf already has a registry with an explicit page order: doctor's `docs/map.yaml` (Story 30.2). `docs/MAP.md`'s page registry is rendered from it, and `docs-map-hygiene` fails a quadrant page it omits. Upstream BMAD-METHOD orders its sidebar with per-page `sidebar.order` frontmatter. Copying the order into 60 pages would make a second registry, and five of those pages are `kind: generated` by doctor- and steward-owned scripts that docs-currency checks byte for byte.

**Approach:** Add one local generator, `docs-site/scripts/sidebar_from_map.py`, that reads `docs/map.yaml` and writes the Starlight sidebar as gitignored JSON at build time: one group per quadrant, items in `map.yaml` order, and each quadrant's `README.md` as its group index. `astro.config.mjs` reads that JSON. A `--check` mode fails on a mapped page with no file, a quadrant page missing from the map, or a page listed twice (CAP-52 D1, AD-21).

## Boundaries & Constraints

**Always:**
- `docs/map.yaml` is read, never written. Its schema is doctor's (`docs-map-schema.json`); the generator needs only `pages[].path` and `pages[].quadrant`, and names any page it cannot resolve.
- The generated JSON is gitignored and regenerated by every `docs-site-build`, so git never holds a stale copy.
- `pixi.toml` changed: run `pixi run -e pyforge-guild pyforge-station-tests` first; regenerate `environment.yaml` (expected byte-identical).
- Before landing, reconcile each co-governor: add a memlog entry on every Spec that `spec-surface-check` names, `git add`, run one scoped stamp per named Spec, re-check, and read the exit code.
- The PR carries the `maintenance` label.

**Never:**
- Do not write `sidebar:` or `sidebar.order` frontmatter into any page under `docs/`.
- Do not edit `docs/map.yaml`, `docs/MAP.md`, or anything under `src/shared/packages/pyforge-doctor/` (Kinship: doctor 30.2).
- Do not edit a vendored upstream file.

**Type:** feature • **Effort:** S • **Deps:** S-27.1 • **FR/AD:** spec-pyforge-herald CAP-52 (FR-8.3; D1); AD-21 • Kinship: doctor 30.2 owns `docs/map.yaml` and its schema; this story only reads it

**Surface:**
- `docs-site/scripts/sidebar_from_map.py` (new, local). It reads `docs/map.yaml` and writes `docs-site/src/sidebar.generated.json`:
  - one group per quadrant, in the order the quadrants first appear in `map.yaml`
  - each item a page slug, in `map.yaml` order
  - a quadrant's `README.md` as its group index
  - `--check` exits 1, naming the page, when a `map.yaml` path has no file, when a quadrant page is missing from `map.yaml`, or when a page is listed twice
- `docs-site/astro.config.mjs`: the sidebar is read from the generated JSON; the per-quadrant autogenerate from 27.1 is removed.
- `pixi.toml`: a `docs-site-sidebar` task in `[feature.site.tasks]`, which `docs-site-build` depends on.
- `.gitignore`: `docs-site/src/sidebar.generated.json` (generated, never tracked).
- `src/shared/packages/pyforge-herald/tests/unit/test_docs_site_sidebar.py` (new). It imports the generator by path and checks:
  - order is preserved
  - swapping two fixture entries swaps the output
  - a missing page, an unmapped page or a duplicate exits 1
  - the live `docs/map.yaml` generates with no finding

**Given** 27.1's sidebar is autogenerated per quadrant (alphabetical), while `docs/map.yaml` is the shelf's registry with an explicit page order
**When** `pixi run -e site docs-site-build` runs (it regenerates the sidebar first)
**Then** the built sidebar lists every `map.yaml` page exactly once, grouped by quadrant, in `map.yaml` order; swapping two entries in `map.yaml` alone swaps them in the built sidebar; no page under `docs/` gains a `sidebar:` key
**And** `docs-currency-check` and `docs-map-hygiene-check` report no new finding; `test_docs_site_sidebar.py` passes in `pyforge-herald-test`
