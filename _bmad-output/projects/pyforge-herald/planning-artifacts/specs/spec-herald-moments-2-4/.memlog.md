topic: Herald's Proclamation Surfaces (Moments 2–4)
updated: 2026-08-01T19:21
---

- (capability) CAP-1: Progress Visibility Surface — Herald Moment 2. Surface showing what changed, what it cost (compute, tokens, time), what it unblocked. Triggered weekly/monthly or on shipping events. Automation: extract from sprint-status ledger, bmad-loop journals, and PRD updates.
- (capability) CAP-2: Success Proclamation Surface — Herald Moment 3. Surface claiming project completion with evidence: tests passing, metrics green, user adoption data. Triggered on shipping milestone. Automation: linked to PR close + test results + dashboard metrics.
- (capability) CAP-3: Operations Proclamation Surface — Herald Moment 4. Surface for deprecations, security fixes, end-of-life notices. Automation: triggered on manual notice authoring + archive/redirect rule generation. No fabricated claims; all notices backed by evidence.
- (constraint) Integration: All three Moments must integrate with Herald CLI and Herald web surface. No separate platforms; unified UI surface.
- (constraint) Automation triggers: Moment 2 weekly/on-ship, Moment 3 on-PR-close, Moment 4 on-notice-author. Each must have explicit automation rule.
- (constraint) Evidence requirement: Moment 3 and 4 claims must be backed by retrievable evidence. No claims without proof links.
- (decision) Scope decision: This spec addresses surface design only (Moment 2, 3, 4 entry points + automation rules). Implementation in separate stories.
- (question) Orchestration: Implement Moments 2, 3, 4 as separate stories within Herald, or as coordinated sub-stories within one epic? Decision needed before epics.
- (decision) DECISION: Coordinated epic approach. Moments 2–4 implemented as 6–7 coordinated sub-stories within one epic. Rationale: shared CLI/web/automation infrastructure, testing simplification, Herald precedent (Moment 1 was unified, not incremental), priority on integration correctness over velocity-to-first-value.
- (decision) DECISION: Moment 2 automation trigger = on-ship event + weekly fallback Thursday 2300 UTC. Ensures progress visible after shipping + guaranteed weekly cadence even if no shipping events.
- (decision) DECISION: Moment 3 automation = auto-extract on PR-close + passing gates. Herald extracts test results from CI, metrics from dashboard, adoption signals from downstream PRs. Operator reviews + approves before publish. Rationale: reproducibility, deterministic claim generation, operator review gates quality.
- (decision) DECISION: Moment 4 archive indexing = simple date/category index (YYYY-MM folders + category tags). No full-text search backend. Rationale: <100 notices expected; date/category is dominant query; manual search acceptable at scale; full-text can be added later without data migration.
