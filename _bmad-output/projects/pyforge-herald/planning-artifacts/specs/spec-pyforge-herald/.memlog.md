- (constraint) Story 1.3 (fallback transport adapter) AMENDED 2026-07-31 with a hard constraint: the nested agent process is NEVER actually spawned during development or in any test. `AgentSdkTransport` must take its process-launch seam as an injected dependency so every test drives it with a stub. Added after BOTH prior dev attempts (run 20260730-192235-062b) died mid-thinking with no error text — OOM, session timeout and env fault each ruled out by direct check — and attempt 2's log showed a real `claude -p` still `Running…` at 6m22s under a `timeout 90` that never fired.
- (note) The root of it is that this story's SUBJECT is a nested Claude Code invocation and its IMPLEMENTER is a Claude Code session. Asking an agent session to spawn an agent session is the one thing the story requires and the one thing that reliably kills the session doing the asking. Its branch carries ZERO commits across two attempts — the only deferral of the 2026-07-30 fleet run with genuinely nothing to recover, confirmed by `git fsck --no-reflogs` over the same window (every dangling commit there belongs to a story that already merged).
- (decision) Injecting the launch seam is not a workaround, it is the AD-4-shaped design — the impure edge belongs behind a port — so the constraint makes the story both survivable and better factored. Protocol conformance, the tool allowlist, the determinism boundary and `serve_url` stripping are all assertions about what the adapter SENDS and RETURNS, none of which needs a live subprocess. Live verification against a real nested agent is deferred to an operator-run integration check, outside the loop. Narrowing a story's surface is what AD-27 permits a spec to do.
