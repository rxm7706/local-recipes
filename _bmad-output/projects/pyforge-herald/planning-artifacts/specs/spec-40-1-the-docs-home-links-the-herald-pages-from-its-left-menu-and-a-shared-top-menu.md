## Intent

**Problem:** since the unified Pages artifact (CAP-52, AD-21; landed 2026-10-08), `https://rxm7706.github.io/local-recipes/`
is the Starlight docs shelf, and docsite's whole output (the dossier, infographics and deck families) lives under
`/herald/`, with the Kedro-Viz export at `/dashboard/kedro-viz/`. Measured on the live site 2026-10-12:

- **The docs left menu** has four first-level groups: Tutorials, How-to, Reference, Explanation. It is generated by
  `docs-site/scripts/sidebar_from_map.py` from `docs/map.yaml` (`_QUADRANTS`) into `docs-site/src/sidebar.generated.json`.
- **The docs header** carries the title, search and the theme toggle, and no navigation (`docs-site/astro.config.mjs`
  overrides no Starlight component).
- **The root's links.** Among herald pages it links only `how-to/presentation-deck/` and
  `how-to/run-herald-live-backend-locally/`. Nothing links `/herald/`, `/herald/dossier/`, `/herald/infographics/`,
  `/herald/decks/` or `/dashboard/kedro-viz/`.
- **Herald's top menu** comes from `docsite/content/site.yml`: `nav` (Overview, Dossier, Infographics, Decks) plus
  `neighbours` (Kedro-Viz), rendered with a `rel` prefix by `docsite/templates/shell_page.html.j2`. It has no link to
  the docs.

The operator, reading the site: "is now docs - which is fine, but where did everything else go".

**Approach:** keep herald's `docsite/content/site.yml` as the one navigation list and add a Docs entry to it. The docs
site reads that list at build time, as data, and renders it twice: as a fifth first-level sidebar group, **Herald**,
after the four quadrants, and as the top menu in a Starlight `Header` override. Herald's shell renders the same list
with Docs first. Every link is built from the configured base path (`getSiteUrl()` on the docs side, the herald `rel`
prefix plus the mount on the herald side), so the menus resolve on the public host and on a CAP-56 second host.
`pages-check` gains a check that every menu link resolves to a file inside the artifact.

## Acceptance Criteria

- **AC1 — The left menu.** In the built artifact, the docs root's sidebar lists, at the first level and in this order:
  Tutorials, How-to, Reference, Explanation, Herald. Herald holds, in this order: Overview (`herald/`), Dossier
  (`herald/dossier/`), Infographics (`herald/infographics/`), Decks (`herald/decks/`), Kedro-Viz (`dashboard/kedro-viz/`).
  The four quadrants and their pages are unchanged from `docs/map.yaml`.
- **AC2 — The shared top menu.** Every docs page and every herald page (the overview, the dossier, the infographics
  gallery, the deck family index and each deck family page) renders a top menu of six links in this order: Docs,
  Overview, Dossier, Infographics, Decks, Kedro-Viz. On a herald page, the current page's link carries
  `aria-current="page"` as it does today.
- **AC3 — One list.** Both menus come from `docsite/content/site.yml`. A test adds an entry to the list in a fixture and
  shows it in the generated docs sidebar group, in the docs top menu and in the herald top menu, with no other edit. A
  test fails if the docs site hardcodes any of the six labels or targets.
- **AC4 — Every host.** Every menu href resolves to a file in the artifact:
  - under the public site URL (`https://rxm7706.github.io/local-recipes/`);
  - under a fixture second-host site URL and base path (CAP-56), with no `/local-recipes/` literal left in a menu href.
- **AC5 — The gate.** `pixi run -e site pages-check` exits 1 naming the page and the href when any menu link does not
  resolve inside the artifact, and exits 0 on the real build.
- **AC6 — Mutation.** Each change below makes a named test or `pages-check` fail:
  - break one href in `site.yml`;
  - drop the Herald group from the generated sidebar;
  - hardcode `/local-recipes/` in the docs top menu and build with the fixture second-host base;
  - remove the Docs entry from `site.yml`.
- **AC7 — Nothing else moves.** No page changes path, no `/herald/` path changes, the former-root redirects (CAP-52)
  are unchanged, and `validate-doc-links.js` and `validate-sidebar-order.js` pass unchanged.

## Boundaries & Constraints

**Always:**
- Keep `docs/map.yaml` the source of the quadrant order. The Herald group is appended after it by the generator, never
  hand-written into `sidebar.generated.json`.
- Read `site.yml` as data from the docs site, and never import herald or docsite code there (AD-21).
- Keep the herald `rel` prefix discipline, so every link resolves at every depth under `/herald/`.
- Read every verdict from the exit code, never through a pipe.
- Reconcile every governed path on the memlogs of the Specs that govern it, then stamp scoped (AGENTS.md pre-PR item 5).

**Never:**
- Never move a page, a deck or the Kedro-Viz export, and never add a second Pages artifact or deploy caller (AD-21).
- Never add a runtime cross-origin call; plain navigation links only (AD-21's 2026-09-28 amendment).
- Never edit the upstream validators to make them pass.

**Residual risk:**
- The infographic pages carry their own fixed back-bar (`BACKBAR` in `docsite/build.py`: All infographics, Overview,
  Dossier). It is not the site top menu, and this story leaves it unchanged.
