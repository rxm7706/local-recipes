## Intent

**Problem:** Three compiled station skills predate the code their stations shipped on 2026-11-25. Each has an open row in its own station's deferred-work ledger, left open because a compiled skill is regenerated by its own tool:

1. `DW-doctor-62-1-1`: `.claude/skills/pyforge-doctor/active/pyforge-doctor/SKILL.md` (the `flags kill-switch` passage, lines 88-93) does not say the reason is printed on the result line or that a tree whose directory cannot take the replacement is a named refusal at exit 2, and its source anchor for `_run_flags` has shifted (doctor Story 62.1).
2. `DW-herald-54-1-1`: `.claude/skills/pyforge-herald/0.1.1/pyforge-herald/SKILL.md:90` (served as `active/`) says `deck pull --commit` "stages and commits `presentations/<slug>/` and the bridge-state file"; since herald Story 54.1 it commits `presentations/<slug>/` alone, the bridge-state file under `.herald/` is ignored and never committed, the etag is recorded after the commit, and a deck that already matches HEAD is reported as `(nothing to commit)`.
3. `DW-scribe-35-1-1`: `.claude/skills/pyforge-scribe/active/pyforge-scribe/SKILL.md:78-89` says recall withholds a node committed after `compiled_at` "where the store keeps one; the flat-file store does"; since scribe Story 35.1 every shipped store keeps the compile time (flat file, PostgreSQL, plane), and the citation range for `models.py` predates that story's edit.

**Approach:** One `skf-update-skill` run per station, by the route steward Story 126.5 took on 2026-11-18 and the team-memory note records: run the workflow from the module copy `_bmad/skf/skf-update-skill`; seed `forge-data/<skill>/<version>/provenance-map.json` from the tracked package copy with each `source_file` made relative to `source_repo` and `file_entries: []` added; keep `scripts_intent: none` and `assets_intent: none` in each station brief and pass both to the detect step; write the tracked `provenance-map.json` as the new map with `source_repo` prefixed to each `source_file`; set `confidence_tier`, `tool_versions` and `source_commit` in `metadata.json` to the run's facts; follow with `skf-export-skill` (the `AGENTS.md` block, `.export-manifest.json`, the result record). Then an independent reader, not the one who ran the tool, checks each rebuilt `SKILL.md` against the live `--help` and the source, and its findings are applied through the tool. The skills catalog is regenerated and each of the three rows is closed in its own ledger.
