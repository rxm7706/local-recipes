## Intent

**Problem:** There is no single path from a bare machine to a working one. `docs/how-to/bootstrap-a-machine-with-steward.md` covers `init`, `setup`, `initrepo`, `validate-fast`, `shell-init` and `session check`, and its sample output shows the podman failure as normal. `docs/tutorials/getting-started.md` is recipe-first. `docs/tutorials/local-platform-development.md` starts the platform servers by hand. `docs/how-to/ocp-cluster-bringup.md`, `docs/how-to/host-nebari.md` and `docs/how-to/run-and-read-pr-preflight.md` each cover one shape. The compiled steward skill describes `init` as a four-tool check.

**Approach:** One tutorial, `docs/tutorials/onboard-a-machine.md`, in the tutorial structure of the documentation style guide (`bmad-os-diataxis`): a hook, What You'll Learn, a Prerequisites admonition, a Quick Path tip, an "Understanding the profiles" table, Step 1 desktop, Step 2 container, Step 3 pod, ocp or nkp, What You've Accomplished, a Quick Reference, Common Questions, Getting Help and Key Takeaways. Each step runs `steward init --profile <name>`, reads the remedies (which are the operator's and which an agent may run), and re-runs to a verdict. Every command is run on this machine and its real output is pasted. Where this laptop cannot reach a profile, the page shows the real `NOT READY` report and says that is what it is.

Frontmatter: `sources:` name `src/shared/packages/pyforge-steward/src/pyforge/steward/bootstrap.py`, `machine.py`, `session.py`, `cli.py`, `docs/governance/machine-readiness.yaml`, the Spec's `contract.md`, `scripts/platform-ci-local.sh`, `src/platform/compose/compose.yml` and `pixi.toml`; `verified:` is the date the commands were run.

The page is registered in `docs/map.yaml` (`path: tutorials/onboard-a-machine.md`, `quadrant: tutorials`, `owner: steward`, `kind: authored`) and `docs/MAP.md` is regenerated by `docs-map-render`. `docs/tutorials/README.md` links it. `docs/how-to/bootstrap-a-machine-with-steward.md` has its step 1, its duty table and its "How to tell it worked" rewritten for profiles, the podman sample removed, and a link to the tutorial. `getting-started.md` (Step 3), `local-platform-development.md` (Prerequisites) and `run-and-read-pr-preflight.md` each gain one line that points to it.

The steward station skill is regenerated with `skf-update-skill`, by the route of steward Story 126.5 and the team-memory note on that run, followed by `skf-export-skill`, so its `init` line, its CLI block and its duty table match the live `--help`. An independent reader checks the rebuilt `SKILL.md` against the live `--help`.

## Boundaries & Constraints

**Always:**
- Paste output a command really printed on this machine, with the date in `verified:`; never write output from memory or from the design.
- Say of every remedy on the page whether it is the operator's or an agent may run it, as the verb prints it.
- Regenerate `docs/MAP.md`, the skills catalog and the compiled skill through their own tools; keep the skill's `[MANUAL]` blocks byte-identical.
- Append the surface reconcile to the memlog of every Spec that governs a page this story edits (the surface baseline lists `docs/how-to/bootstrap-a-machine-with-steward.md` under `spec-pyforge-doctor`) before the scoped stamps.
- Read every verdict from its exit code, never through a pipe.

**Never:**
- Never paste a token, a password, a pull secret, a home-directory path that names the operator, or an email address into the page.
- Never install software, sign in or start a cluster to make a step read `READY`; the page shows the machine as it is.
- Never hand-edit the compiled skill, `docs/MAP.md`'s generated section or `docs/reference/skills-catalog.md`.
- Never restate a version in the tutorial that a tracked file already declares; point to the row or the file.
