- (direction) Operator scope decision 2026-08-09: a REUSABLE PATTERN other dashboards adopt. NOT a hardening of pyforge-atlas's existing Vizro board, NOT a standalone second dashboard. Atlas's board is first adopter and proof, never the subject.
- (direction) Operator ownership decision 2026-08-09: owner=steward, chosen over atlas. The blueprint is ~5/6 security+infrastructure to 1/6 dashboard craft; Steward provisions the engines, deploys the services and holds the keys. Vizro is what is being secured, not the work.
- (note) surface: [] VERIFIED, not asserted. grep for dashboard_audit_trail, ROLE_HEADER, USER_ID_HEADER, allowed_roles, SECURITY_WEBHOOK_URL, ENCRYPT_EXPORT_FILE returns zero hits outside docs/dreams and docs/intake. The Flask-Caching hits that do exist are conda RECIPES (recipes/flask-caching, recipes/vizro, recipes/apache-superset) and warden test fixtures — packaging artifacts, not implementation.
- (note) ASSET already in the estate: vizro and flask-caching are already packaged as conda recipes here, and pyforge-atlas already ships a BSL-driven Vizro dashboard with a dashboard-dryrun gate. The pattern lands on existing ground rather than greenfield.
- (constraint) Secrets come from Steward's keys surface, never from source or a default constant. The blueprint's sample embeds a literal ENCRYPTION_KEY and a DEFAULT_KEY fallback; scripts/container-gates' secrets-scan (steward 7.3) already exists to refuse exactly that, so the sample is incompatible with this estate as written.
- (constraint) The absent UI control is never the access control. Role-gated export must be refused SERVER-SIDE; stripping the button is presentation, not enforcement.
- (constraint) A role-filtered dataset is never written back to the shared cache. Global cache holds the master set; slicing happens per request, in memory, after it leaves the cache.
- (capability) CAP-1 identity and role from the request, no authentication of our own
- (capability) CAP-2 row-level isolation an adopting dashboard declares rather than implements
- (capability) CAP-3 navigation built per caller, so an unauthorized page is absent from the DOM
- (capability) CAP-4 an audit trail with row counts, not merely event names
- (capability) CAP-5 export gated server-side, optionally encrypted
- (capability) CAP-6 a deployment perimeter: WSGI topology, container stack, TLS and subnet policy
- (capability) CAP-7 a security suite that proves isolation and cannot pass vacuously
- (question) Where does the pattern live: a steward subcommand that scaffolds and verifies, a library the dashboard imports, or a template repository? Each implies a different upgrade story when the pattern improves, and a diverged adopter is the case that matters.
- (question) Does the pattern PROVIDE the RLS pipeline and audit writer, or VERIFY that an adopter has an acceptable one? Provide is reusable and rigid; verify tolerates dashboards that already chose.
- (question) Proxy headers are trusted implicitly — anything that can reach the app directly can forge X-Forwarded-Roles. The blueprint configures header NAMES but never defends the trust boundary. Needs a defence or an explicitly recorded assumption.
- (question) Is Redis mandated or one pluggable cache backend? The blueprint's sample uses FileSystemCache, which contradicts its own Compose stack: with Gunicorn --workers 4, a filesystem cache does not deliver the shared-cache guarantee Redis exists to provide.
- (question) Does the audit trail have a retention and access policy? It accumulates per-user activity and is therefore both a compliance asset and a privacy liability.
- (question) What enforces that search runs AFTER role filtering? The blueprint's sample gets the order right but nothing binds it, and reversing it leaks.
- (note) VACUITY WARNING carried from intake: the blueprint's own test_admin_sidebar_visibility mocks a VIEWER and asserts one page — it never exercises the Admin path, so it would pass against an implementation that always returns one page. CAP-7 exists partly because the supplied suite does not prove what it claims.
