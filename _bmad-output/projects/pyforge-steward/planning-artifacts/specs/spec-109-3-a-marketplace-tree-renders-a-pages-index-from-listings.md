## Intent

**Problem:** The reset needs a tree that can be pushed to an internal GitHub, with listings a static site can render, without changing the v1 catalog engine or the empty estate module list.

**Approach:** `catalog/marketplace/` holds `index.yaml` (`schema: pyforge.bmad-marketplace/v1`, `compatible_with: registry/estate.yaml`), the skill folders, `templates/SKILL.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `MANUAL-CHECKLIST.md`, and `site/` generated by `pyforge.steward.marketplace_pages.write_site`. `write_site` reads `pyforge.steward.marketplace_pages` and writes nothing while it is off. `registry/estate.yaml` with `modules: []` loads as no listings. A module row maps with `listing_from_estate_module`. `CatalogEngine.render` is not called and is not edited.

## Acceptance criteria

1. `load_listings` of the committed `registry/estate.yaml` returns `[]`.
2. A skill whose `path` is not `skills/<scope>/<slug>` raises `MarketplaceIndexError` and creates no site directory.
3. With the flag off, `write_site` raises `MarketplacePagesDisabled` and writes nothing. With the flag on, it writes `index.html`, `listings.json`, and one card per listing. The card names `.agents/skills`, `.claude/skills`, and any package with `published: false`.
4. The committed `site/` byte-matches `write_site_from_index` of the committed `index.yaml`.
5. The index lists `mason/environment`, `mason/package`, and `warden/scan`.
6. `catalog check` on the real tree still exits 0. `dedicated_repo` stays null.

## Boundaries

- No new steward CLI duty. No edit to `catalog.py`'s render path. No edit to `catalog.yaml` or `registry/estate.yaml`.
- No GitHub repository is created.
