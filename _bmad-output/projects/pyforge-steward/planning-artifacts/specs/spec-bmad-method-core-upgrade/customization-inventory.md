# BMAD-METHOD customization inventory — what this repo changes, keeps, and should drop

Companion of `spec-bmad-method-core-upgrade`. Measured 2026-09-06 on the
6.12.0 tree (branch `steward/bmad-core-upgrade-6.12.0`, PR #1074) by diffing
the installed tree against the cached 6.11.0 and 6.12.0 conda packages
(`~/.cache/rattler/cache/pkgs/bmad-method-<v>-*/lib/node_modules/bmad-method/src`),
the installer manifests (`_bmad/_config/*`), and the packaged sources of the
sibling modules (skf, bmad-loop, CIS). Every row was checked, none inferred.

**Method.** A "customization" is any byte this repo holds that the upstream
installer, a module's own installer, or a generator did not produce — plus any
repo mechanism that *depends* on an installer-produced shape. Each row carries
the mechanism (sanctioned custom layer, in-place edit of an installer-owned
file, repo-authored, package copy), whether the 6.12 `install --action update
-y` preserved it, and a verdict.

## 3. The upgrade recipe until CAP-6..8 ship

1. `git diff` the installed `.claude/skills/bmad-*` tree against the cached package of the **installed** version; keep the list (C5).
2. `steward upgrade bmad-core --target X --apply` — since Story 14.6 (CAP-6, 2026-09-06) the apply itself passes `--directory <repo> --modules <every module the manifest lists, core first>` with stdin closed and resolves `node` / `bmad-method` from `.pixi/envs/local-recipes/bin` when they are off PATH; the `--installer <wrapper>` of the first 6.12 apply is retired. An exit-0 run that changed nothing is refused (`zero_diff`, trap 12).
3. Confirm the review branch has a non-empty diff (trap 12), `_bmad/custom/**` byte-identical, CAP-3 clear.
4. Restore `_bmad/skf/config.yaml` from git (bump the header), then `bmad-module-skill-forge update`; correct `[modules.skf]` — since Story 14.7 (CAP-7, 2026-09-06) the apply itself does the first two: every catalog `custom_modules[].config_paths` entry (`_bmad/skf/config.yaml`) is snapshotted before the core installer and restored verbatim after it, then the module's own installer (`bmad-module-skill-forge update`) runs from the repo root; the report names each restored path and the `[modules.skf]` block of `_bmad/config.toml` as a diff (never edited — correct it by hand, or pin the answers in `_bmad/custom/config.toml`, C7/C17). The `--pin skf=…` question (§ 4) stays open: the 6.12.0 catalog ships `pin: null`.
5. Re-diff against the cached package of the **new** version; 3-way merge the step-1 list with `git merge-file`.
6. Delete `_bmad-output/projects/cap3-probe/` and `_bmad/scripts/resolve_config.py.bak`; port the upstream delta into C1.
7. `render_skill.py --skill .claude/skills/bmad-build-auto` must print a render path, not HALT (C2).
8. `bmad-method-version-drift-check`, `detectors-ci`, `bmad-drift-check`, `steward upgrade prove-landed`, then the spec-surface reconcile (memlog + scoped stamps).
