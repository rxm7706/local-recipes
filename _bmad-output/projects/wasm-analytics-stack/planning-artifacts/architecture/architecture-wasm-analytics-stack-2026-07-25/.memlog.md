- (event) Headless/express BMAD orchestrator run: Fast-path (no interactive coaching session available). Spine drawn from prd-wasm-analytics-stack-2026-07-25/prd.md + both research reports. [ASSUMPTION] tags on inferred load-bearing calls (paradigm, stack pins, security-context-parity mechanism).
- (decision) Paradigm: pipes-and-filters (medallion pipeline: upload -> validate -> ingest -> transform -> serve) with a ports-and-adapters (hexagonal) boundary specifically around the WASI validation stage -- the WIT interface IS the port, componentize-py compiles the one adapter behind it. Chosen over a pure hexagonal framing for the whole system because the dominant shape is a linear staged pipeline, not a request-driven core with swappable adapters throughout.
- (decision) AD-1 Trust-boundary data shape: the WASI component's WIT interface accepts only primitive/record types (strings, numbers, booleans, lists, records) built from plain Python objects -- never raw file bytes, never an Arrow buffer, never a host-shared-memory type. Excel parsing (bytes -> rows) happens in the FastAPI process BEFORE the WIT call, outside the sandbox. Binds FR-1, FR-2. Prevents a builder later deciding to pass raw bytes or an Arrow buffer across the boundary, which the technical research found has no confirmed working precedent.
- (decision) AD-2 Dependency-denylist enforcement: a static-import-scan build step (pixi task, part of ) parses the validation component's Python source + resolved dependency closure and fails the build if numpy/pandas/pyarrow/pydantic (or any other C-extension-backed/componentize-py-unproven package) is imported, transitively or directly. Binds FR-13. Prevents one builder relying on PR-review-only enforcement (a policy, not a gate) while another assumes it's automated.
- (decision) AD-3 No WASI sandboxing for dlt/dbt/DuckDB: dlt ingestion and dbt-duckdb transformation run as conventional Restricted-SCC-hardened OS processes/containers, never compiled to a wasm32-wasi target, because DuckDB's native engine has no WASI build and no roadmap (technical research finding). Binds FR-4, FR-5. Prevents a future builder re-litigating this per-story under ecosystem pressure without an explicit ADR amendment backed by new upstream evidence.
- (decision) AD-4 Isolation-Verification Gate is CI-blocking and non-hollow by construction: the gate (FR-12) must include a meta-test asserting that deliberately widening the component's declared WIT capabilities causes the gate itself to fail, mirroring pyforge-atlas story G1's own wasm-smoke design (zero-non-loopback-request assertion). Binds FR-12. Prevents a builder shipping a gate that only instantiates the component successfully without probing denied capabilities -- a pass that proves nothing.
- (decision) AD-5 One trace-ID field, generated once: the W3C trace ID is minted at FastAPI ingress (or extracted from an inbound traceparent header) and threaded through as a single well-known field -- stored as upload_trace_id in the dlt load package metadata, passed to dbt via --vars, and carried in every OpenLineage run event's parent-run facet. Binds FR-8, FR-9, FR-10. Prevents each stage inventing its own correlation-id field name/shape, which would break the single-lookup lineage reconstruction UJ-2 depends on.
- (decision) AD-6 Security-context single source of truth: one canonical securityContext definition (non-root UID 1001, readOnlyRootFilesystem true, no privilege escalation) is authored once and consumed by both the Podman digital-twin compose file (via a generation/translation step) and the OCP Helm chart values -- never hand-authored twice. Binds FR-15, FR-16. Prevents digital-twin and production security contexts silently drifting apart, which would defeat the parity claim UJ-2 exercises.
- (decision) AD-7 DuckDB single-writer serialization: dlt ingestion and dbt-duckdb transformation never hold concurrent write handles to the same DuckDB file (DuckDB is single-writer) -- ingestion completion gates transform start, enforced via a sequenced pipeline trigger, not left to chance scheduling. Binds FR-4, FR-5, FR-17. Prevents two independently-scheduled stages corrupting or lock-blocking the shared PVC-backed DuckDB file.
- (decision) AD-8 Air-gap-routable dependency fetch: every build-time fetch (pixi packages, DuckDB extensions, componentize-py/WASI toolchain artifacts) routes through the configured channel/mirror -- never a hardcoded public URL (extensions.duckdb.org, direct PyPI) -- matching pyforge-atlas G1's vendored-extension pattern and this repo's enterprise-airgap posture. Binds FR-14. Prevents a build script that works today but breaks the moment it runs behind an air-gapped mirror.
