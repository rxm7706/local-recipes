Success: six formats + lockfiles; PyPI inputs delegate to the engines' native parsers (no bespoke re-implementation); corpus conformance over ~1,950 real recipes = 0 uncaught exceptions + a ratcheted unparseable rate; a differential oracle asserts the extracted dep set is a superset of the authoritative renderer's, modulo name-only-marked.
- (capability) CAP-3 honest, split, per-axis coverage: a consumer can tell what was assessed from what was merely present. Success: coverage is per-axis with its own denominators + resolution_depth (direct-only vs locked-closure); a manifest can be 100% hygiene-covered and 0% vuln-covered and the two are asserted as DISTINCT fields; every withheld component states its reason and is always visible, never silently dropped.
- (capability) CAP-4 the axes of trust: every resolved component is assessed on each registered axis. Success: hygiene (deptry DEP001-005), security (osv-scanner + CISA-KEV + FIRST EPSS), license (SPDX via license-expression from conda about: + importlib.metadata), currency (bundled LTS registry -> endoflife.date -> N/N-1 -> unknown) each yield a verdict for 100% of resolved components; provenance and maintenance are named and unbuilt. - (capability) CAP-5 configurable, two-mode policy: a team tunes what blocks without editing the tool. - (capability) CAP-6 auditable, expiring suppression: a team accepts a risk in the open and on a clock. Success: waivers and baselines are committed files the tool READS and never writes; suppression keys on the stable finding-ID grammar; every applied entry is echoed in the report; an expired entry re-blocks; wildcards are rejected (least-privilege); a bypassed run carries bypassed + review_required in the audit record even though its residual exit is 0.
- (capability) CAP-7 the machine contract: a pipeline or downstream estate consumes the run as data. Success: a schema-validated versioned ComplianceReport on stdout as a single valid document OR empty — never partial, never diagnostics-contaminated; a CycloneDX 1.6 SBOM with source-registry-correct purls and self-declared partiality; BOM component count == resolved-inventory count == report.inventory_count, post-merge, root project excluded.
- (capability) CAP-8 typed failure with a named owner: a fleet operator routes every failure without reading a log. Success: the typed error kinds (unparsable-manifest, engine-unavailable, engine-output-unrecognized, engine-output-unparseable, engine-execution-failed, engine-timeout, config-parse, config-validation, internal-error) each route to an owner (developer / platform / CLI maintainers); a missing, incompatible, crashed, timed-out or output-drifted engine is exit 2 and never a silent pass; absence of an expected field is an error, not a zero.
- (capability) CAP-9 adoption without a day-one red wall: a debt-laden repo turns the gate on without ripping it out. Success: --warn-only reports everything at exit 0; a committed baseline grandfathers existing findings so the gate blocks NEW findings only, with expiring entries that re-block; every non-zero exit names the offending package, the finding (advisory id + severity + fixed version, or the hygiene rule), the source manifest + location, and a remediation path.
- (capability) CAP-10 determinism and non-mutation at fleet scale: a run reproduces and leaves nothing behind. Success: decision-determinism by default (identical inputs + DB snapshot => identical exit code + findings set), byte-identical output in --deterministic over a pinned volatile-field set; a scan never mutates the scanned tree or host state and cleans up on success AND failure; per-invocation cost is O(project) independent of fleet size; all live axes run in parallel with no shared mutable state.
- (capability) CAP-11 offline-first with no silent egress: an air-gapped fleet runs the gate with no network. Success: the orchestrator's own process opens no socket (socket-guard test); the vuln DB and the KEV/EPSS/endoflife feeds are provisioned or cached, offline by default and opt-in online never silent; every verdict records its data source + snapshot timestamp; stale, empty, swapped or unverifiable data routes to indeterminate, never a confident clean.
- (capability) CAP-12 opt-in remediation that never touches the tree: findings become pull requests without the tool writing the scanned repo. Success: --open-fix-prs runs strictly post-verdict with environment-supplied credentials, opening upgrade/removal PRs via the forge API only; a failed PR-open never alters the verdict or exit code (it lands in the actuation report section, outside status/exit composition); --fix-prs-dry-run shares the code path to the egress seam and opens no sockets.
- (constraint) FROZEN exit-code contract: the enum {0, 1, 2, 130} is a CLOSED set — 0 clean/warn/not-applicable/bypassed, 1 policy-violation or indeterminate, 2 operational error, 130 SIGINT. Adding a code is a MAJOR change (a new code silently breaks every 'elif rc == 2' consumer) — the deliberate opposite of the additive-flag rule. Exit 2 stays RESERVED for operational error so fleet routing (rc==2 -> infra owner) holds. No abnormal exit returns 0: any signal, interrupt or uncaught internal error is non-zero and never a passing report.
- (constraint) The verdict lattice is frozen at 7 rungs, in this order: error > policy-violation > indeterminate > warn > bypassed > clean > not-applicable. Status severity and exit code are DELIBERATELY different orderings (bypassed sits above clean because a suppression is an audit-relevant event). verdict.py is the SOLE OWNER of both the lattice and the exit projection — no other module maps a status to an exit code, enforced by a sole-ownership guard test. Every non-clean status carries status.driver (axis + finding id): an exit that cannot say 'critical CVE' vs 'blocking DEP001' is an incoherent contract.
- (constraint) NEVER FALSE-GREEN is THE acceptance property (C0), not one reliability item among many. Its mechanism is the indeterminate doctrine: not-applicable = NOTHING existed to scan; indeterminate = SOMETHING existed we could not or would not scan. indeterminate sits ABOVE warn so a clean sibling axis can never mask 'we could not scan what existed', and it projects to exit 1 — never a silent 0. Any run that did not meaningfully scan (empty extraction, expected-but-missing manifest, crashed engine, skipped coverage) is never clean in the STATUS channel; only the sanctioned downgrades (--allow-empty, --warn-only) may lower the EXIT — the status stays honest. Absence of an expected field is an error, not a zero. Coverage improves ONLY by resolving (reading the lock) or name-level flagging — NEVER by assuming a version.
- (constraint) The ComplianceReport schema is versioned and its producer is CLOSED at 1.1.0: exactly ONE sanctioned amendment was paid (story 6.1) and no other story may widen the schema. A coverage claim for an axis not registered in report.py's _REPORT_AXES is a HARD ERROR, never a silent drop. The report and the CycloneDX SBOM version INDEPENDENTLY (SBOM = spec 1.6 + its own profile version, emitted experimental until a consumer ingests it).
- (constraint) Six axes of trust, four live: hygiene, security, license and currency are registered producers that report and gate in v1; PROVENANCE (Sigstore/SLSA, PEP 740 trusted publishing, in-toto/GUAC) and MAINTENANCE (OpenSSF Scorecard, criticality_score, sustainability) are named direction and remain UNBUILT — the Charter's six-axis identity is the destination, not the shipped surface. A new axis registers behind the existing Engine seam with an axis string; there is no Axis protocol.
- (constraint) One spine: a single Component + ResolvedInventory. Discovery/routing/extract PRODUCE it, axis producers ANNOTATE it, report/sbom/verdict READ it — no stage reaches around it and no stage redefines a parallel shape. Identity is (ecosystem, name, concrete_version); the purl is DERIVED and its non-identity qualifiers stripped before any comparison. A (name, None) entry merges into (name, version) only when exactly ONE concrete version exists — zero leaves one indeterminate, two or more keeps the bare entry a distinct indeterminate. Never guess-attribute a version.
- (constraint) No EXECUTION of untrusted input (the constraint was never 'stdlib-only'): extract/ is a no-execution zone importing no eval/exec/compile/__import__/os.system/subprocess and rendering no templates (no jinja2 import), yaml.safe_load only — enforced by an AST-denylist meta-test. Safe parsers are permitted because they do not execute input. engines.py is the ONLY module that spawns subprocesses, always through the _engine_env() helper (machine output forced to a system-temp file, NO_COLOR=1, stdin=DEVNULL, explicit utf-8 decode with undecodable output mapping to a typed error).
- (constraint) The tool NEVER writes the scanned repository. Waiver stanzas and baseline candidates are emitted to stdout for the human to commit; temp artifacts go to the system temp dir via mkstemp/mkdtemp at 0600/0700 (mkstemp IS the symlink/TOCTOU defense); the fix-PR actuator writes pull requests through the forge API, never the tree. Cleanup happens on success AND failure.
- (constraint) No SILENT egress: the orchestrator's own process opens no socket (socket-guard test) and all network is confined to the named engine subprocesses; air-gapped mode passes explicit offline/local-DB flags because osv-scanner defaults ONLINE (an assertion, not a hope); KEV, FIRST EPSS and endoflife.date are cached feeds under the same posture. actuator.py is the SOLE egress carve-out — scoped to that module under the real flag, never a global loosening.
- (constraint) Engines are CONSUMED, not authored: deptry and osv-scanner are conda run-deps provisioned from existing conda-forge feedstocks (never curl-fetched at runtime), pinned to a tested version RANGE rather than an exact pin, failing loud when out of range — the guard against silent upstream output-schema drift. That same version range is also the distribution gate. Where the local mirror recipes for the engines are touched, this repo's CFE Rule 1 (invoke the skill) and Rule 2 (closeout retro) apply.
- (constraint) osv exit codes are read as CONTENT, never as the gate: 0 = no vulns, 1 = vulns-found and EXPECTED, 127 is MULTIPLEXED (a DB-absent/empty/corrupt 127 is a coverage gap -> indeterminate; any other 127 -> error), 128 no-packages -> indeterminate, anything outside {0,1,127,128} -> error. The decisive case: a present-but-EMPTY database makes osv exit 0 with an empty body — a false-green neither the exit code nor a namelist count catches — so the loader runs a DB CONTENT pre-flight (parse + validate the advisory shape, count >= 1, at osv's case-sensitive PyPI segment) before trusting any clean; a provenance-less DB (snapshot_at = None) routes to indeterminate.
- (constraint) osv has NO conda ecosystem — it keys advisories over PyPI/npm/Go, so a conda dep is parsed as PyPI and a differently-named pinned package (pytorch -> torch, native openssl) would match the WRONG identity and silently false-green. Therefore vuln_matchable = (pypi_identity is not None) AND (version resolved to ==X.Y.Z), and pypi_identity resolves ONLY from trustworthy provenance: pixi.lock pypi: entries, explicit PyPI sections, or the bundled static conda->pypi map. Unmapped -> None. Conda '=1.2' is a PREFIX (1.2.*), not an exact match -> withheld as range-only.
- (constraint) Cross-ecosystem names are NEVER silently merged or deduped: per-ecosystem attribution is preserved and uncertainty is MARKED. A component's purl reflects the source registry of the manifest it came from (pkg:pypi/... vs pkg:conda/...?channel=) and an unresolved registry-of-truth is marked, never guessed into a purl. Full conda<->PyPI reconciliation is deferred.
- (constraint) Stream discipline: the report goes to stdout and ALL diagnostics, progress and warnings to stderr; in machine mode stdout is a single valid document OR empty, never partial and never contaminated. Human text output and stderr are EXPLICITLY unstable and may change any release — declaring non-contract is itself a stability statement.
- (constraint) Contract stability is taxonomized, not one rule: OUTPUT (the report, the SBOM) evolves by add-fields-and-bump-version; INPUT (config keys, the waiver/baseline file schema) evolves by accept-old-forever then deprecate -> warn -> remove, because those keys live in 20k repos, and an unknown or future waiver-file version is REJECTED with a typed error, never guessed; the exit enum is the frozen closed set. v1 ships the behavior, not the paperwork — no deprecation lifecycle machinery.
- (constraint) Determinism discipline: never iterate a set for output — sorted() before every emit, JSON with sort_keys and fixed separators; no unguarded datetime.now(); --deterministic pins the documented volatile-field set (report/SBOM timestamps, CycloneDX serialNumber and bom-ref derived from a content hash, set-iteration order, absolute paths -> repo-relative, DB version, and the actuation section).
- (constraint) Single-writer rules that bind independently-built stories: config.py alone computes the per-axis gating bool (producers and the report only READ it); axis producers never feed a rung above warn (producer meta-test) and one story solely owns the escalation mapping; suppression matching-by-finding-ID plus expiry is implemented ONCE in waiver.py for both the waiver and baseline formats (waiver wins where both match, echoed once); KEV/EPSS enrich findings at exactly ONE position — inside the vuln producer BEFORE policy dedup, never post-dedup.
- (constraint) The waiver file, the baseline file and the offline vuln DB are untrusted-or-verified INPUTS: schema-validated, expiry enforced against wall-clock, never executed. Authorship and integrity are explicitly delegated to code review + CODEOWNERS — the tool cannot verify a forge control at runtime and says so rather than pretending otherwise. The DB's trust anchor is conda package integrity plus build-date staleness.
- (constraint) Bundled data (the LTS registry, the conda->pypi map) carries a build-time snapshot_at, and EVERY verdict derived from it carries max_age_ok against a configurable max-age (default 180 days): a stale bundled registry can never silently report supported — stale under an active gate routes to indeterminate. Absent or stale KEV/EPSS feeds under an active policy do the same: the gate never silently no-ops, and kev: null (feed absent) stays distinguishable from 'assessed, not KEV-listed'.
- (constraint) Resource bounds are enforced mechanisms, not hopes: extraction is line-bounded with a per-line byte cap and a total manifest-size cap; no compiled pattern contains nested unbounded quantifiers (static assertion); DB extraction is decompression-bounded (zip-bomb) and zip-slip confined; every engine invocation carries a bounded, configurable timeout whose expiry maps to a typed error and the frozen exit code — never an indefinite hang, never scored as a pass.
- (constraint) Engine-input purity and output neutralization: the synthesized requirements projection is a PURE DATA projection — any line starting with '-', or carrying a URL, VCS ref, path or environment marker we did not author, is rejected or neutralized; manifest-derived values are NEVER passed as CLI flags; shell=True is banned. Every input-derived string is emitted only through a schema-aware encoder (never string concatenation), purls are canonically percent-encoded, and control/escape chars are stripped — so a malicious component string cannot make the tool a confused-deputy injection vector against a downstream SBOM or dashboard consumer.
- (constraint) Runtime shape: Python >= 3.12; argparse, not Click or Typer; stdlib-lean with a small set of targeted, conda-provisioned, safe-API-only runtime deps (PyYAML safe_load/safe_dump, packaging, cyclonedx-python-lib, jsonschema, license-expression) — 'lightweight' means runtime footprint, not total cost. pixi >= 0.72.2 is a build/dev-env floor: the tool NEVER invokes pixi at runtime (pixi.lock is safe_load-parsed). Scope is Python only — PyPI plus conda-forge.
- (constraint) Non-rendering two-pass extraction is the security posture made into a parsing strategy: v1 recipe.yaml is valid YAML and safe_loads directly; v0 meta.yaml is not, so selectors are captured as marks, {% ... %} statement lines stripped, and simple {{ VAR|filter }} substituted through OUR OWN safe-filter allowlist — never a Jinja engine — before safe_load. run_constrained / run_constraints entries are CONSTRAINTS, not dependencies: excluded from vuln matching and SBOM counts. Per-construct handling: extraction-contract.md.
