- (decision by claude) Cross-cutting -- THE FALSE-GREEN TRIAD (the acceptance invariant, non-negotiable). Three decisions are only sound together: (1) a new verdict state 'indeterminate' added to the lattice ABOVE warn -- error > policy-violation > indeterminate > warn > bypassed > clean > not-applicable -- so Gap-C's withheld/skipped/unresolved outcomes route there and never to not-applicable (not-applicable = nothing existed to scan; indeterminate = something existed we could not or would not scan), which stops a clean sibling axis masking 'we could not scan what existed'; (2) the 7-to-4 exit projection, pinned 2026-07-12: {clean, not-applicable, bypassed} -> 0, warn -> 0 (configurable), policy-violation -> 1, INDETERMINATE -> 1 (never a silent 0), error -> 2 (reserved for operational failure so fleet routing rc==2 -> infra owner survives), SIGINT -> 130; (3) the Gap-C withhold, honest but load-bearing on the first two. Fix one without the others and the cardinal rule (never false-green) reopens. Every non-clean status carries status.driver (axis + finding id).
- (decision by claude) GAP A -- deptry severity to verdict = TWO-AXIS, PER-RULE CEILING. deptry emits no severity at all (uniform DEP001-005, confirmed against upstream docs), so 'separate axis' means a separate default CEILING plus status.driver, both axes computing in the SAME lattice. DEP001 (missing dependency) blocks by default but gated on conda<->PyPI name-mapping confidence (block on a high-confidence mapping, warn on an ambiguous one -- a mapping miss must never become a false-red disable-driver in a repo with known name unreliability); DEP002/003/004/005 warn by default. The hygiene-to-status table and the CVSS severity thresholds are OUR policy artifacts (deptry has no severity, osv has no gate) and live in the FR30 ConfigLoader. - (decision by claude) GAP B -- ComplianceReport vs CycloneDX = ONE ResolvedInventory, TWO ARTIFACTS. One internal model projected into two independent emitted artifacts. Component{name, version|None, ecosystem, pypi_identity:(name,version)|None, purl, provenance:[(manifest,section)], hygiene_covered, vuln_matchable, indeterminate_reason|None}. - (decision by claude) GAP C -- osv input contract + offline DB = ECOSYSTEM-IDENTITY PREDICATE + NAME-LEVEL TIER + PROVISIONED DB. osv has no conda ecosystem: it keys advisories by (ecosystem, name, version) over PyPI/npm/Go/..., so a conda dep is parsed as PyPI and a pinned-but-differently-named conda package (pytorch -> torch, native openssl) matches the WRONG PyPI identity -- a silent false-green. Therefore vuln_matchable = (pypi_identity != None) AND (version resolved to ==X.Y.Z). pypi_identity resolves ONLY from trustworthy provenance: pixi.lock pypi: entries, explicit PyPI sections ([pypi-dependencies], environment.yml - pip:), or the bundled static conda->pypi map (the CLI is offline and cannot call the MCP get_conda_name mapper; regenerable from the atlas export-purls TSVs or parselmouth-direct for non-atlas orgs). Unmapped -> None. Conda '=1.2' is a PREFIX (1.2.*), not an exact match -> withheld as range-only. WithholdReason enum: no-version | unmapped-ecosystem | native-nonpypi | range-only (later grew ambiguous-identity, additively).
- (decision by claude) GAP C -- the NAME-LEVEL CVE TIER rescues beachhead value: for a mapped-but-unversioned dep, ask the DB 'does this package carry ANY critical CVE across any version' and report indeterminate: 'carries known critical CVEs -- pin/lock to prove immunity' -- a ranked worry-list plus a lock-nudge instead of a dead 12 percent. GUARDRAIL (binding): coverage improves ONLY by resolving (read the lock) or by name-level flagging, NEVER by assuming a version.
- (decision by claude) GAP C -- osv EXIT CODES ARE READ AS CONTENT, NEVER AS THE GATE (Story-1.4-reconciled): 0 = no vulns; 1 = vulns found and is EXPECTED, not an error; 127 is MULTIPLEXED -- a DB-absent/empty/corrupt 127 is a COVERAGE GAP -> indeterminate (gated by the DB content pre-flight, not by the exit code alone), while any OTHER 127 (osv crashing with a valid DB) -> error; 128 no-packages -> coverage: skipped -> indeterminate; any exit code outside {0,1,127,128} -> error. Absence of an expected field is an error, not a zero.
- (decision by claude) GAP C -- OFFLINE DB posture: pre-provisioned as a conda package ({ecosystem}/all.zip), run full --offline (NOT --offline-vulnerabilities, which egresses on transitive resolution); trust anchor = conda package integrity; staleness from the DB package build date (--db-max-age default 7 days, strict) -> stale degrades or fails loud, never confident-clean. - (decision by claude) E1 EXTRACTION STRATEGY -- NON-RENDERING PARSE-AS-DATA plus a SUPPORTED-CONSTRUCT MATRIX. NFR-S1 forbids rendering untrusted Jinja, which rules conda-build MetaData / grayskull / rattler-build off the runtime path (they EVALUATE) and rules out CRM/conda-souschef as the primary parser (CFE gotcha G93: CRM crashes on odd comments, failing NFR-R1). E1 is a bounded two-pass scrape: pass 1 captures context without executing (v0 regex-captures {% set K=V %}; v1 safe_loads the context: block); pass 2 neutralizes and safe_loads (v1 recipe.yaml is valid YAML so safe_load directly; v0 meta.yaml is not, so capture '# [selector]' marks, strip {% ... %} statement lines, substitute simple {{ VAR|filter }} through OUR OWN safe-filter allowlist -- never a Jinja engine -- then safe_load). Walk requirements.{build,host,run} + test(s).requirements + outputs[].requirements; run_constrained/run_constraints entries are CONSTRAINTS, not dependencies -- excluded or flagged provenance: constraint, out of vuln matching and SBOM counts (corrected 2026-07-12 to match shipped scan_project semantics).
- (decision by claude) E1 SUPPORTED-CONSTRUCT MATRIX (the FR-flagged unowned deliverable, owned by this spine): 'numpy >=1.20' -> name + spec; {{ name }} / ${{ version }} with VAR in context -> resolve to literal; ${{ compiler("c") }} / stdlib("c") -> variant-expanded BUILD TOOL, mark and EXCLUDE from the scanned set; ${{ pin_subpackage('foo') }} -> intra-recipe output, mark internal-subpackage and exclude from external deps; '# [linux]' / if: linux then/else -> UNION both branches, each tagged with its condition; {{ version.replace(...) }} expression logic -> version field becomes None (Gap-C range-only), name field best-effort; {% for %}-generated deps -> degrade the block to name-only + marked; a bare {{ }} in a v1 file (G20) -> literal text, raw string + malformed-recipe flag. v0<->v1 differences the parser must encode: {{ }} vs ${{ }}, {% set %} vs context:, '# [sel]' vs if/then/else and match(python,...), run_constrained -> run_constraints, neutralize-then-load vs load-directly.
