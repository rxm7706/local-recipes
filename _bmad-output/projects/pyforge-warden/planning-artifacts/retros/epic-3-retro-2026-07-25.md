## Delivery snapshot

The policy layer that turns a fixed gate into a governable one: configurable policy via the `ConfigLoader` (3.1), auditable expiring waivers (3.2), and waiver expiry + the warn-only adoption on-ramp (3.3). **3/3 done, merged via PR #104.**

## What went well

- **3.1 (ConfigLoader) picked up the hooks Epics 1&2 had stubbed throughout** — the accumulated deferred-work items owned by 3.1 (per the 1&2 retro) were consciously absorbed rather than dropped. The natural wedge landed where the code was already waiting for it.
- **Waivers are auditable and expiring by design** (3.2) — a suppression carries its own authorization and a deadline, so grandfathering can't silently become permanent. This directly enabled the later baseline mechanism (6.8 reuses this engine).
- **Warn-only is an honest adoption on-ramp** (3.3) — a repo can adopt Warden in observe-mode before flipping the gate, without the tool ever pretending a warn is a pass.

## What was harder / carried forward

- **The mutable-policy-dict deferral remains open.** Story 3.1's dev-2 froze the *resolved* `Policy` dataclass (mitigating the runtime risk) but left the module-level `DEFAULT_HYGIENE_POLICY` / `DEFAULT_VULN_SEVERITY_POLICY` seed dicts mutable. The operator consciously chose to leave this open at the 3.1 gate (2026-07-17). It is still an open `action_items` entry.

## Lessons

1. The waiver/warn-only engine built here is load-bearing far beyond Epic 3 — Epic 6.8's baseline/grandfathering is a second producer over the *same* suppression engine. Getting the auditable-expiring shape right early paid off downstream.
2. The lost spec files are concrete proof of the paper-trail action item's cost: an epic's own dev record is now unrecoverable. This raises the priority of that fix.
