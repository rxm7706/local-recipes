## Delivery snapshot

The fleet-readiness on-ramp: actionable diagnostics + safe-by-default posture via the `--doctor` command (5.1), and fleet-scale validation + corpus/oracle maturation (5.2). **2/2 done, merged to main via PR #110.** Test count grew to ~1,918 → 1,936 (fast) plus the slow corpus suite.

## What went well

- **Adversarial review caught two real, security-relevant defects in 5.1** — both before merge, both with new tests:
  - **Cross-package fixed-version attribution** — `_extract_fixed_version` read `fixed` events from *every* `affected[]` entry, so a multi-package advisory could attribute an unrelated package's fixed version to the finding (a wrong "upgrade to ≥X" — Warden's cardinal false-green risk). Fixed by filtering on `pkg_name`/`pkg_ecosystem`.
  - **A `--doctor` TOCTOU crash** — an unguarded stat that could turn a health-check into a raw traceback; wrapped to return a clean typed result.
- **5.2's fleet-scale validation is real, not decorative:** a ~2,000-recipe corpus + differential-oracle + a **strace egress counter proving zero network across the full corpus scan**, plus a dogfood scan that runs Warden on itself and exits `bypassed`/0.
- **The dogfood exercise found a real bug along the way** — `license.py` imported `license_expression` without declaring it in `pyproject.toml`; added.

## What was harder than it should have been

- **5.1 hit the bmad-loop idle-strand issue** — review-1 crossed the ~4M-weighted per-session token cap, triggering a second review cycle. It resolved well (the follow-up review ran inline and merged clean) but the cap was hit because of the underlying strand behavior.
- **5.2 was the heaviest story of the effort** — a 144K-line diff, overwhelmingly the 2,000-recipe corpus (test data), which is expected for "corpus maturation" but is a large surface to validate.

## Lessons

1. **The loop auto-discharges follow-up reviews on resume.** 5.1's `followup_review_recommended: true` made the resume run the deeper review inline (two cycles) before merging — the "review debt" doesn't need separate hand-tracking.
2. **Verify a hypothesized bug against the validation layer before patching** (crystallized in Epic 6.9, applies here too): the fixed-version fix was a *real* reachable bug precisely because it wasn't blocked upstream — the discipline is to check reachability, then patch only real ones.
