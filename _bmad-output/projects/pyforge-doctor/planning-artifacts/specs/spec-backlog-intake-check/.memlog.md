- (capability) CAP-1 — backlog-intake surfacing. intent: when a new story/spec is drafted for an epic, tracked deferred-work entries whose owner:/prose names that epic or a story within it are surfaced as candidate acceptance criteria, instead of staying inert prose only a human happens to notice by re-reading the ledger. success: given a story/spec draft naming epic E, tracked entries across the fleet's ledgers whose owner:/prose names epic E or a story within it are surfaced to the drafting session as candidates.
- (constraint) Matching must be precise, not substring/membership. This fleet has already shipped one real bug from exactly this failure mode: chain-completeness's INV-A decides a Spec is decomposed by testing whether its slug appears ANYWHERE in concatenated epics.md prose (a substring test over a blob), which reported false-clean while 7 of 10 capabilities had zero stories (found 2026-08-15, tracked as an open deferred-work entry in this same ledger). CAP-1 must not repeat that class of bug — matching an owner:/prose reference to an epic/story id needs to name the id precisely (e.g. a parsed epic/story-id token), not a bare string-contains check that would also match a substring collision (e.g. epic 1 matching epic 11's prose).
- (non_goal) Not auto-writing acceptance criteria into the story/spec. CAP-1 surfaces candidates for the drafting session (human or agent) to accept, reject, or reword — it does not silently insert text into epics.md or a story spec.
- (non_goal) Not deciding which Tier-3 findings get promoted into tracked storage in the first place — that is deferred-work-audit-completeness's / spec-deferred-work-visibility's territory, same non-goal spec-deferred-work-resolution-sweep already states for its own sibling capabilities.
- (question) Trigger mechanism unresolved: does CAP-1 hook into the story-drafting skills themselves (bmad-create-story / bmad-create-epics-and-stories, surfacing candidates inline during drafting), or ship as a separate doctor CLI verb a drafting session invokes manually before finalizing a spec/epic? The source Dream says only 'surfaced in the drafting flow as candidates,' not which flow or mechanism.
