## Intent

**Problem:** a tracked story spec can repeat a frontmatter key, and no detector reports it. Readers then disagree on
the spec: PyYAML keeps the last occurrence, so Doctor's own `_frontmatter_parse_text` (`sources/chain.py:204`,
CAP-81) and its `deferred-work` source (CAP-86) read the last one; marshal's scalar reader reads the first. Line
numbers below are at `a21524e9d6`.

**The evidence (measured on `main` at `a21524e9d6`):** a PyYAML `SafeLoader` whose mapping constructor records
repeated keys finds 40 repeats in 37 of the 1,407 tracked story specs with frontmatter:
`followup_review_recommended` 29 times and `review_loop_iteration` 11 times, in marshal (15), steward (7), herald (6),
doctor (5), mason (4) and warden (3). Doctor's own five are `spec-21-7`, `spec-34-6`, `spec-41-4`, `spec-41-6` and
`spec-6-13`. None of the other 900 tracked frontmatter files under `_bmad-output/` and `docs/` (174 Dreams, 171
`SPEC.md`, 10 PRDs, 9 spines, 8 `epics.md`, 195 memlogs and the rest) repeats a key. Four repeats hold two different
values. One of them is herald 29.2, which reads `followup_review_recommended: true`, then `false`: `deferred-work`
reads `false` and marshal reads `true`. The writer is the dispatched `bmad-build-auto` session (marshal's Dream,
2026-10-11). Marshal Story 96.1 stops it and cleans all 37 specs. Without a detector a repeat comes back unseen: herald
37.1's was removed by hand on 2026-10-11, and steward 91.1's dispatch branch already repeats `review_loop_iteration`.

**Approach:** a new repo-scope Doctor source, `frontmatter-duplicate-keys`, in `detectors-ci`.
- It reads every tracked story spec, `git ls-files` matching `_bmad-output/projects/*/planning-artifacts/specs/spec-*.md`.
  Untracked files are not read, as for every repo-scope source.
- It bounds each frontmatter block with CAP-81's reader (`_fenced_lines` and `_split_fenced_block`, banner-aware) and
  loads the block with a `yaml.SafeLoader` subclass whose mapping constructor records every key that repeats inside
  one mapping, at any depth.
- Each repeat is one FAIL finding (`frontmatter-duplicate-key`). It names the file, the key (a dotted path when
  nested, e.g. `flag.key`), and both line numbers and values. The remedy: keep the occurrence git wrote last
  (`git blame`) and delete the other, marshal Story 96.1's rule.
- A block that cannot be bounded or loaded is one WARN (`frontmatter-unreadable`) naming the file: never a pass. No
  tracked story spec is unreadable today.
- With nothing to report, the source returns its OK row.
- Registration follows doctor Story 21.16's path: a `Source` member, a `REGISTRY` entry (scope `repo`), a `DISPATCH`
  entry, the pixi task `frontmatter-duplicate-keys-check` (`python -m pyforge.doctor.sources
  frontmatter-duplicate-keys`, under `[feature.guild-tasks.tasks]`), and the row `("frontmatter-duplicate-keys",
  "frontmatter-duplicate-keys-check")` in `scripts/detectors.py` `_DOCTOR_SOURCE_TASKS`, so `detectors-ci` runs it. The
  generated pages that list detectors and tasks (`docs/reference/detectors.md`, `docs/how-to/pixi-tasks.md`) are
  regenerated by their own `docs-*` tasks.
- **Unchanged:** `_frontmatter_parse_text`, `_frontmatter_parse` and every existing source's verdict. A source that
  reads a repeated key keeps reading it as it does today.

## Acceptance Criteria

The source tests build real temporary git repositories with tracked specs, as
`tests/unit/test_sources_chain_spec_surface.py` does.

- **AC1 — A top-level repeat fails.** A tracked story spec whose frontmatter reads `followup_review_recommended: true`
  at line 6 and `followup_review_recommended: false` at line 10 (herald 29.2 at `a21524e9d6`) gives exactly one FAIL
  naming the file, `followup_review_recommended`, lines 6 and 10, and `true` and `false`. The source exits 1.
- **AC2 — Every depth, every spelling.** A key repeated inside a nested mapping (`flag:` holding `key:` twice) fails
  with the dotted path `flag.key`. A quoted and a bare spelling of one key (`"status":` and `status:`) fail as one
  repeat. A block below a `<!-- … -->` provenance banner is read.
- **AC3 — Scope.** An untracked story spec with a repeat, a tracked `SPEC.md` with a repeat and a tracked file outside
  `planning-artifacts/specs/` each give no finding. A tracked story spec under any project's `planning-artifacts/specs/`
  is read.
- **AC4 — Unreadable is not clean.** A tracked story spec whose fence never closes, or whose block does not load,
  gives one WARN naming it, never the OK row alone.
- **AC5 — Registered where the gate runs.** `scripts/detectors.py --list` shows the source, `--scope repo` runs it,
  and `tests/scripts/test_detectors_doctor_sources.py`'s count and membership assertions include it. With one planted
  repeat in a fixture repository, `python scripts/detectors.py --scope repo` exits 1 and names the source.
- **AC6 — `main` reads clean.** On the tree after marshal Story 96.1, `pixi run -e pyforge-guild
  frontmatter-duplicate-keys-check` exits 0 with the OK row, and `pixi run -e pyforge-guild detectors-ci` exits 0.
  The generated pages are current, so `docs-currency-check` exits 0.
- **AC7 — Nothing else moves.** Every existing Doctor test passes, and no existing source's fixture verdict changes.
- **AC8 — Mutation.**
  - Remove the repeat check: AC1's fixture gives the OK row, and its test fails.
  - Drop the `_DOCTOR_SOURCE_TASKS` row: AC5's registry test fails, and a planted repeat no longer reds
    `detectors.py --scope repo`.
  - Report a repeat as WARN instead of FAIL: AC1's exit-code assertion fails.

## Boundaries & Constraints

**Always:**
- Read tracked files only, through git, and import no station's internals.
- Read every verdict from the exit code, never through a pipe.
- Reconcile every governed path the change touches on the memlogs of the Specs that govern it, then stamp those Specs
  scoped: `spec-pyforge-doctor` and every co-governor `spec-surface-check` names (`spec-pyforge-core` co-governs
  station `src/`; `pixi.toml` has several) (AGENTS.md pre-PR item 5).

**Never:**
- Never edit a story spec to clear a finding here; the cleanup is marshal Story 96.1's.
- Never change `_frontmatter_parse_text`, `_frontmatter_parse` or any existing source's verdict.
- Never hand-edit a generated docs page, a `SPEC.md` or a `sprint-status-ledger.yaml`.

**Residual risk:**
- A story spec that `git ls-files` cannot see (a Tier-3 draft) is not read. It is checked once it is promoted into
  `planning-artifacts/specs/`, which is when it can reach `main`.

| Tracked story spec frontmatter | Finding | Exit |

| no frontmatter at all | nothing | 0 |
| an untracked spec, a `SPEC.md` or a file outside `specs/` with a repeat | nothing | 0 |
