- (capability) CAP-1 (doctor check, PRD §4.1/FR-1-3): intent - operator or Marshal runs 'doctor check --env --engines' for a fast, tri-state pre-flight wrapping warden's engine self-check and a new credential/env-hygiene detector. success - engine findings identical to warden's --doctor output; every check reports ok/warn/fail and is individually nameable/filterable via 'doctor check --list'; a JFROG_API_KEY-shaped unconditional-credential-injection pattern is caught by --env.
- (capability) CAP-2 (doctor monitor --fleet, PRD §4.2/FR-4-5): intent - operator runs 'doctor monitor --fleet --watch <axis>[,<axis>...]' to get one normalized, source-tagged fleet-pulse view over cf_atlas's staleness/cve/abandonment signals instead of reconciling five separate CLIs by hand. success - findings equivalent to the underlying atlas CLI/MCP call for the same scope, each tagged and filterable by originating Source; omitting --watch runs a documented default axis set (staleness+cve) rather than every axis unconditionally.
- (capability) CAP-3 (doctor diagnose --prescribe, PRD §4.3/FR-6-8): intent - operator triaging a target runs 'doctor diagnose --target <target> --prescribe' to get every gathered finding partitioned (actionable/blocked/accepted-risk, none silently dropped) and the actionable set ranked by severity x exploitability x blast-radius with root cause named. success - total findings across partitions equals findings gathered; a KEV-flagged finding outranks a non-KEV one of equal severity, higher-EPSS outranks lower at equal severity, smaller upgrade-lag outranks larger as tiebreaker; every Prescription shows its rank_factors (never a bare number) and a root_cause templated from the finding's own structured evidence (no new inference layer).
- (capability) CAP-4 (machine-consumer contract, PRD §4.4/FR-9): intent - every verb (check/monitor/diagnose) accepts a --json flag producing one schema-validated DoctorReport document with the same information as the human-readable output. success - --json output validates against a committed JSON Schema; no information present in the human-readable render is absent from --json (parity requirement).
- (constraint) AD-1: 'doctor check --engines' calls pyforge.warden.engines.run_doctor_checks as a library import, never a subprocess reimplementation; pyforge-doctor declares pyforge-warden as an optional 'gate' extra (mirrors pyforge-atlas's identical existing edge to warden). A meta-test asserts doctor.sources.warden contains no subprocess import/call.
- (constraint) AD-2: Doctor owns its own closed exit-code space {0 = all ok, 2 = a fail present, 130 = SIGINT} that never merges with or re-exposes warden's exit code, permanently omitting warden's policy-gate rung 1 -- Doctor reports operability, never policy. A warn-status finding never changes the exit code. Warden's own exit code is consumed only as data folded into a Finding.status.
- (constraint) AD-3: Doctor defines its own closed Finding/Source/DoctorStatus taxonomy (pyforge.doctor.models: DoctorStatus{ok,warn,fail}, a closed Source enum with one member per wrapped instrument, a Finding dataclass) structurally mirroring warden's models.py pattern but never importing warden's ErrorKind directly. Resolves PRD §8 open question 5.
- (constraint) AD-4: 'diagnose --prescribe' (pyforge.doctor.prescribe) is a pure function over an already-gathered list[Finding] -- zero subprocess or MCP calls of its own; a meta-test asserts no subprocess/MCP-client import exists in doctor.prescribe.
- (constraint) AD-5: exactly one narrow, typed subprocess site in the whole package -- pyforge.doctor.cli_bridge -- reserved for the CLI-fallback branch of AD-6; argv as a list (never a shell string), NO_COLOR-equivalent + stdin=DEVNULL discipline, bounded timeout, typed Finding(status=fail) on failure, never a raw traceback. A meta-test asserts cli_bridge is the only module containing a subprocess call.
- (constraint) AD-6: 'monitor --fleet' calls cf_atlas's MCP tools when an MCP client is available in-process (the expected Marshal/agent path); otherwise falls back to the equivalent CLI subprocess via AD-5's cli_bridge. Both paths must normalize to the identical Finding shape -- the caller cannot tell which path produced a given Finding except via its Source tag.
- (constraint) NFR-1: v1 is read-only/non-mutating across all three verbs -- no module under pyforge.doctor writes outside a tempfile-scoped path or mutates a scanned tree; no --fix/actuator exists.
- (constraint) NFR-4: doctor check's default run must stay within a documented speed budget (the five-second pre-flight promise, UJ-1) -- a benchmark test guards against future checks regressing this; check-suite runtime must not creep upward in pursuit of more findings (PRD SM-C1 counter-metric).
- (constraint) NFR-5: the DoctorReport JSON envelope ({schema_version, verb, generated_at, findings, prescriptions}) carries a schema_version field starting at 1, carrying warden's ComplianceReport precedent forward; 'prescriptions' is present only when verb=diagnose.
