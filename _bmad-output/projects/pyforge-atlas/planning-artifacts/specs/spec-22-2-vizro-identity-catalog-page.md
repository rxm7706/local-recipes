## Intent

**Problem:** The identity catalog (every OpenTeams-universe package with its priority
bucket, rank, score, and packaging work) is only browsable through Cursor Canvas —
`identity-2026-08-20.canvas.tsx`, generated by `scripts/conda-forge-packaging-inventory-
operations_priority.py::write_canvas`. That canvas is a Cursor-only artifact (not this
repo's test suite, no CI gate, no browser-neutral URL). CAP-7 / Epic 22's north star is a
**parallel** Vizro page reachable from `dashboard-serve` that shows the same ranked
universe — proven, not asserted, against the canvas generator's own output on a shared
fixture.

**Approach:** Add one BSL-driven Vizro page, `identity-catalog`, to the existing 28-page
`PAGE_INVENTORY` (`dashboard/app.py`), following the SAME `PageDef` + `_data_page` +
provenance-per-page pattern every other page in that file already uses (no new
mechanism). The page's loader (`dashboard/data.py::load_identity_catalog`) runs a
declared BSL query (`semantic/models.py::build_identity_catalog_model`) over
`identity_ranked_export.parquet` — Story 22.1's bridge export (`P`/`Rank`/`Score`/`Work`
+ identity columns, confirmed dependency, not re-litigated here). Parity is proven by a
new offline test that feeds ONE hand-built fixture record set into BOTH
`write_canvas(...)` (unmodified, imported from `scripts/`) and a Parquet fixture with the
SAME data under the ranked-export's column names, then asserts the Vizro loader's row
count and a sample of `P`/`Work`/`Core_Python_Package_Name` match the canvas's own
embedded `DATA` blob.

## Boundaries & Constraints

**Always:**
- The page is wired into `dashboard/app.py`'s existing `PAGE_INVENTORY` tuple and
  `build_dashboard()` — not a second dashboard entrypoint, not a standalone script.
- The loader routes through `dashboard/data.py`'s existing `_bsl_query_or_empty` seam
  (AD-8) — no raw SQL, no re-implemented metric arithmetic, no direct
  `boring_semantic_layer` import outside `semantic/models.py` (mirrors
  `test_dashboard_only_imports_semantic_seam_never_bsl_directly`).
- Absent `identity_ranked_export.parquet` → the page renders an empty typed AgGrid + a
  "Data gap" Card note (the same DW-D2-2 honest-shell contract every `bsl-shell` page
  already carries), never fabricated rows.
- The parity test imports `scripts/conda-forge-packaging-inventory-
  operations_priority.py::write_canvas` **unmodified** (via the same `importlib`-by-path
  technique `tests/packaging/test_openteams_handoffs.py::_load_module` already uses) — it
  does not fork, re-implement, or rewrite the canvas generator to make comparison easier.
- New/changed files stay inside `src/shared/packages/pyforge-atlas/` (dashboard + tests)
  plus the one new test file; `scripts/*.py` is read-only from this story's side.

**Block If:** Story 22.1 (`identity_ranked_export.parquet` producer) is not `status:
done`. This spec is written and reviewable ahead of that (mirrors
`spec-21-8-end-to-end-verification-gate.md`'s own precedent for a spec drafted ahead of
its hard dependency) — see Design Notes for the resulting dispatch-timing note.

**Never:**
- Do not touch `scripts/conda-forge-packaging-inventory-
  operations_priority.py`/`openteams_identity_dashboards.py` — this story is a Vizro-side
  consumer of the ranked export, not a canvas-generator change.
- Do not build pixel-perfect UX parity (search-box styling, pagination controls,
  bucket/work `Select` filters matching the canvas's exact widgets) — AG Grid's default
  per-column filter (already present on every existing `_data_page`) satisfies
  "searchable table" for v1; a bespoke search/filter UI is explicitly deferred.
- Do not wire a Cursor panel integration of any kind (out of scope per
  `vizro-canvas-parity.md` § 22.2).
- Do not build the cross-page "canvas vs Vizro" CI parity harness — that is Story 22.5's
  `tests/dashboard` parity module; this story's own parity test is scoped to the
  `identity-catalog` page only.
- Do not add a new `PageDef.kind` value — reuse `"bsl-shell"` (see Design Notes).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| `identity_ranked_export.parquet` absent (today's real state) | No file at the resolved relpath under `PYFORGE_ATLAS_DATA_ROOT` | Page builds, AgGrid renders 0 rows, Card states "Data gap" + `AD-17` "unavailable — backing file not found" | Never raise, never fabricate rows (mirrors `test_data_loaders_offline_return_empty_typed_frames_not_fabricated`) |
| Parquet present, well-formed | A fixture Parquet with the ranked-export column shape | Loader returns one row per package, columns matching the declared BSL dimensions | N/A |
| Parquet present but a queried column is all-null/untyped | A present-but-degenerate fixture | Degrades to the declared-column empty shell (mirrors `test_present_but_untyped_parquet_degrades_not_crash`), does not crash page build | Caught by the existing `_bsl_query_or_empty` `TypeError` guard — no new guard needed |
| Parity check | Hand-built `records`/`counts` fed to `write_canvas` AND a matching Parquet fixture fed to `load_identity_catalog` | Row count equal; a sample of rows match `P`/`Work`/`Core_Python_Package_Name` between the canvas `DATA.rows` array and the Vizro loader's DataFrame | A mismatch fails the story — not a "close enough" tolerance |

## Design Notes

**Why `PageDef.kind = "bsl-shell"` and not a new kind.** The existing 6-value
`_ALLOWED_PAGE_KINDS` set (`test_dashboard_dryrun.py` L99-106) documents the page-lifecycle
CONTRACT (grounded / bsl-shell / no-bsl-shell / factory / report-artifact /
live-scan-artifact), not the PRODUCER of the backing Parquet. `identity-catalog`'s backing
file happens to come from a quartet script bridge (Story 22.1) rather than a Kedro
pipeline, but the honest-empty-until-materialized contract is byte-for-byte the same as
every other `bsl-shell` page — introducing a 7th kind value purely to record "this one's
producer is a script, not Kedro" would be a distinction the existing test/consumer surface
has no use for. The `note` field on the `PageDef` is where that provenance detail belongs
(mirrors every other page's `note`).

**Why `status: ready-for-dev` despite Story 22.1 not being `done` yet.** Same reasoning
`spec-21-8-end-to-end-verification-gate.md`'s own Design Notes already established for
this project: the spec itself — Intent, Boundaries, I/O matrix, Code Map, Tasks &
Acceptance — is complete and actionable; what is outstanding is upstream code, not spec
clarity, and that is a dispatch-ordering constraint recorded in `Block If`, not an
ambiguity in what this story must build. Unlike `spec-21-8`, Story 22.1's own spec does
not yet exist in this repo (confirmed: `_bmad-output/projects/pyforge-atlas/planning-
artifacts/specs/spec-22-1-*.md` is absent as of this drafting) — only `stories.yaml`'s row
and `vizro-canvas-parity.md` § 22.1 describe its target shape. This story's Code Map
treats `identity_ranked_export.parquet`'s column names as a CONFIRMED assumption per this
drafting's own instructions (not an open question to re-litigate), but the exact relpath
under `PYFORGE_ATLAS_DATA_ROOT` is a genuine coordination point with whoever authors Story
22.1's own spec — flagged, not blocking. Whoever picks this story up should confirm
Story 22.1's live status (`fleet-picture` or its own spec frontmatter) before dispatch.

**Why the parity test bypasses `main()`'s xlsx read entirely.** `write_canvas` takes
`records`/`counts`/`tab` directly (L250) — it never touches the workbook itself (only
`main()`'s xlsx-reading path does, L600-605). Building a full multi-tab `.xlsx` fixture
just to reach `write_canvas` would add substantial fixture weight for zero additional
proof value; calling `write_canvas` directly with a hand-built `records` list is both
simpler and a closer parity test (it isolates the canvas-rendering logic from the
xlsx-parsing logic, which this story does not touch or care about).
