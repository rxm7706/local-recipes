## 2026-08-15 — `compose.yml` changed within the same Story 10.3 repair session

`src/platform/compose/compose.yml` changed again, later in the same repair session that wrote
the entry above, before it ever landed: Story 10.3's own review pass (Blind Hunter + Edge Case
Hunter) found the `platform` service never ran `manage.py migrate`, so a fresh `docker compose
up` served a database with zero tables (`GET /admin/login/` 500'd,
`django.db.utils.ProgrammingError: relation "django_site" does not exist`, confirmed live). Fixed
by adding a `command:` override to the `platform` service that runs `manage.py migrate --noinput`
before `exec`-ing gunicorn — full evidence trail (before/after, live-reverified) is in
`spec-10-3-one-image-both-engines.md`'s own Verification section
("Repair-pass re-verification"). No other file under either governed tree changed in this same
pass. Baseline re-stamped for this spec only in the same change (see command below); no
clause-conformance implication for this spec's own CAP-1 — the change is inside
`spec-python-agent-platform`'s territory, this spec's surface just happens to overlap it.
