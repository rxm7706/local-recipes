- (constraint) Five artifact classes, closed set (PRD Extraction Manifest, FR2): REFERENCED (not materialized, version-range only) | COPIED-MANAGED (tool-owned, regenerated wholesale, check reports hand-edits) | COPIED-SEEDED (written once, repo-owned forever, never auto-touched) | GENERATED-DERIVED (recomputed every run, idempotent) | HYBRID-MANAGED-REGION (repo-owned file, tool-owned marker span). Classification rule: by who must be able to change it and how an installed repo takes a later model upgrade for it. Per-artifact V1 assignment in companion extraction-manifest.md.
- (constraint) The never-write set is structural, not conventional: docs/dreams/*.md (except the one init seed), **/planning-artifacts/** (except the init-seeded specs/README.md), **/implementation-artifacts/**, docs/specs/*.md (legacy tier), _bmad/bmm/** and _bmad/core/** (installer-owned). Upgrading the model can never touch the work made with it (FR6/FR35/SC-08).
- (constraint) The never-write guard is enforced at the LOWEST WRITE PRIMITIVE, not at call sites (NFR-R4/AD-11/P-01): every byte written to a target repo passes through one fs module holding an immutable path set frozen at construction; each write resolves to an absolute symlink-resolved path and matches BEFORE opening anything (the _bmad-output/planning-artifacts symlink would be missed unresolved); an AST meta-test enumerates write calls outside fs so the guard cannot be routed around.
- (constraint) AD-01 — CLI is typer+rich, confined to cli.py; no other module imports rich or typer, so --json output and library use stay presentation-free. Plan rendering is the product's main human surface, so warden's argparse minimalism is deliberately not adopted.
- (constraint) AD-02 — one Genesis-owned state file at .genesis/state.yml (git-tracked, schema-validated); Copier's answers file is opaque and tool-owned, never read by Genesis and written only via Copier; answers are re-supplied programmatically from Genesis state on every Copier call, so Genesis state is the single source of truth.
- (constraint) AD-03 — one canonical marker grammar rendered per comment syntax (html for .md; hash for .gitignore/.toml/.yml/shell); format is DECLARED per artifact in the manifest, never sniffed by content; the marker sha covers the region body only so the marker line is not self-referential; nested or overlapping regions are a hard error.
- (constraint) AD-04 — genesis check RE-IMPLEMENTS the generic subset of the repo's bmad_drift_check.py (the Finding shape, the HARD/DRIFT/INFO ladder, the coverage check, --json); it does not import, vendor, or extract it. ~85% of that 662-line script is local-recipes factory-specific. The two detectors coexist; convergence is explicitly out of V1.
- (constraint) AD-05 — the manifest is ONE YAML document, entries keyed by stable artifact id and never by path (paths are per-repo), each carrying class, path, format, regions+anchors, since/until model-version bounds, applies_to, and rationale. One file keeps coverage a single-pass check and makes the manifest reviewable as a diff — it IS the product's contract.
- (constraint) AD-06 — region insertion uses a declared ordered anchor list with append-at-EOF fallback and never mid-file guessing; never inserts inside a fenced code block; the chosen anchor is always reported in the plan so a human reviewing it can veto placement.
- (constraint) AD-07 — the plan is a machine-readable artifact at .genesis/plan.json, gitignored by default, carrying a repo_fingerprint (git HEAD + dirty flag + hashes of the artifacts it names); apply REFUSES a plan whose fingerprint no longer matches. Deliberately not committed (unlike Nx's migrations.json): a plan is cheap to regenerate and a committed stale plan is a hazard.
- (constraint) AD-08 — no eject verb in V1, but state must not preclude one: for every managed artifact state records id, path, class, body_sha, and inserted_region_span, which is sufficient for a future eject to strip markers and forget artifacts without touching content.
- (constraint) AD-09 — legacy conventions are preserved, recorded in state.legacy[], and at most advised (an INFO finding naming the successor); never migrated, never written to. Genesis ships no automated Tier-1 to Tier-2 migration: legacy content is the team's work product and falls inside the never-write set.
- (constraint) Every mutating verb is the same resolve->detect->plan->apply pipeline over a different input (A-01); check is adopt's detect+plan with the apply stage structurally unreachable, which is why 'check never writes' is cheap to guarantee rather than a discipline. Detect is pure (no I/O side effects); apply consumes only a serializable Plan and never re-derives state; hash guards are checked in detect, never in apply.
- (constraint) Managed-region replacement is pure byte-span substitution between markers, never a three-way merge and never semantic markdown parsing — so a half-merged file and a conflict marker are not representable states (L-05/FR44/P-06/NFR-R3).
- (constraint) Idempotence is DEFINED as plan-emptiness (AD-10): a verb is idempotent iff detect+plan immediately after a successful apply yields zero actions. This makes the local-recipes oracle (SC-02) and adopt-twice (SC-03) the same assertion against different repos — one mechanism, two proofs.
- (constraint) Copier is a dependency, not a framework (A-04/P-02/FR55): exactly one module imports copier, and only its public run_copy/run_update/run_recopy; pinned >=9.17,<10 by range with a version-range sync test. Copier's code-executing template features stay gated behind an explicit --unsafe flag (FR56/NFR-S1).
- (constraint) adopt and update are dry-run/two-phase by default and refuse on a dirty git worktree, because git is the designated undo mechanism (L-06/FR14/FR20/FR29/NFR-R2). State is written LAST, after all file writes succeed, in one atomic replace — the bmad-switch marker/symlink desync lesson encoded (P-08).
- (constraint) Two clocks (AD-05/L-04): CLI semver and operating-model semver move independently, both recorded in state; migrations are keyed to model version only, are pure plan-producing functions that never write directly, and are applied exactly once.

- (decision) 2026-07-31 FOLD THE CLI INTO MARSHAL; RETIRE THE `genesis` BINARY (operator call). No separate `genesis` executable: the verbs become Marshal subcommands. Rationale, in order of weight. (1) NOTHING IS LEFT OF THE RELATION — the 2026-07-28 split completed on 2026-07-30; `pyforge-genesis` now holds only the two constitutive Dreams and an `epics.md` whose first line is "No epics, and that is the contract", while the installer's entire chain (Spec, manifest, PRD, architecture, 6 epics, 19 stories) sits under `pyforge-marshal`. Zero artifacts overlap. The product is named after a project explicitly separated from it, on the grounds that constitutive records and the machine that installs them are different nouns (Charter §5). (2) THE NAME RECORDS ITS ORIGIN, NOT ITS JOB — the same defect the Charter already corrected once, when `seeded`/`in-deck`/`in-spec` were retired for "naming a file or a place rather than a state". (3) THE OWNERSHIP ARGUMENT RESTED ON A SPENT VERB — this Spec's own case for Marshal ownership is that "Marshal\'s CLI cadence already opens with `marshal init`", but shipped `marshal init <slug>` provisions a LOOP HOME (story 1.4), and the Charter cadence separately uses `marshal init --spec` for a project blueprint. Three meanings of `init`, resolved by folding rather than by a fourth namespace. (4) It matches the Execution Doctrine (execution has one owner) and the runtime-orchestration Dream seeded the same day (docs/dreams/one-front-door.md).
- (open) 2026-07-31 VERB MAPPING IS NOT DECIDED — folding is agreed; the surface is not. `genesis check` and the shipped `marshal homes`/`config` are all conformance-shaped; `genesis init` collides head-on with the shipped `marshal init <slug>`; `genesis adopt`/`update`/`explain`/`version` have no collision. Candidate shapes: a `marshal repo <verb>` group that keeps the installer distinct inside one binary, or flat verbs with `init` renamed on one side. Deliberately left to the re-derivation rather than guessed here, because the 19 story keys under Epics 10-12 are named for the old verbs and renaming them is the expensive half.
