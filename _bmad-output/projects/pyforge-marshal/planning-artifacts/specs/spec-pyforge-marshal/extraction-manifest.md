# The Extraction Manifest — V1 per-artifact classification

Companion to `SPEC.md` (folded in 2026-08-02 from genesis-installer's own Spec; original at
`archive/_bmad-output/projects/pyforge-marshal/planning-artifacts/specs/spec-genesis-installer/extraction-manifest.md`).
This manifest is what CAP-10 (genesis-installer's former CAP-1, "model-as-data") is judged
against. The kernel's Constraints declare the five classes, the classification rule, and the
never-write set as the normative contract; this file holds the **V1 inventory** — which
artifact sits in which class, and why. It is the reference `genesis explain <artifact>`
renders from, and the thing a manifest diff is reviewed against.

Derived from a live inventory of the model surface in `local-recipes` (2026-07-25),
**re-audited 2026-07-31** — that audit added ten REFERENCED rows the V1 inventory had
missed entirely and flagged two rows as restated-rather-than-derived. See the Spec's
memlog for the findings; the gaps are recorded there rather than silently closed here,
because this file is a companion and the kernel re-renders from the log.

## The classification rule

> Classify each artifact by **who must be able to change it** and **how an installed repo
> takes a later model upgrade for it.**

| Class | Definition | On `genesis update` | On hand-edit |
|---|---|---|---|
| **REFERENCED** | Not materialized. The repo depends on it by version range; it lives upstream. | nothing in the repo changes | n/a |
| **COPIED · MANAGED** | Materialized, **tool-owned**. The repo should not hand-edit it. | regenerated wholesale | `check` reports; `update` refuses without `--force` |
| **COPIED · SEEDED** | Materialized once as a starting point, then **repo-owned forever**. | never touched | expected and fine |
| **GENERATED · DERIVED** | Computed from the neutral contract and/or repo state. | recomputed every run (idempotent) | overwritten on next run; `check` reports |
| **HYBRID · MANAGED REGION** | A repo-owned file containing a tool-owned, marker-delimited span. | only the span is replaced | `check` reports hash mismatch on the span only |

The Dream posed a three-way split (copied / referenced / generated). "Copied" divides into
**MANAGED** and **SEEDED**, and that distinction is load-bearing rather than pedantic: it
is exactly what decides whether a model upgrade may rewrite a file.

## HYBRID · MANAGED REGION

| File | Region(s) | Rationale |
|---|---|---|
| `AGENTS.md` | `tiers`, `portability-contract`, `dream-first-workflow` | the neutral contract must upgrade; the rest of the file is the repo's own |
| `CLAUDE.md` | `tiers`, `bmad-multiproject` | in `local-recipes` this is ~230 lines of repo-specific guidance around a small model core; the core must upgrade, the rest must never be touched |
| `.gitignore` | `model-ignores` | the tier rules in executable form, inside a file every repo owns |
| `README.md` (optional) | `model-badge` | opt-in; off by default |

Marker grammar (per AD-53 in the kernel):

```
<open> genesis:begin region=<name> model-version=<semver> sha=<8-hex> <close>
<open> genesis:end region=<name> <close>
```

Registry v1 covers `html` (`<!-- … -->`) for `.md` and `hash` (`# …`) for `.gitignore`,
`.toml`, `.yml`/`.yaml`, and shell. `slashstar` is reserved and unused in V1.

## The never-write set

Restated from the kernel's Constraints for locality. Enforced by code and proven by test,
not by convention.

| Path | Why |
|---|---|
| `docs/dreams/*.md` (except the one seed at `init`) | Tier 0 is the team's aspiration |
| `**/planning-artifacts/**` (except the seeded `specs/README.md` at `init`) | Tier 2 is the team's spec and planning work |
| `**/implementation-artifacts/**` | Tier 3, gitignored, runtime scratch |
| `docs/specs/*.md` | legacy tier — preserve and mark, never edit |
| `_bmad/bmm/**`, `_bmad/core/**` | installer-owned; regenerated by BMAD |

## Watch metrics — signals that a classification was assigned wrong

These do not gate a release; they are read after adopters accumulate, and each has a
specific remedy in the manifest rather than in the engine.

| Signal | What it means |
|---|---|
| Manifest entries in **COPIED · SEEDED** that adopters later hand-edit back *toward* the model | the class was assigned wrong — those artifacts should be COPIED · MANAGED |
| A growing `skips[]` list across adopters | the model is being rejected in practice at that path |
| Migrations authored per model **minor** version | if every minor needs a migration, the model surface is too volatile to install (the unresolved K-03 threshold) |

## `unclassified-deferred`

`.claude/skills/**` (skill content), `pixi.toml` task blocks, and
`docs/reference/library-llms-full.md` are model-adjacent but too repo-specific to classify
confidently at V1. They are recorded as `unclassified-deferred` in the manifest, so the
coverage check treats deferral as an explicit, enumerated state rather than a gap.
