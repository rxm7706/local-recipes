- (note) Governs sprint-status-ledger.yaml's generator (scripts/promote_sprint_status.py), core/status.py::derive_home_state (fleet view), and Epic 4's spec-promotion/reconciliation machinery in pyforge-marshal (3 candidate surfaces). Source: docs/dreams/quick-dev-reconciliation.md, captured 2026-08-11.
- (note) Confirmed empirically: grep for quick-dev/quick_dev across src/shared/packages/pyforge-marshal/ returns zero matches -- every reference lives in planning prose (architecture-bmad-infra.md, development-guide.md, source-tree-analysis.md), never in core/, cli/, adapters/, or a schema.
- (note) sprint-status-ledger.yaml's development_status map is a flat done|backlog vocabulary with no field for how a story reached done; scripts/promote_sprint_status.py:24 states plainly that bmad-loop marks a story done at DEV completion -- a quick-dev completion never calls that path, so the key stays backlog forever regardless of real, merged, tested work.
- (note) core/status.py::derive_home_state (Story 5.1, AD-5) derives fleet state from journals and run state only -- a quick-dev session leaves no journal entry, so Marshal cannot distinguish 'loop between stories' from 'a human just landed a real story by hand.'
- (note) Epic 4's durability guarantees (Story 4.1 spec promotion, Story 4.6 reconciliation) key entirely off bmad-loop's own journal/merge signal -- a quick-dev'd story's spec, if one exists, gets none of that promotion/durability treatment today.
- (capability) CAP-1 detect a quick-dev completion after the fact -- something observes git (repository fact) plus existing spec/story-identity artifacts and recognizes that a backlog story's work landed via a path other than bmad-loop, without a hand-maintained flag.
- (capability) CAP-2 fold the detected completion into the tracked ledger -- the story's key advances out of backlog in sprint-status-ledger.yaml (or the mechanism feeding it), and the record distinguishes bmad-loop vs bmad-quick-dev as the completion path, so marshal status / the fleet dashboard can show it without commit archaeology.
- (capability) CAP-3 give a quick-dev'd story's spec the same durability guarantee Story 4.1 gives a loop-landed one -- promoted means will still exist next week, regardless of which path produced it.
- (capability) CAP-4 mixed-mode coherence -- an operator can hand-pick any backlog story for bmad-quick-dev while that station's bmad-loop run is between stories, or mid-run on a DIFFERENT story, and Marshal's tracked state (ledger, dashboard) stays coherent either way; no corruption of the live run's own journal.
- (constraint) Not a routing change -- this spec does not decide whether Marshal ever invokes bmad-quick-dev on an operator's behalf (PRD Q-16's open question, untouched). Strictly reconciliation of a completion that already happened outside Marshal's control.
- (constraint) Not a concurrency/locking mechanism -- mid-run-different-story means the ledger stays coherent when a quick-dev completion is folded in around a live loop run, not that Marshal orchestrates the two simultaneously or arbitrates a same-file conflict. Genuine concurrent-writer coordination is out of scope (a sibling investigation thread owns concurrency more broadly).
- (constraint) Stays inside AD-5/AD-33 -- detection reads git (repository facts) and existing spec/story-identity artifacts, never a new hand-maintained flag, and never a special case bolted onto the loop's own journal format.
- (question) Which concrete detection signal (a merge-commit heuristic, a spec-promotion event, an explicit operator-declared 'this stroy was quick-dev'd' marker checked against observed diff/merge evidence, or some combination) answers 'did this story complete outside the loop' -- a story-level design decision, not resolved by the Dream.
- (note) Non-goal (from the Dream): bmad-quick-dev itself does not change and does not gain any Marshal dependency -- it keeps working exactly as it does today, run directly by a human against any station's codebase.
- (event) Spec drafted and self-validated 2026-08-11 (Pass 1 coherence + Pass 2 preservation against the Dream, both clean).
