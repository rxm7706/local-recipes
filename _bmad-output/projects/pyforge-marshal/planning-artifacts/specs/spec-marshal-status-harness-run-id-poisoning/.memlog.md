- (direction) Source: docs/dreams/marshal-status-harness-run-id-poisoning.md (owner: marshal, status: dreamt), captured + specced same day at operator request after a live root-cause during a fleet landing pass.
- (decision) Why: reproduced live 2026-08-15 -- a spin-time poll timeout (MRS-SPIN-004) journals harness_run_id: null permanently into the launch OUTCOME entry; cli/status.py's only fallback (_resolve_harness_run_id_for_resume) re-reads the same poisoned field and can never recover, even though .bmad-loop/runs/<id>/state.json is real, readable, and correctly updating for the run's whole life. A prior session (2026-08-13) logged this same symptom as resolved after simply not observing it once -- it was never fixed.
- (capability) CAP-1 -- harness_run_id recovers via filesystem discovery. intent: a status read for a run whose journal-poll timed out (harness_run_id: null) recovers the real bmad-loop run id via the same .bmad-loop/runs/ filesystem discovery cli/spin.py::_latest_run_dir already performs, rather than permanently reporting unknown. success: given a run whose journal entry has harness_run_id: null but whose .bmad-loop/runs/<id>/ directory exists and is readable, marshal status reports the run's real state (running/idle/stopped), not unknown -- reproduced against the live 2026-08-15 case (pyforge-doctor story 9.1's spin).
- (capability) CAP-2 -- MRS-STATUS-002 keeps firing correctly for genuinely unrecoverable cases. intent: a run whose directory truly cannot be found or read still reports unknown with the MRS-STATUS-002 finding -- the fix narrows the failure mode, it does not remove the honest-degradation signal. success: given a run with no discoverable .bmad-loop/runs/ directory at all (or an unreadable one), status still reports unknown and the finding still fires.
- (constraint) No live subprocess or network call per status read (NFR-14's own 'no live query per home' discipline) -- the fallback stays a plain Path.glob, the same budget _latest_run_dir already operates within.
- (constraint) Must not weaken MRS-STATUS-002's own honest-degradation contract for the case it actually protects -- CAP-2 exists specifically to hold this line while CAP-1 narrows the surface that trips it.
- (non_goal) Not fixing the poll's own timeout window or retry behavior -- this Spec is about the permanent-blindness consequence of a timeout, not about preventing timeouts from happening in the first place.
- (non_goal) Not a general audit of every other journal field with a similar single-write-no-repair shape -- scoped to harness_run_id specifically, the field this session's live reproduction actually hit. bmad-loop-liveness-footgun (engine.pid's own two-field liveness misread) is a separate, already-captured sibling Dream, not this Spec's territory.
