## Intent

**Problem:** Nothing in the tree durably records what a gate evaluation checked or said (`marshal gate evaluate` only prints to stdout), and AD-34's mandated single-redactor egress boundary (`core/egress.py`, a `Redacted` payload type, one egress-port registry) does not exist yet -- both `cli/gate.py` and `ports/process.py` merely note this as "planned."

**Approach:** Add `core/egress.py` owning a `Redacted` wrapper, the single redacting serializer (`to_redacted`), a pure `build_gate_record` shaping function matching the new `schemas/gate-record.json`, and the egress-port classification registry; add a new `ports/record.py` (`RecordPort`) as the first and only port classified `egress: true`, implemented by a new `LocalFs.write_redacted_atomic` in `adapters/fs_local.py` that reuses the existing `write_text_atomic` write mechanics.

## Boundaries & Constraints

**Always:**
- `core/egress.py::Redacted` -- a frozen dataclass wrapping `text: str` (already-redacted, already-serialized). `to_redacted(payload: Mapping[str, object]) -> Redacted` recursively walks a dict/list/scalar payload: a key matching `core.policy.is_secret_key` has its value replaced by `core.policy.REDACTED_SENTINEL` (reuses Story 1.3's existing suffix vocabulary -- no second secret-key concept); every `str` value (keyed or not) is additionally scanned against a small closed set of known token-shape regexes (GitHub PAT `ghp_[A-Za-z0-9]{36}`, GitHub fine-grained PAT `github_pat_[A-Za-z0-9_]{20,}`, AWS access key `AKIA[0-9A-Z]{16}`, a generic `sk-[A-Za-z0-9]{20,}` secret-key prefix) and any match is replaced with the same sentinel; result is `json.dumps(..., sort_keys=True)` wrapped in `Redacted`. Raises `TypeError` for a non-`Mapping` payload (contract violation).
- `core/egress.py::build_gate_record(*, story_key: str, commands: Sequence[Mapping[str, object]], scope_check_verdict: str | None, tree_revision: str, timestamp: str) -> dict[str, object]` -- pure, matches `schemas/gate-record.json` exactly: `story_key` is canonicalized via `core.identity.normalize()` (reuses AD-23's one parser, stored as `str(key)`); each `commands` entry requires `command`/`returncode`/`resolvable` (mirrors `core.gate.classify_outcome`'s existing report shape); `scope_check_verdict` must be `None` or one of `core.model.Verdict`'s 6 values (Story 2.3 doesn't exist yet, so `None` is the only value any real caller can supply today); `tree_revision` a non-empty `str`; `timestamp` a UTC ISO-8601 string (validated via `datetime.fromisoformat`, tz offset zero -- parsing only, never `datetime.now()`, so this stays clock-free per AD-4). Malformed input raises `ValueError`/`MalformedStoryKeyError` (a caller bug, matching `EffectivePolicy`/`StoryKey`'s own "raise for contract violations" convention) -- no new `MRS-*` finding code, mirroring Story 2.5's `describe_gate_mode` precedent.
- `core/egress.py::EGRESS_PORTS: Mapping[str, bool]` -- the one registry, keyed by Protocol class name: `{"ProcessPort": False, "FsPort": False, "HarnessPort": False, "VcsPort": False, "RecordPort": True}`.
- `ports/record.py` (new) -- `RecordPort` Protocol, one method: `write_redacted_atomic(path: Path, payload: Redacted) -> None`. `adapters/fs_local.py::LocalFs.write_redacted_atomic` implements it by delegating to the existing `self.write_text_atomic(path, payload.text)` -- no new write mechanics, only a type boundary.
- `tests/meta/test_ad34_egress_registry_completeness.py` (new, AST/introspection style matching `test_ad26_seed_field_access_guard.py`/`test_ad7_verdict_sole_ownership.py`): (1) every `Protocol` subclass defined under `pyforge.marshal.ports.*` has an entry in `EGRESS_PORTS` -- a new port module with no entry fails the build; (2) every port classified `True` has no method parameter type-hinted bare `str` (must be `Redacted`); (3) no module other than `core/egress.py` references its private `_TOKEN_SHAPE_PATTERNS` (AST scan, matching `test_ad26`'s privacy-boundary style) -- the structural proof that a future caller cannot hand-roll its own redaction.
- Redaction fixture tests cover BOTH halves: a secret-shaped key (e.g. `API_TOKEN`) and a known-shape substring buried in an ordinary-named field, plus a non-redacted control proving no over-redaction.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Secret-shaped key | `{"API_TOKEN": "x"}` | value replaced with `REDACTED_SENTINEL` | No error expected |
| Known token shape in an ordinary field | `{"note": "leak ghp_" + "a"*36}` | the matched substring replaced with the sentinel | No error expected |
| Ordinary data | `{"command": "pytest -x"}` | passes through unchanged | No error expected |
| Non-`Mapping` payload | `to_redacted("bare str")` | rejected | `TypeError` |
| Valid gate record | canonical `story_key="2-6"`, 2 commands, `scope_check_verdict=None`, valid UTC timestamp | dict matching `schemas/gate-record.json`, `story_key` canonicalized to `"2.6"` | No error expected |
| Malformed timestamp | `timestamp="not-a-date"` | rejected | `ValueError` |
| Non-UTC or unparseable story key | `story_key="!!"` | rejected | `MalformedStoryKeyError` |
| New port added, not classified | a 5th `Protocol` under `ports/` with no `EGRESS_PORTS` entry | meta-test fails | Build fails (pytest) |
| Egress-classified port with a bare `str` param | hypothetical `RecordPort` method typed `content: str` | meta-test fails | Build fails (pytest) |

## Design Notes

**Why `cli/gate.py` is untouched.** Epics.md's declared Surface for this story omits it, `core/gate.py`, `ports/vcs.py`, and `adapters/vcs_git.py` -- and Story 2.4 already set the precedent of shipping a fully-tested pure function (`classify_doc_only_declaration`) with zero `cli/gate.py` wiring, landing `done` with `followup_review_recommended: false`. Live wiring here would additionally need a `VcsPort` method returning a tree revision (none exists) and a real scope-check verdict (Story 2.3, blocked on S-3.2) -- both genuinely out of reach without widening the declared surface, which AD-27 forbids a machine-drafted spec from doing.

**Why two redaction mechanisms coexist.** `core/policy.py::redact()` (Story 1.3) redacts by field NAME for policy-value DISPLAY (`cli/config.py`); `core/egress.py::to_redacted` is the NEW, broader AD-34 serializer for durable records, reusing `policy.is_secret_key`/`REDACTED_SENTINEL` rather than inventing a second vocabulary, but adding shape-pattern scanning `policy.redact()` never had. `cli/config.py --materialize`'s own persisted-record write is a real, pre-existing AD-34 gap this story doesn't retrofit (out of surface) -- named here and in `deferred-work.md`, not silently left unmentioned.

**Why the registry lives in `core/egress.py`, not scattered per-port-file.** `ports/__init__.py`'s Story-1.1 placeholder said "each port will declare egress: true|false", but the AC requires ONE registry -- and a per-file declaration importing `Redacted` from `core.egress` while `core.egress` also imports that port module would risk a cycle. Keying the registry by class-name STRING (not an imported class reference) avoids `core/egress.py` needing to import `ports/*` at all; only the meta-test (test code, outside the package's own layering rules) imports both sides.
