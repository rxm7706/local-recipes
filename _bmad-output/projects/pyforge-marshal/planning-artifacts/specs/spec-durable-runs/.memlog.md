- (decision) Source: docs/dreams/durable-runs.md (owner marshal, status dreamt). Why: an unattended factory that loses its own output is not autonomous, it is lucky — measured 2026-07-31: 6 unpushed station branches, ~5,150 lines on recover/*, herald 1.2's 734-line transport story unpushed 6 days, 156 dangling commits one git gc from unrecoverable, marshal 1.8's 1,748 lines unpushed 40 minutes. Nine detectors ran green throughout because none asked the durability question.
- (capability) CAP-1 unpushed-work detection (SHIPPED). Intent: a runtime-scope detector finds local branches carrying unique content on no remote, plus dangling commits holding real work git gc may collect, and reports unknown rather than green where it cannot run (CI has no local branches/dangling objects). Success: scripts/unpushed_work_check.py (pixi task unpushed-work-check) flags every such branch/commit; vacuous-pass avoided by scope=runtime exclusion from CI.
- (capability) CAP-2 interval push stopgap (SHIPPED). Intent: while any bmad-loop engine runs, push every loop home's station + per-story branches on an interval so worst-case loss is bounded to one interval rather than unbounded; exits on its own when the fleet does; read-only against working trees so safe beside a live run. Success: scripts/loop_push_watch.py (pixi task loop-push-watch), default interval 1800s, flags --interval N / --once / --quiet.
- (capability) CAP-3 stage-boundary push (OPEN). Intent: the durable fix — bmad-loop's supervisor (owned by Marshal, since bmad-loop itself is a git-pinned external dependency) pushes after each stage boundary of a run: after the dev commit, after the review verdict, after the merge — so loss is bounded by a stage, not a timer. Success: a killed session between two stage boundaries loses at most the incomplete stage; loop-push-watch's interval window is no longer the binding bound.
- (capability) CAP-4 durability as a fleet-launch default (OPEN). Intent: the interval-push watcher starts automatically as part of a fleet launch rather than requiring a human to remember to start it by hand — it was absent for the entire 2026-07-31 run for exactly that reason. Success: launching the fleet starts the watcher (or the stage-boundary push once CAP-3 ships supersedes it); no manual step required.
- (capability) CAP-5 durability reported as a run/console property (OPEN). Intent: a run whose work is not on a remote is not green — the fleet console (factory-console / Guildhall) refuses to report a row clean when its branches are unpushed, the same refusal discipline it already applies to an unowned Dream row. Success: the dashboard surfaces an unpushed-work finding on the owning chain's row rather than only in a separate detector's CLI output.
- (capability) CAP-6 branch retirement (OPEN, PR #178 recorded the frontier item only — no code yet, verified: PR #178 touched only docs/dreams/durable-runs.md). Intent: the inverse of CAP-1 — derive which station/story branches may be released: content in main BY PATCH-ID (not a diff heuristic; three-dot mismeasures squash-merges, two-dot mismeasures branches main has moved past), the branch's run concluded, and its story done with a merge sha. loop/* branches and rescue/* tags are never candidates (loop/* is how the fleet works; rescue/* tags are the only reachability for commits git gc would otherwise collect). Success: a pruning run proposes retirements only where it can name the evidence (merge sha + patch-id match + concluded run) per branch, dry-run by default like adopt, refuses rather than defaults to delete on anything unproven.
- (constraint) Interval-push and stage-boundary push are read-only/append-only against working trees and remotes — push only, never force-push or rewrite — so they cannot disturb a live session or destroy work.
- (constraint) unpushed-work-check is scope=runtime and MUST stay out of the scope=repo/CI detector set: a CI runner has neither local branches nor dangling objects, so running it there would be a vacuous pass (false green), not a stricter gate.
- (constraint) Two branch prefixes are permanently excluded from CAP-6 retirement: loop/* (how the fleet operates) and rescue/* tags (the only reachability for commits git gc would otherwise collect — untagging re-arms the failure they exist to prevent).
- (constraint) CAP-6's classification must use patch-id matching against main, not a two-dot or three-dot diff heuristic — both were tried in this Dream's own session and both misclassified real cases (squash-merges, branches main had moved past).
- (non-goal) Not a general git-hygiene tool — scope is bounded to the loop/story/station branches this factory's fleet creates, not arbitrary developer branches.
- (non-goal) Not a replacement for CAP-3 (stage-boundary push) — CAP-2 (interval watch) is an explicitly named stopgap that stays only as a floor/backstop once CAP-3 ships.
- (non-goal) Rescue-tag lifecycle management (when a rescue/* tag itself may finally be dropped) is out of scope for this Spec — CAP-6 only reads rescue/* as a permanent exclusion, it does not manage their retirement.
