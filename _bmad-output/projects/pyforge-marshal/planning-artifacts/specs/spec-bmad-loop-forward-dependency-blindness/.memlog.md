- (origin) Found 2026-08-03 setting Marshal up to run its backlog unattended. `next_actionable` (`bmad_loop.sprintstatus`, called from `engine.py::_pick_next`) is a strict file-order scan within the current epic with NO `depends_on` concept — confirmed against the installed library, not inferred. Marshal's own epics.md had already documented three forward deps (2.3→S-3.2, 2.7→S-4.1, 8.5→S-10.2) and the engine could see none of them.
- (decision) Fix is a non-standard `blocked` status in the sprint feed, not an engine patch: `load()` does not validate `status` against its declared `STORY_STATUSES`, and `ACTIONABLE_STATUSES` naturally excludes anything that is not `backlog`/`ready-for-dev` — the same mechanism the pre-existing `optional` retrospective status already relies on. bmad-loop is an installed conda package, so an engine patch would be undone by the next reinstall.
- (constraint) `ACTIONABLE_STATUSES` is IMPORTED from `bmad_loop.sprintstatus`, never restated, so the check stays tied to real engine behavior if upstream changes it. This is why the detector cannot move into a lean product env that lacks the harness (see the §6 note below).
- (capability) CAP-3 shipped `scripts/forward_dependency_check.py`, self-registered via `scripts/detectors.py`. PR #238, merge `a825ac0749`, 2026-08-03. The retroactive SPEC was written 2026-08-08 — the Dream went straight to code, a real process gap against the Dream-first mandate.
- (event) SPEC written retroactively 2026-08-08 from the Dream's "What is real" section plus the shipped detector. Not invented; traceability only in frontmatter.

## 2026-08-08 — the detector's own coverage was dishonest

- (event) Investigated the fleet-readiness note that 4 of 8 stations read `[unmeasured]`. The premise was wrong in both directions: the DATA was fine, the DETECTOR was not. Two independent defects, one per direction.
- (event) **Atlas was invisible, not unmeasured.** `STORY_HEADING_RE` matched only the plain `### Story 2.3:` shape; atlas writes alias-first `### Story A1 (2.1):`, so **zero** of its 46 stories parsed and its 43 real dependency declarations could not be seen. The in-code comment accepted this as "low-risk" because "atlas is already 100% shipped" — a premise that expired: atlas has 8 actionable stories in Epics 12–13, which is precisely where its machine-readable Deps fields live.
- (event) **Mason was a FALSE GREEN, and had been since this detector shipped.** The coverage gate asked whether any Deps *text* existed (`any(deps ...)`), but `DEP_RE` reads only `S-<epic>.<num>`. Mason's 30 declarations are prose (`'Story 1.4 (informs cost of the "add two more recipes" branch)'`) — **zero** parse — so `forward` was always empty and the station always reported measured-and-clean. CAP-1's claim that atlas and mason were "structured enough to carry a mechanical Deps field" was simply false for mason; corrected inline in the SPEC.
- (decision) Coverage is now keyed on READABLE references, four classes: `NO-DISPATCH` (ledger positively shows 0 actionable — nothing dispatchable, so no forward dep can fire; a measured fact, explicitly not a parse-clean claim), `MEASURED` (every declaration resolved or explicitly none), `PARTIAL` (a real dep stated in an unreadable grammar; readable refs still checked, ratio reported), `UNMEASURED` (no declaration and work remains, or ledger unreadable).
- (constraint) `NO-DISPATCH` requires POSITIVE ledger evidence — ≥1 story key parsed AND none actionable. A missing or unparseable ledger falls to `UNMEASURED`, never `NO-DISPATCH`, or absence would read as reassurance. Live: herald 0/47, scribe 0/9, warden 0/31.
- (constraint) The LAST non-empty stdout line stays the authoritative verdict and carries the coverage breakdown: `scripts/detectors.py` lifts `tail[-1][:200]` as the registry/dashboard summary, so appending output after it would silently change what the fleet reports.
- (decision) Grammar extended, binding on all stations: `S-<epic>.<num>` story · `S-<epic>.*` whole epic · `<station>:S-<epic>.<num>` cross-station · `—` none. Prose allowed ONLY as trailing context. The two new forms exist because declarations legitimately depend on a whole epic (`'Epic 3 complete'`) or another station (atlas 12.2 → `Steward S-2.1`) and neither was expressible — which is WHY those declarations were prose. The cross-station form also fixes a live misread: atlas 12.2 parsed as atlas's OWN epic 2, benign only because 2 < 12 and that epic is shipped.
- (event) Non-atlas parsing proven unchanged by tuple-diff before/after (292 tuples across 7 stations, byte-identical); atlas went 0 → 46.
- (note) A by-hand audit of all 62 prose declarations found **no hidden forward dependency** — mason's chain is strictly backward (1.7←1.4, 3.4←3.1/3.2/3.3, 7.3←7.1/7.2), atlas's likewise. So the prose is a legibility gap, not a live risk, and migrating it cannot red CI.
- (note) A mechanical token-substituter was written, dry-run, and DISCARDED: prose negations invert under substitution. `'**Blocks I4 and I5**'` (reverse-direction info) became deps on 10.5/10.6 — both LATER than 10.4, manufacturing a false forward-dep finding; `'none (runs manually, ahead of Epic 7's automation)'` injected `S-7.*` into a *none* declaration; `'none (independent of Epics 2–3)'` inverted "independent of" into a dependency. The migration must be hand-authored.
- (deferred) 59 prose declarations in atlas/mason/steward are NOT migrated here, so those stations report `PARTIAL`. Migration + a gate that FAILS on `PARTIAL` must land in ONE change, because the gate reds CI until the migration completes.
- (note) Charter §6 relevance: this detector judges every station's epics INCLUDING Marshal's, and is owned by Marshal — Marshal grading Marshal. Its `bmad_loop` import blocks a naive re-home into the lean `pyforge-doctor` env, which carries no harness. Tracked with the fleet-wide §6 re-home, not resolved here.
