- (decision) Source: docs/dreams/fidelity-enforcement.md (owner marshal, status dreamt, ~652 lines — largest peer Dream by ~3.5x, trim deferred to after this Spec exists per its own Realization log). Why: EXEMPLAR-STANDARD.md states 10 conformance requirements; dream_chain_check enforces only INV-0..3. Rows 7-10 (per-story specs tracked, delivery records, deferred-work ledger, layout README) are written down and enforced by nothing. Verified fresh at spec time (2026-08-01, not restated from the Dream's 07-31 numbers): marshal has 10 done stories against 1 tracked story-spec (spec-1-1-...), i.e. 9 of 10 lack a tracked spec — worse than the Dream's own cited 6-of-7. Fleet-wide at Dream-seed time: 125 done / 73 tracked, gap ~52.
- (decision) The deeper finding (found during the Dream's own authoring review): the eight then-existing detectors were themselves untriggered — no .github/ workflow and no git hook invoked any of them, so a red finding never gated anything. This was fixed same-day (2026-07-31) and is captured as CAP-1 below, verified still live at spec time: .github/workflows/detectors.yml and scripts/detectors.py both exist on disk.
- (capability) CAP-1 detector trigger, advisory (SHIPPED, verified on disk 2026-08-01). Intent: every repo-scope detector runs on every PR and push to main via a derived registry that fails on its own gaps (a detector script with no pixi task, or vice versa, is itself a finding) rather than a hand-written list. Success: .github/workflows/detectors.yml invokes scripts/detectors.py --scope repo; findings post as warning annotations (advisory, non-blocking per the 2026-07-31 amendment) rather than failing silently or not running at all. Nine detector scripts confirmed present: bmad_drift_check, spec_surface_check, dream_chain_check, deferred_work_check, dashboard_drift_check, story_status_check, loop_stall_check, llms_full_check, unpushed_work_check.
- (capability) CAP-2 INV-4 -- shipped story implies tracked spec. Intent: a story marked done in a station's sprint-status ledger must resolve to a tracked specs/spec-<key>.md on main; the check names the story key and its accountable station when it does not. Closes row 7. Success: dream_chain_check (or a sibling detector reusing its registry) reports every done-without-tracked-spec gap by story key + owner; deleting a tracked story spec at random makes CI name it within one run (this Spec's overall success signal).
- (capability) CAP-3 automatic Tier-2 promotion. Intent: bmad-loop's own completion path writes a finished story's spec directly to the tracked planning-artifacts/specs/ location, rather than leaving it in gitignored Tier-3 for a human to remember to promote after merge -- the ~52-story fleet gap is the proof a manual step does not hold. Success: a story that reaches done in the loop has its tracked spec on main in the same merge, with no separate human promotion step required.
- (capability) CAP-4 reverse gate: Success signal bound to verify command. Intent: a promoted story spec's stated Success criterion binds to the verify command that gated its story, so a later change deleting or weakening that test is visible as a contract breach rather than a silently passing suite. Success: removing or defanging a story's verify command trips a finding naming the story spec whose Success signal it backed.
- (capability) CAP-5 Spec-to-chain reverse gate (extends dream_chain_check; EXEMPLAR-STANDARD rows 5-6). Intent: every kernel Constraint that compresses an enumeration must resolve to a live companion, and every chain artifact (PRD/architecture/epics) must name the Spec it decomposes -- INV-3 today checks only the shape of the chain (prds/, architecture/, epics.md exist), not that a PRD actually decomposes its Spec. Success: a companion referenced by a kernel Constraint that goes missing, or a chain artifact naming no owning Spec, is a named finding -- not silent shape-only pass.
- (capability) CAP-6 the actor-attributed event record (Scribe records; Marshal and Doctor are emission points). Intent: every act an agent or human makes or does is recorded with five fields -- who (actor class human/agent + identity), what, when, how (skill/tool/command/direct-edit), why (story key, Spec capability, or override justification) -- durably, outliving the worktree that wrote it. Captures three cases a naive design drops: a judging run that never happened (recorded as not-run, never as silent absence), an override (who bypassed which gate, on what authority), and an act that produced nothing (crash/timeout/abandoned branch). Governing rule: an absent record and a clean record must never look the same. Success: journal.jsonl's existing {ts, kind, run_id, story_key, adapter_dev, adapter_review} schema gains actor class + authority fields and is promoted out of Tier-3 (.gitignore:750) into a durable store queryable via the existing duckdb dependency and pyforge-scribe's capture seam.
- (capability) CAP-7 the ungated boundary declares itself. Intent: where a tier boundary genuinely has no gate yet, the detector registry reports it as explicitly ungated rather than passing in silence -- a green board that only means we did not look here is the false-green doctrine failing at the meta level. Success: scripts/detectors.py's registry (or dream_chain_check's scoreboard) enumerates known-ungated boundaries by name, distinct from both pass and fail.
- (capability) CAP-8 the fixed point, declared per reconciliation. Intent: when bmad-drift-check's surface-changed reconciler (or any code/contract reconciliation) runs, it records which layer was treated as owning truth for that change and why, riding the existing append-only memlog convention -- today that decision is made silently by whichever agent runs the reconciler. Success: a drift reconciliation's memlog carries a fixed-point entry a later reader can adjudicate against, rather than the decision surviving only in a session transcript.
- (capability) CAP-9 install the judge -- Doctor holds the verdict on Marshal's own rows (ratified 2026-07-28, currently unenforced). Intent: (a) a check fires when a threshold, skip-list, or disable flag in a Marshal-owned detector moves without a Doctor-side approval marker; (b) structurally, checks that judge Marshal's own conformance live in Doctor's package with no Marshal write path. This is the control that makes every other capability in this Spec trustworthy -- CAP-2 (INV-4) is a check Marshal would otherwise build, set the threshold for, and be the biggest finding against, self-graded. Success: a Marshal-authored change to a Doctor-judging check's threshold/skip-list/disable-flag is blocked or flagged without Doctor-side sign-off; until (a) or (b) ships, every verdict this Spec produces about Marshal is self-graded and the Dream says so on the board.
- (constraint) Marshal may not weaken, re-threshold, or disable a check that judges Marshal's own conformance rows (Charter ratification, 2026-07-28) -- CAP-9 is how this becomes enforced rather than prose; until it ships this constraint binds by convention only.
- (constraint) A detector declares its own scope: repo (reads tracked files, can run in CI) or runtime (observes host state -- Tier-3 feeds, tmux, ~/.bmad-loops -- and structurally cannot run in CI). A runtime detector must never be added to the CI-required set; doing so produces a vacuous pass, not a stricter gate (unpushed-work-check is the precedent).
- (constraint) A detector that cannot run reports unknown, never green -- binding on every consumer of the detector registry, not just the existing eight/nine.
- (constraint) CI detectors are advisory, not blocking (amended 2026-07-31 from the original blocking-in-CI-and-fleet design, operator decision). A red detector can still be merged past in CI; the fleet's own [verify] gate set is what currently carries the whole binding weight until CI is upgraded.
- (constraint) No detector may run as a blocking pre-commit hook. Every worktree (loop homes and per-story worktrees alike) resolves to the same .git/hooks, so a blocking pre-commit would fire inside unattended dev sessions that cannot interpret a detector failure and could convert one red check into fleet-wide story loss. pre-push is the local seam, never pre-commit.
- (constraint) INV-4 (CAP-2) cannot switch on unconditionally: it would immediately red CI against every pre-existing done-without-spec story fleet-wide. Migration doctrine (baseline the debt, never lower the rule; the exemption list may only shrink, ratchet-checked; grandfathering carries an expiry date, never open-ended) must land in the same change as INV-4 itself, not after.
- (non-goal) Writing a tenth ad hoc detector before the existing nine are wired and trustworthy is out of scope -- wiring what exists (CAP-1, shipped) was and remains the cheapest, highest-ratio item, ahead of any new check.
- (non-goal) Restoring AI-attribution commit trailers as the provenance mechanism is explicitly rejected. This repo's convention of removing AI attribution from commits/PRs stays; CAP-6's actor record is the correct home for provenance because it is structured and queryable, not prose in a commit message that only a human reader with git blame access could reconstruct.
- (non-goal) Narrowing the Spec's own kernel (making it as detailed as the code) is out of scope and rejected on principle -- the Spec-to-code gap is deliberately wide per Charter; this Spec's job is gating that gap's intermediate layers (the story spec), not shrinking the kernel itself.
- (non-goal) Adopting the source essay's privileged-layer framework wholesale is out of scope. Authorization (nothing ships unauthorized from Tier 0) stays permanently privileged and is not up for a per-change fixed point; only origination (where a change may legitimately begin) is unprivileged, and that half the factory already does via bmad-drift-check's surface-changed reconciliation.
