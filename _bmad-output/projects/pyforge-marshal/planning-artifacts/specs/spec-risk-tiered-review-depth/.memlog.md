- (note) core/policy.py DEFAULT_POLICY sets max_dev_attempts=2 and max_review_cycles=3 as flat, repo-wide ceilings -- identical for a doc-only story and a cross-cutting rewrite; no dial exists between full review and skipped review.
- (note) core/gate.py::classify_doc_only_declaration (Story 2.4, FR-23) read in full: a PURE function of two already-gathered facts (declared_doc_only, has_uncommitted_changes), zero I/O. Fails only the one combination indistinguishable from silent failure (no changes AND not declared doc-only). Feeds exactly one finding code (MRS-GATE-006) into gate pass/fail -- it says nothing about review depth, only about whether a no-diff story is allowed to close. Real precedent for the CLASSIFICATION IDIOM (pure fn of declaration + observed fact), never before pointed at review scheduling.
- (note) DW-AD23-3 incident (_bmad-output/policy-defaults.toml:19-36) read in full: upstream max_followup_reviews default of 1 silently damped five still-recommended follow-up reviews across three projects (atlas 10.5/10.6, marshal 1.1, warden 6.3/5.1) into a gitignored ledger -- the reason deferred-work-check exists. Repo-wide value is now 2, explicit, with reasoning inline. Lesson: a cap that is too low doesn't fail loudly, it produces a clean-looking envelope while dropping real reviewer-identified work.
- (capability) CAP-1 classify a story's review weight before review runs, mechanically, from something already true about it (its own declaration, its diff shape, or both) -- the same pure-function-of-already-gathered-facts idiom classify_doc_only_declaration already establishes.
- (capability) CAP-2 vary review depth/cost by weight WITHOUT ever skipping the independent reviewer -- a low-weight story may run fewer review cycles or a cheaper review pass; gate_mode=none's human-approval-only boundary is untouched.
- (capability) CAP-3 preserve deferred-work-check's full capture guarantee at every tier -- any review-recommended follow-up is tracked with the same durability regardless of which weight tier the story ran at, so a tightened cap for a low-weight story can never reproduce DW-AD23-3 (a real recommendation silently vanishing into an unindexed ledger entry).
- (capability) CAP-4 surface the tier a story's review ran at, and why, in the same machine-readable envelope other gate output already uses -- never a silent choice.
- (constraint) Never skips the independent reviewer -- gate_mode=none already means human-approval-gate-only; that boundary is load-bearing and this spec does not reopen whether review runs at all.
- (constraint) Never lowers max_followup_reviews (or an equivalent cap) below what deferred-work-check can still fully capture, for ANY tier -- DW-AD23-3 must be cited by name in the downstream story and the proposed mechanism proven not to reproduce it before it ships.
- (constraint) Not model-tiering/adaptive-escalation -- a cheaper review model is one plausible lever this spec names as a possibility, but DEV-side model selection by difficulty and adaptive escalation generally are a separate, already-scoped sibling investigation thread; this spec does not decide or duplicate that mechanism.
- (note) Non-goal (from the Dream): not a prescription of which signal drives the classification, which review lever it adjusts (cycle count, model choice, a cheaper lens set), or how the tier is surfaced -- left to the downstream story's design.
