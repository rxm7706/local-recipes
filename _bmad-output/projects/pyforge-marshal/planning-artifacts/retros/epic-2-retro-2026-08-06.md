# Epic 2 Retrospective: Verify commands are gated, honestly

**Date:** 2026-08-06
**Epic:** 2 — 7/7 stories done (2.1–2.7)
**Facilitator:** Claude (direct synthesis, condensed per operator preference — matches the Epic 3 retro's format)

## Summary

The operator can run `marshal gate evaluate` and trust the verdict: commands are classified through a closed, never-false-green lattice (2.1/2.2), scope changes are checked against declared and frozen surfaces with narrowing-only semantics (2.3), doc-only stories don't trip false failures (2.4), gate mode carries an explicit autonomy label (2.5), evidence is redacted at the egress boundary (2.6), and — closing the epic — a gate now confirms it's still running the commands a story's own tracked spec promised (2.7). All 7 specs are durably archived in `planning-artifacts/specs/`.

## What went well

- **Zero `intent_gap`/`bad_spec` findings across the epic's own review rounds** — every review finding stayed at `patch`/`defer`, matching Epic 3's own record. The specs were consistently implementable as written.
- **2.3 and 2.7 — the two stories done via manual `bmad-quick-dev`, not `bmad-loop` — were the only ones in the epic with zero `oversized` warnings.** Direct replication of Epic 3's own finding (3.8 was the one `bmad-loop`-free story there, also unflagged). Two epics now show the same pattern.
- **The epic's last story doubled as a live systems test.** Story 2.7 depended on Story 4.1 (Epic 4) actually having promoted specs to bind against — running `marshal deploy promote` for real to close out the epic immediately surfaced two genuine bugs (a filename regression, and a real cross-project key collision affecting every other BMAD project sharing this repo's git history) that the unit-test suite alone hadn't caught. Both fixed and verified live before landing.

## What was rough

- **5 of 7 stories carry `warnings: [oversized]`** — the same systemic pattern Epic 3 showed (7/8 there). Consistent enough across two epics now to call it a `bmad-loop`-authored-spec tendency, not noise.
- **Story 2.1 (standalone verify-command runner) was the epic's roughest**: 4 review rounds and 14 deferred-work entries — the most of any story in the epic, and disproportionate for what became the epic's foundational story everything else built on.
- **Epic 2 contributed 33 of this project's 158 deferred-work entries (21%)** from 7 stories. Notably uneven: the two `quick-dev`-authored stories (2.3, 2.7) contributed 4 and 3; the five `bmad-loop`-authored ones ranged from 0 (2.2) to 14 (2.1).

## Directly validated finding

The `deploy promote` tool built in Epic 4 (still in progress) got its first real-world exercise closing out *this* epic, and immediately proved its own value: it found that this repo's actual commit history is bimodal — some stories land via manual GitHub-PR branches, others via `bmad-loop`'s own shared `loop/<project>` branch — a distinction no story spec anticipated because nobody had run the tool for real against real data until now. Both landing shapes are now correctly (and safely, project-scoped) recognized.

When more of Epic 4 lands (4.2+), re-run `deploy promote` for real again — the tool is proving genuinely more informative live than in unit tests alone, and the rest of this project's non-Epic-1-4 story specs (5.x/6.x, once they exist) will be the next real test of its cross-project scoping fix.
