## What the effort got right

**The audit-before-delete gate earned itself immediately.** Story 32.4 made "read all eight
files" a precondition, not a formality, because steward's test-tier mandate had been found by
accident inside one of them. The mechanical line-diff then cleared all eight honestly —
herald's file looked 94% novel and turned out to be a verbose rendering of 30 stories its
`epics.md` already carried among 64. Without the audit that would have read as "delete it, we
checked" or "keep it, it looks important." Neither would have been true.

**A green suite gated every move, never the diff.** Five stations' trees moved; each landed
as its own commit behind its own passing suite. That caught the atlas path bug (below) at the
one moment it was cheap.

**Detectors caught what humans missed, twice.** `chain-completeness` refused a `ready` Spec
with no epic — correctly, and before any code moved. `governance-currency`, on its very first
real run, found that `AGENTS.md` pointed at `_bmad-output/projects/local-recipes/`, a project
INV-2 dissolved: an agent following that line looked in a directory that does not exist.
Nobody had noticed in the weeks since.

## What went wrong, and what it teaches

**A blanket transformation was wrong for three of 36 cases.** Moving atlas's tests one level
deeper, every `Path(__file__).parents[N]` was incremented. That is correct only for references
that *escape* the tests tree. Three referenced targets that moved *with* the file, where the
relative depth is unchanged — and a fourth pattern (`MEMBER_DIR.parents[3]`, derived rather
than from `__file__`) had to be left alone entirely. **Lesson: a depth shift is not a global
constant; it applies to references that cross the moved boundary, not to those inside it.**
The suite found all three in one run, which is the argument for the green-suite gate.

**The new detector's first cut was wrong in exactly the way the standard warns about.** It
assumed every backticked `bmad-*` token was a skill and reported `bmad-loop` (the orchestrator
package), `bmad-switch` (a script) and `bmad-groundtruth` (a pixi task) as dead references.
INV-0 records this precise failure — *"a detector's own bugs propagate outward as confident,
wrong numbers"* — and the fix was to derive resolution from the tree (skill, script, task, or
dependency) rather than hand-list exceptions.

**The chain-currency cascade was under-estimated at planning time.** A one-line
`requires-python` change moved three stations' `spec` stage (the memlog dates it, by design),
which put their PRDs out of currency, which required a genuine prd/spine/epics reconcile plus
a frontmatter `updated:` bump each. Then moving test files moved six stations' `code` stage
past their last retro. **Lesson: in this fleet the cost of a change is not the size of the
diff; it is the number of chain stages the diff dates forward.** Worth pricing that in before
committing to a fleet-wide edit, not after.

**A `| tail` pipe masked an exit code twice.** Both times it briefly read as a false green
before being re-checked without the pipe. Cheap to avoid, easy to repeat.

## Deliberate non-goals held

Coverage was **not** re-minted here: it amends `spec-pyforge-testing-charter` CAP-4, which
already owned it. `EXEMPLAR-STANDARD.md` was **not** deleted despite "replace" being the
operator's first framing — `pixi.toml`'s `dream-chain` detector names it as its `Contract:`
and 33 files reference it, so it was rewritten as this Spec's companion instead. That
correction was surfaced and confirmed before any work began.

## Measurement

The fleet's coverage was measured for the first time (`coverage-baseline-2026-09-07.md`):
station totals **84–98%**. The gate's floors were left at 80/70 rather than seeded downward,
because `coverage_gates_ci.py` already gates only *touched* modules — the ratchet the operator
asked for already existed, in the right place. No grandfathering mechanism was invented and no
floor was fabricated.
