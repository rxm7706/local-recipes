- (capability) CAP-1 (Capture & Promotion, Wave 1, PRD §4.1/FR-1-8): intent - a developer or agent runs 'scribe capture --type decision --text ...' to land a decision in checked-in team memory the moment it happens, and 'scribe capture --promote' to deliberately move a team-relevant user-local auto-memory entry into team memory with review. success - .claude/memory/<type>/*.md frontmatter (name/description/type in {feedback,project,reference}) is schema-identical to user-local auto-memory; promotion halts after producing a structured proposal and writes nothing until explicit confirmation; a promoted entry is rewritten in team voice (never a verbatim copy) and its user-local source becomes a promoted:true pointer stub, never deleted; re-invoking promotion skips already-promoted entries (idempotent); nothing is written outside .claude/memory/, Scribe's own package/graph-store paths, and the one pointer-stub exception.
- (capability) CAP-2 (Graph Compile, Wave 2, PRD §4.2/FR-9-11): intent - 'scribe graph compile --nightly' reads named tool surfaces the team already uses (.claude/memory/, .memlog.md files across BMAD projects, git history, retros, CHANGELOGs, docs/dreams/) and rebuilds the knowledge graph unattended, on a cadence, with a superseding capture invalidating (never deleting) the prior record. success - every node is traceable to its source file/commit; re-running compile with no new source activity yields an unchanged graph (no duplicate nodes, no spurious edges); a capture naming a prior record as superseded leaves that prior record queryable with ended validity, distinguishable from the current record; compile runs without prompting and without a human present.
- (capability) CAP-3 (Recall, Wave 2, PRD §4.3/FR-12-13): intent - a developer or agent runs 'scribe recall <query>' to get an answer grounded in the compiled graph, identically regardless of which operator or concurrent agent worktree asks. success - every response carries at least one citation resolvable to a real file/record, or an explicit 'no grounded answer found' result -- never a fabricated or generic answer; two different callers querying the same repo state get the identical answer, since the graph is the single shared source, not per-session state.
- (capability) CAP-4 (Package & CLI Surface, cross-cutting, PRD §4.4/FR-14-15): intent - Scribe ships as an installable, pixi-workspace-member package (dist pyforge-scribe, module pyforge.scribe, CLI scribe) with capture/graph-compile/recall as its three independently invocable top-level commands and sole public contract. success - each command is independently testable; other components (Herald, Marshal, Doctor) integrate only via the CLI or a documented, versioned API, never by importing pyforge.scribe internals directly; the three-command CLI skeleton exists from Wave 1's start so the public contract's shape does not change between waves.
- (constraint) AD-1: capture is the single mutation path for decisions/ADRs/runbooks -- append-only, never edited in place, only superseded. scribe graph compile never accepts direct graph edits; the compiled graph is 100% derived and re-computable from source records at any time, from scratch, with the same result. No component queries or mutates the compiled graph store except the compile step (write) and scribe recall (read).
- (constraint) AD-2 (promotion write-boundary): the only write Scribe performs outside .claude/memory/** and its own package/graph-store paths is the pointer-stub rewrite of a confirmed-promoted user-local entry, and only after explicit human confirmation, gated by the idempotent promoted:true check. Scribe MUST NOT write to .claude/skills/ (other than its own), .claude/scripts/, .claude/agents/, .mcp.json, recipes/, _bmad/, _bmad-output/ outside its own project directory, or root CLAUDE.md (that wiring is a human-driven edit, never automated).
- (constraint) AD-3: .claude/memory/<type>/*.md frontmatter (name, description, type) is byte-identical in shape to Claude Code's user-local auto-memory schema; type is exactly one of {feedback, project, reference}, no additional required fields in Wave 1 -- no translation layer that could silently drop or corrupt fields during promotion.
- (constraint) AD-4: fact supersession, never deletion -- a capture naming a prior record as superseded marks that prior record's validity as ended in the compiled graph; it is never deleted or overwritten. Binds at the projection-builder (compile) level, independent of which concrete GraphStore adapter is active.
- (constraint) AD-5: the storage engine sits behind a GraphStore port (write: upsert-node/invalidate-edge-shaped operations; read: query-by-citation-path). No module outside the concrete adapter implementation may import a specific storage engine's client library directly -- prevents a KuzuDB-archival-style premature lock-in recurring inside Scribe. The concrete v1 adapter and the embedded-graph-engine question are Deferred (open question 1).
- (constraint) AD-6 (air-gap by construction): the default configuration performs zero outbound network calls for scribe capture, scribe graph compile, or scribe recall. Any optional network-touching capability (e.g. a future hosted-LLM backend for recall's answer synthesis) is opt-in, off by default, and gated behind an explicit flag. scribe recall's v1 default path must not require network reachability to return a grounded answer.
- (constraint) AD-7: the scribe CLI is the sole public contract; pyforge.scribe's public __init__.py exports only what the CLI needs. Other pyforge-* stations (Herald, Marshal, Doctor) integrate via the CLI (subprocess/CliRunner-style invocation) or a documented, explicitly-versioned Python API -- never by importing pyforge.scribe.compile or pyforge.scribe.graph_store internals directly.
- (constraint) AD-8: every scribe recall response either includes at least one citation resolvable to a real captured record (file path / capture ID / commit), or returns an explicit 'no grounded answer found' result. No code path may return synthesized prose without a resolvable citation attached.
- (constraint) AD-9 (wave boundary): .claude/memory/ frontmatter (AD-3) is a stable input contract for the Wave 2 compile step; Wave 2 development reads that format as-is -- if Wave 2 needs additional metadata, it is additive (new optional fields), never a breaking rewrite of Wave 1's already-shipped schema.
- (constraint) Manual-only invocation (inherited legacy FR-9/D4): no Stop/SessionEnd/PreCompact hook triggers capture in Wave 1 or Wave 2 -- every scribe capture invocation is a deliberate, authored action.
- (constraint) Versioning (PRD §4.4 feature NFR): semver: CLI subcommand additions are MINOR, breaking flag/output-format changes are MAJOR, consistent with this repo's existing skill/package versioning discipline.
