## What went well

- **The `GraphStore` port (AD-5) held the seam it was designed for.** Story 2.1 established the protocol once; `compile.py` (2.2), the supersession logic (2.3), and `recall.py` (2.4) all built against it without any story needing to reach past the port into a concrete storage engine. No rework, no leaked abstraction.
- **AD-8 (no fabricated citations) was verified, not just asserted.** Story 2.4's review confirmed the "no grounded answer found" path is reachable both from zero token matches AND from a matching node whose citation fails to resolve — the check sits on the return path, so a partial match can't slip through as `grounded=True`. This is the same fail-closed discipline Warden's Epic 1 retro credited for its socket-deny/no-scan-guard pattern; Scribe reapplied it in the recall domain.
- **Determinism was proven with two independent store instances, not code inspection.** 2.4's test loads the same on-disk graph via two separate `FlatFileGraphStore` objects with no shared Python state and asserts byte-identical answers — directly proving FR-13's "single shared source, not per-session state" claim rather than eyeballing the code for an obvious mutable global.
- **Story 1.5 was performed by the tool, not authored by hand**, as the legacy spec's Story-6 AC demanded — the promotion diff that landed for the two BMAD↔CFE entries is the literal output of `scribe capture --promote`, confirmed by the story's own binding requirement.
- **A blocked dev session investigated instead of just failing** (see the dangling-commit incident below) — a genuinely good instance of the loop's failure mode producing a better outcome than a clean deferral would have.

## What was harder than expected

- **1.1's frontmatter schema had already drifted once before Scribe even started.** The architecture doc's shorthand described a flat `name`/`description`/`type` schema, but the actual, currently-written auto-memory files nest `type` under `metadata:` — older files use the flat form. Scribe had to verify against live ground truth (the most-recently-written on-disk entries) rather than trust the architecture doc's prose, and isolated the choice into one deserializer function so the next drift touches one place, not every caller.
- **1.1's concurrency bug was real, not theoretical.** `capture()`'s original two-step write (record file, then unlocked read-modify-write of `MEMORY.md`) was reproduced losing entries under load: 20 threads racing `capture()` left only 7 of 20 index lines standing, with some calls raising mid-write. Fixed with a cross-platform locked critical section; the regression test reproduces the exact race.
- **1.2 needed two review passes on a two-line diff.** The first review passed a `CLAUDE.md` edit with only cosmetic findings; a *second*, independent follow-up review on the same "done" spec caught a real footgun the first pass missed: the file's only prior `@path` reference (to `.claude/docs/bmad-method-llms-full.txt`) is backticked — an inert code span, not a live import — meaning the new `@.claude/memory/MEMORY.md` line was the file's *first* live import, and a future stylistic edit that backticked it would silently sever team memory with no failure signal. A guard sentence was added specifically to prevent that. Small diffs are not low-risk diffs.
- **Epic 2's adversarial review (Blind Hunter + Edge Case Hunter, dispatched with diff-only context) found real, non-cosmetic bugs after the "no findings" self-review pass on the same stories had already run clean** — see the recurring-pattern section below.

## The dangling-commit near-miss (Story 1.3)

Story 1.3 (promotion workflow — proposal-then-confirm, team-voice rewrite) was deferred on 2026-07-30 with a `dev session timeout` at attempt 2. Its branch showed **eight insertions** — a diffstat that reads unambiguously as "nothing was written." That reading was wrong.

`promote.py` (339 lines) and `test_promote.py` (457 lines) — 1,102 insertions across 6 files — existed in a **dangling commit** (`91d3571f10`, message "attempt worktree snapshot", authored by `bmad-loop`), unreachable from any ref and alive only until the next `git gc`. It was found not by tooling but by Scribe's own dev agent: Story 1.4 could not be planned without 1.3's `promote.py`, so the blocked session investigated instead of accepting the empty deferral — read the sibling worktree, found a stray `promote.cpython-314.pyc` as the only on-disk trace, ran `git log --all -- '*promote.py'`, located the commit, confirmed the object with `git cat-file -e`, traced two consecutive `reset: moving to 491f3ec4` entries in that worktree's reflog, and escalated with the SHA. The commit was cherry-picked cleanly onto main (`70673665d7` / PR #168, `d68187f4b3`), taking Scribe's suite from 18 to 47 tests in one recovery.

Two things about this incident matter beyond the recovery itself:

1. **It landed with zero review.** The original deferral was a dev-timeout at attempt 2 — no follow-up-review commit ever ran against `promote.py`/`test_promote.py`, unlike the pattern applied to other same-day recoveries. 47 green tests and a full six-station/four-detector merge gate covered it, but no reviewer ever read the diff by the time it landed. That review debt was logged in the spec's memlog at the time and, per the current spec archive, `spec-1-3-promotion-workflow-proposal-then-confirm-team-voice-rewrite.md` carries no `Review Triage Log` section at all — confirming the debt was never paid down, only inherited.
2. **The rule this incident established was applied and verified, not just written down**: a story branch's diffstat is *not* evidence that nothing was written; check `git fsck --no-reflogs` for dangling commits in the same window before concluding a deferral was empty. That test was run against the other two same-day empty deferrals (herald 1.3, steward 1.4) and both were confirmed genuinely empty.

## Corrections / systemic patterns (2+ independent occurrences)

Epic 2's dedicated adversarial-review pass (Blind Hunter + Edge Case Hunter, dispatched with diff-only, no shared context, 2026-08-07 — landed as PR follow-up commit `a53b5c581e`) found the same *class* of bug independently in two different stories, after each story's own self-review had already passed clean:

- **"A single degraded input crashes the whole unattended pipeline instead of being skipped and logged," found twice.** Story 2.2's `_read_git_surface` used `subprocess.run(text=True)` with no `encoding=`/`errors=`, so a commit with non-UTF-8 content raised an uncaught `UnicodeDecodeError` — a `ValueError` subclass that the surrounding `except (OSError, subprocess.TimeoutExpired)` did not catch — crashing the entire nightly compile. Story 2.3's `_apply_supersession` re-globbed and re-parsed `.claude/memory/*.md` a second time instead of reusing the first pass's records, so a file removed between the two scans raised an uncaught `FileNotFoundError`. Both violated the same documented guarantee ("a single degraded surface does not abort the rest of the compile") that both stories' own self-review had explicitly claimed was upheld. Both were one-line-category fixes (widen the caught exception set / add `encoding=`) with dedicated regression tests, but the pattern recurring twice, independently, in an *unattended nightly* pipeline is the real finding: self-review by the same session that wrote the code is structurally blind to "did I actually catch everything the docstring promises," and an independent adversarial pass with no shared context caught what two separate "no findings" self-reviews missed.
- **Over-broad matching on a short, common name.** Story 2.2's `_EXCLUDED_DIR_NAMES` matched the bare string `"data"` anywhere in the repo tree, not just `.claude/data` (the graph store's own gitignored home) — silently dropping any legitimate `CHANGELOG.md`/`.memlog.md`/`*retro*.md` living under an unrelated directory literally named `data`. Fixed by matching only the adjacent pair `(".claude", "data")`. This is a narrower instance of the same "the self-review didn't stress the boundary it claimed to cover" pattern as above, on a different axis (path matching vs. exception handling).

## Lessons

1. **The `GraphStore` port pattern (AD-5) is a template worth reusing**: establish the seam once, in the first story of a multi-story chain, and every later story builds against the protocol, never the concrete adapter. No Scribe story after 2.1 needed to touch `graph_store.py`'s internals.
2. **"No findings" from a same-session self-review is not evidence of correctness for an unattended pipeline.** Every self-review pass across 2.1–2.4 came back clean; the independent adversarial pass on the same stories, run afterward with no shared context, found two real crash bugs and one silent-data-loss bug. For anything that runs unattended (cron/CI, no human present to notice a crash), route it through an independent adversarial pass before calling the story done, not just the authoring session's own review.
3. **A branch's diffstat is not proof of absence.** The dangling-commit incident is the concrete version of this: "eight insertions" looked like an empty deferral and was actually missing 1,102 lines of real, working code. `git fsck --no-reflogs` is cheap; treat it as a standard step before writing off a timed-out dev session as having produced nothing.
4. **Small diffs still need a genuine second look.** Story 1.2's two-line `CLAUDE.md` edit passed one review clean and only surfaced its real defect (the backtick/live-import ambiguity) on a *second*, independent follow-up pass against the already-"done" spec. Diff size is not a proxy for review effort needed.
5. **Recovering after the fact from a legacy-doc / architecture-shorthand mismatch is cheaper than trusting the doc.** 1.1's frontmatter-schema check against live on-disk files (not the architecture doc's prose) caught a real, already-occurred schema drift before it became Scribe's problem too.
