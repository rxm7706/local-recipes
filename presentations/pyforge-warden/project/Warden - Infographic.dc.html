The problem

Dependency hygiene and security compliance across enterprise infrastructure require disjointed tools. Teams run deptry and osv-scanner as separate pipelines — friction that grows in Conda- and Pixi-heavy environments where neither engine natively understands those manifests.

The severity-tiered gate

Verdict lattice — highest wins
errorexit 2 · operational
policy-violationexit 1 · blocks merge
indeterminateexit 1 · unproven
warnexit 0 · non-blocking
bypassedexit 0 · audited waiver
cleanexit 0
not-applicableexit 0 · non-Python
Frozen exit enum 012130
Default policy

v1 blocks on CVSS-critical CVEs only; high/medium/low + all hygiene warn. v1.x adds a KEV tier — any CISA-KEV-listed advisory affecting a pinned version blocks regardless of CVSS. Configurable via --fail-on, max_critical, --fail-on-kev. Replaces the brittle "any finding blocks" gate.

Waivers as code

--bypass --reason emits an expiring waiver stanza (default 14 days) the team commits. The tool reads it, never writes the repo — loud, recorded, and review_required.

Three rings — scan the whole supply chain

Warden runs at three depths. The further out it scans, the more it prevents rather than reports.

Outside the firewallvision
Public upstream
Scan PyPI & conda-forge themselves — malicious packages, typosquats, name-squatting, stale or abandoned feedstocks. Threat intel on the open ecosystem.
→blocklists
The firewallv1.x
Registry perimeter
Turn that intel into block / allow lists on Artifactory / JFrog — quarantine bad packages so they never cross the firewall. A census of everything that enters.
→clean pulls
Insidetoday
Consumption edge
Scan repos, desktops & CI — the six axes on what apps actually pull. Precise per-project, but only sees what you scan.
Scan the edge and you report what you found; scan the supply and you prevent what enters. The registry & upstream rings are a security · license · provenance census — hygiene (unused deps) stays a repo-side axis.

Local & workstation mode

CI is the primary consumer — but the supported first contact is a developer at a terminal. Same CLI, same exit codes.

First contact
--warn-only at a terminal

Trial the gate and clear a finding before wiring CI — adoption realistically starts here, not in a pipeline.

Waiver authoring
Local-only by design

--bypass emits a waiver stanza for the human to commit — the tool never writes the repo, so CI can't do this.

Environment debugging
Reproduce runner failures

Chase an engine-unavailable exit 2 outside the runner image; a doctor self-check verifies the engines are present.

Local mode never softens the gate — same verdict lattice, same exit codes, TTY-colour auto-detect, zero prompts.

Beyond v1 — now, next & later

v1 ships the hygiene + security gate. License and currency complete the four axes next; the same manifest engine and report contract then generalize into a full policy platform — sequenced by how soon each piece lands.

NOW v1.x — completes the four axes
License compliance

Metadata-based, no source scan — SPDX from the conda recipe about: and PyPI package metadata, normalized with license-expression, gated by allowed families; unknown → indeterminate, and written into the SBOM. (Axis 3)

Currency & supportability

Is each dep — and the Python runtime — on a supported line: LTS · N / N-1 · not EOL? Only current versions receive security patches. (Axis 4)

Baseline & grandfathering

Accept existing debt and gate only new findings — teams adopt without hitting a wall of red on day one.

Automated fix PRs

Open remediation pull requests, not just findings — bump the fixed version and route it for review.

NEXT v2 — the governance layer
Pluggable scanners

Run multiple security backends behind one report — corroborate findings across engines, not a single source.

Allowlist enforcement

Check every dependency against an approved-library registry — anything off-list is flagged before it lands.

Maintenance & health

Is the upstream alive, funded and resilient? Scores cadence, bus-factor and abandonment risk — feeding the OSS give-back loop: fund it, contribute back, or fix at source. (Axis 6)

Vendor-support backlog

Auto-generate a remediation backlog as tracked work items — fix CVE, upgrade to the 3.14 LTS, drop EOL deps.

LATER Vision — where it heads
Reachability analysis

Flag a CVE only when the vulnerable code is actually called — the single biggest cut to false positives at fleet scale.

Malicious-package detection

Install-script and behavior signals, signing and build attestation catch supply-chain attacks that known-CVE feeds miss entirely. (Axis 5 · provenance)

Alternate-library suggestions

When a dep is unused, risky or unmaintained, suggest a vetted, better-supported replacement to migrate to.

Sibling ecosystems

The naming convention pays off — js-depcheck-osv, go-<tool>-osv siblings share osv-scanner + the report schema.

Start here — the on-ramp

Adoption starts at a terminal, not a pipeline. Three steps from first run to fleet gate.

1
Try it locally

Run warden scan . --warn-only at your terminal — see findings and clear one, no CI wiring needed.

2
Make it pass, honestly

Lock (pixi.lock), file an expiring waiver, or fix the finding. Green is earned, never faked.

3
Gate in CI

Wire the same command — its exit code blocks risky merges. Same lattice, now running fleet-wide.

Honest by design — no false greens

Warden refuses to fake a pass. If it can't prove your dependencies are safe, it fails — until you pin them, formally accept the risk, or explicitly run --warn-only. An honest "not verified" beats a false "all clear."
