ACT I Two engines, no gate
The problem and the model
01

The problem

Dependency hygiene and dependency security are two disjointed tools and two disjointed pipelines — deptry and osv-scanner — stitched in CI by brittle glue that decides whether to fail the build. And conda / pixi projects are second-class in both: neither engine parses environment.yml, meta.yaml, recipe.yaml or pixi.toml, so a feedstock maintainer's only option was to hand-translate a recipe into a fictional requirements.txt — lossy, stale the instant the recipe changes, quietly wrong. Every incumbent scanner requires an installed environment; nobody served pre-build source-manifest scanning, and nobody brought dependency hygiene to conda at all.

7864
recipe directories in the local conda-forge mirror — every one a pre-build source manifest that no incumbent scanner could read
33
pixi environments in this one workspace alone — pixi.toml and pixi.lock are manifests too, and the gate reads them per environment and platform
46
MCP tools on the estate's conda-forge server — the project-scanning intelligence layer Warden complements and, by written non-goal, never replaces
Failure costs are asymmetric — a missed CVE is catastrophic, a blocked build is merely expensive. In that domain an honest "not verified" beats a false "all clear", at fleet scale, without ever mutating the host or the source. Both jobs begin at the same manifest parse, so Warden builds one conda/pixi-native front door feeding independent per-axis assessment paths and emits one schema-validated report behind one exit code. Charter § Warden — the Guardian: halt the threat, clear the axes, protect the perimeter.

04

The spine — one Component, one ResolvedInventory

Discovery, routing and extraction produce the inventory; axis producers annotate it; report, SBOM and verdict read it. No stage reaches around it or redefines a parallel shape. Identity is (ecosystem, name, concrete_version); the purl is derived and its non-identity qualifiers stripped before any comparison.

The predicate that prevents the silent false-green. osv keys advisories by (ecosystem, name, version) over PyPI, npm, Go — it has no conda ecosystem, so a conda dependency is parsed as PyPI, and a differently-named pinned package (pytorch → torch, a native openssl) would match the wrong identity and false-green silently. Therefore vuln_matchable = (pypi_identity is not None) AND (version resolved to ==X.Y.Z), with pypi_identity resolved only from trustworthy provenance: pixi.lock pypi: entries, explicit PyPI sections, or the bundled static conda→pypi map. Unmapped → None. Conda =1.2 is a prefix, not an exact match → withheld as range-only.
Withhold reasons — always visible, never silently dropped
no-versionunmapped-ecosystemnative-nonpypirange-onlyambiguous-identity
A withheld component stays in the report — that visibility is what routes it to indeterminate rather than letting a clean sibling axis absorb it. For a mapped-but-unversioned dependency the name-level tier asks instead: does this package carry any known critical CVE across any version? → carries known critical CVEs — pin or lock to prove immunity. A ranked worry-list and a lock-nudge, not a dead coverage number.
Merge rule: same identity across manifests → one component with a provenance list; (name, None) merges into (name, version) only when exactly one concrete version exists; different versions of one name → distinct components, both scanned. len(SBOM.components) == len(inventory) == report.inventory_count, post-merge, root project excluded.

Twelve capabilities — the whole contract at a glance

Every capability carries a success criterion written to fail when the capability is absent, and every one carries a verified: line from a code-level plus live re-verification at a named HEAD. The Spec reads ready; the Dream reads specified; the ledger reads 49/49 stories across 12/12 epics.

CAP-1one command
One non-interactive command, one exit code
warden scan <path> reduces N per-finding outcomes to one status and one code from the frozen enum; the gate decides on report content + severity, never a subprocess return code; zero prompts in any mode — --bypass takes its reason inline.
CAP-2the wedge
Source manifests, pre-build
six formats plus lockfiles with no resolved or installed environment; PyPI inputs delegate to the engines' native parsers; corpus conformance yields zero uncaught exceptions under a ratcheted unparseable rate; a differential oracle asserts a superset of the renderer's output.
CAP-3honest coverage
Assessed, not merely present
every discovered manifest is scanned and reported per manifest (union coverage, not a precedence winner); coverage per axis with its own denominators and a stated resolution_depth; every withheld component states its reason and stays visible.
CAP-4four axes
Every component, every registered axis
hygiene, security, license and currency each verdict all resolved components with per-axis coverage and provenance; each non-clean status carries a driver naming its axis and finding; a claim for an unregistered axis is a hard error.
CAP-5policy
Tune what blocks without editing the tool
[tool.pyforge-warden] in pyproject.toml and/or pixi.toml, deterministic per-key precedence, flags override, conflicts named to stderr; [tool.deptry] ignores honored; a coverage-floor gate exists but defaults off.
CAP-6waivers
Accept a risk in the open, on a clock
waivers and baselines are committed files the tool reads and never writes; suppression keys on the stable finding-ID grammar; every applied entry is echoed; an expired entry re-blocks; wildcards are rejected; a bypassed run still exits bypassed in the audit record.
CAP-7machine contract
Consume the run as data, not prose
a schema-validated, versioned ComplianceReport on stdout as a single valid document or empty; a CycloneDX SBOM with source-registry-correct purls, self-declared partiality, and a component count equal to the resolved inventory post-merge.
CAP-8routing
Route every failure to its owner
nine typed error kinds — unparsable-manifest → developer; engine-unavailable → platform; the rest → the tool's maintainers; a missing, incompatible, crashed or drifted engine is exit two, never a silent pass; --doctor re-exposes the same detection and never exits one.
CAP-9adoption
Turn the gate on without a day-one red wall
--warn-only reports everything at exit zero; a committed baseline grandfathers existing findings so the gate blocks new findings only, with expiring entries that re-block; every non-zero exit names package, finding, manifest location and a remediation path.
CAP-10determinism
Reproduce, and leave nothing behind
decision-determinism by default, byte-identical output under --deterministic; a scan never mutates tree or host and cleans up on success and failure; cost is O(project), axes run in parallel; the tool's own overhead bounded at p95 over a pinned corpus with engines stubbed.
CAP-11air-gap
No network at all — and know how fresh the data was
the orchestrator opens no socket (socket-guard test, and strace over the whole process tree); the vulnerability DB and the KEV, EPSS and end-of-life feeds are provisioned or cached, offline by default; every verdict records source and snapshot; stale, empty, swapped or unverifiable data → indeterminate.
CAP-12actuator
Findings into pull requests, never into the tree
--open-fix-prs runs strictly post-verdict with environment-supplied credentials, through the forge API only; a failed PR-open never alters the verdict or exit — it lands in the report's actuation section; --fix-prs-dry-run shares the real path up to the egress seam and opens no socket.
One genuine spec-vs-implementation gap, recorded rather than papered over. The re-verification pass found CAP-6's review_required literal only in the Spec documents themselves — the bypassed-run audit trail that exists is status=bypassed at exit zero plus the emitted waiver stanza's authorized_by / reason / timestamps, real and tested, with no literal field of that name in models.py, report.py or waiver.py. The Spec names it as a mismatch. That is the never-false-green doctrine applied to the contract's own claims.

Why engines are consumed and never authored. Stream discipline, and what is deliberately unstable. The report goes to stdout; all diagnostics, progress and warnings to stderr; in machine mode stdout is a single valid document or empty, never partial. Human text output and stderr are explicitly unstable and may change any release — declaring non-contract is itself a stability statement. Output evolves by adding fields and bumping a version; input (config keys, the waiver and baseline schemas) evolves by accepting the old form forever, then deprecate → warn → remove, because those keys live across a fleet; an unknown or future waiver-file version is rejected with a typed error, never guessed. The exit enum is frozen.

Frozen, closed exit enum 012130 — adding a code is a MAJOR change
Status severity and exit code are deliberately different orderings. bypassed sits above clean because a suppression is an audit-relevant event. indeterminate sits above warn for one reason: a clean sibling axis must never be able to mask "we couldn't scan what existed" — that single placement is what makes partial coverage non-silent. Every non-clean status carries status.driver (axis + finding id): an exit that cannot distinguish "critical CVE" from "blocking DEP001" is an incoherent contract.
Default policy

Hygiene and security gate by default: DEP001 blocks on a high-confidence mapping; CVSS-critical and any CISA-KEV-listed advisory on a pinned version block regardless of CVSS. --fail-on lowers the severity bar; --min-epss adds an exploitability threshold. License and currency are flag-activated — unconfigured they feed a visible warn, never a silent clean. A minimum-coverage floor (--fail-under-coverage) exists but defaults off, so first contact is never gated on coverage.

The tool reads it, never writes the repo; suppression keys on the stable finding-ID grammar, every applied entry is echoed once, an expired entry re-blocks, a wildcard rejects the whole file. The autonomy gradient — what the gate may decide, and where it stops

Warden's autonomy is total inside its verdict and zero outside it. It extracts freely, assesses every registered axis, and decides one status and one exit that nobody else may recompute — and then it stops. Everything past the line belongs to a human commit, a forge API, or another station; the tool never writes the tree.

No prompts, ever
zero interactivity in any mode — local workstation mode softens nothing; --bypass takes its reason inline, and the only usage error is a bypass without one
Sanctioned downgrades lower the exit, never the status

Coverage improves only by evidence

Enterprise and air-gap — a gate that carries nothing in, and proves it

An air-gapped or firewalled fleet can run the gate with no network at all, and know how fresh its data was. This is the strongest form of the claim — an outside-the-process observation, not an in-process promise: strace -f -e trace=network wraps the full warden scan process tree over the real corpus and asserts zero internet-family syscalls anywhere in the trace.

The orchestrator opens no socket. A socket-guard test asserts it in-process; the strace egress counter asserts it over every forked engine subprocess too. All network is confined to named engine subprocesses, and air-gapped mode passes explicit offline / local-DB flags because osv-scanner defaults online — an assertion, not a hope.
Provisioned or cached, offline by default. The vulnerability database and the KEV, EPSS and end-of-life feeds are provisioned in CI or cached on the host — opt-in online, never silent. Every verdict records its data source and snapshot timestamp; stale, empty, swapped or unverifiable data routes to indeterminate, never a confident clean. The database's trust anchor is conda package integrity plus build-date staleness.
Engines from your mirror, never from the internet. deptry and osv-scanner are conda run-dependencies provisioned from existing feedstocks through the estate's own channel — JFrog / Artifactory mirrors, the same routing the rest of the factory uses — pinned to a tested version range. Nothing is curl-fetched at runtime; the runner image is reproducible from the lock.
Resource bounds are enforced mechanisms, not hopes. Extraction is line-bounded with a per-line byte cap and a total manifest-size cap; database extraction is decompression-bounded and zip-slip confined; every engine invocation carries a bounded, configurable timeout whose expiry maps to a typed error and the frozen exit code. Pointing the gate at an untrusted tree is safe by construction — shell=True is banned and manifest-derived values are never passed as CLI flags.
Edge mode is the shipped differentiator. No data estate at runtime: the bundled LTS registry and the conda→pypi map carry a build-time snapshot_at, every verdict derived from them carries max_age_ok against a configurable maximum age, and N/N-1 currency degrades to a visible unknown when channel data is absent. A stale bundled registry can never silently report supported; stale-under-an-active-gate routes to indeterminate. Fleet mode — estate-backed, with the availability-at-N/N-1 finding — is roadmap, and composes to the same lattice.
