01

The problem

chronic, compounding — never acute

The legacy cf_atlas orchestrator built a database over the whole conda-forge feedstock population — versions, downloads, maintainers, vulnerabilities, readiness — and read it back through bespoke CLIs and MCP tools. It demonstrably shipped. But every phase re-implemented checkpointing, TTL gating and backoff by hand; lineage was implicit; execution was observable only through stdout; ad-hoc questions meant hand-written SQL against a single SQLite file; and a coarse per-run timeout could silently drop a phase and still score the run green. The cost was never performance. As the factory's workforce shifted from one developer to loop-driven agents adding the next phase unattended, a procedural monolith became the single largest risk to the whole packaging factory's autonomy story.

7864

The load-bearing justification is agent-maintainability, not speed. The cold rebuild is network-bound, so the honest headline is incremental re-materialization, query-time analytics and Parquet reads — never an engine-swap cold-start miracle. Atlas is conda-forge-only by name, serving one operator and one agent workforce; that narrowness is the design, not a gap to close later.
02

From procedural phases to a declared dataflow

the topology · CAP-1 · CAP-2 · CAP-6 · CAP-8

Every unit of ingestion or compute is a pure function with declared inputs and outputs; execution order is resolved from the dependency graph, never called procedurally. Sources and outputs are entries in conf/base/catalog.yml; credentials attach to a dataset's destination host only; partitioned Parquet is the canonical store and DuckDB the only engine — analytical compute, recursive-CTE graph traversal and vss vector similarity alike. Above the store, metric logic is declared exactly once in the Boring Semantic Layer and every read surface translates through it.

The producer owns the dataset. Each dataset has exactly one producing pipeline; consumers reference it by catalog name and cross-pipeline edges resolve by name — core_cf_graph_raw feeds vcs_health, core_packages_enumerated feeds pypi_intelligence. Two pipelines writing one dataset is the failure the closure rules out.
Incremental state is a dataset concern. IncrementalParquetDataset round-trips *_fetched_at TTL state: stale rows re-fetch, fresh rows skip, with the TTL declared per dataset in the catalog. The bespoke phase_state checkpoint table is gone — resumability comes from the runner plus persisted intermediates.
Two freshness clocks, never conflated. The fetch TTL asks "is this row stale enough to re-fetch?" and re-fetches it. The consumer freshness contract asks "is this dataset too old to be read?" and makes the consumer refuse the input — degrading the affected read or policy axis to indeterminate, never a silent pass.

08

The ways work flows — every entry point rides identical machinery

one execution plane · CAP-4 · CAP-5 · CAP-9 · CAP-12

A scheduled tick, a sensor event, an MCP trigger and a CLI run all execute the identical named pipeline with identical machinery: budgets, validation hooks, lineage and trace instrumentation, profile definitions — all declared in run configuration, none in a node. Admission is dispatched first: one OS file lock per output dataset, so two triggers of the same dataset set are rejected fast with a typed error naming the holder, or wait to a bounded deadline if the run asked to — never interleaved.

11

The relay — from a rising repo to a shipped recipe

the discovery engine and its Mason handoff

The factory should not wait for requests. Discovery senses what the ecosystem is adopting and carries worthy candidates toward conda-forge before anyone files an issue — but Atlas proposes, never authors, and never auto-submits. The baton changes hands as structured data at every step.

1
Sense. upstream_discovery ingests GitHub trending Python repos (daily, weekly, monthly) through an injected fetcher — HTML scrape primary, GitHub Search API fallback. A layout break keeps the last-good snapshot and exits non-fatal.
2
Classify. Each repo is joined against Atlas's own signals — on conda-forge already, in the PyPI universe, license, requires_python, packaging shape, downloads, readiness — and labelled tier 1 (curated gap: noarch: python, one recipe), tier 2 (compiled, multi-output, or needing a prerequisite closure) or skip, with a reason on every row.
3
Ask. trending-candidates --period --tier --top --not-on-cf --min-stars --json and the MCP tool query_trending_candidates answer "what is worth packaging next?" from the same read seam — offline-safe, zero network after ingest.
4
Re-verify. The fixed-source audit track re-checks each org-audit candidate's current state through the same classifier — one that shipped independently since the list was written is dropped, not re-proposed.
5
Screen. hand_off_candidate requires a caller-supplied passing health-screen verdict — abandonment signal and license clarity, Doctor's domain — and raises on a failing or missing one with no catalog write.
6
Hand off. One structured, schema-documented record — never a recipe, never a staged-recipes PR — reaches Mason, whose conda-forge-expert-governed craft authors, validates, scans, builds green and submits. Warden judges; Herald proclaims; Scribe remembers.

13 · Doctrine — the lines Atlas holds

The DAG is the single source of truth. Everything else is replaceable glue.

Atlas measures; Warden judges.An upstream-maintenance signal is a Warden axis, never an Atlas gate. Atlas may join and expose it as a feed; the verdict is not Atlas's to render. The Charter's the hand that builds is never the gate that judges, applied to signals.
No data access in a node body, ever.Sources, outputs, credentials, endpoints and physical layout are catalog concerns. Nodes are pure functions taking and returning dataframes; they carry no retries, no backoff, no checkpointing — those belong to datasets and the orchestrator.
One execution plane.Scheduled job, sensor, MCP trigger and CLI execute the identical named pipeline with identical machinery. An MCP trigger names a profile explicitly or inherits maintainer. A dataset has one writing run at a time — admission is dispatched first, by tryfirst, not by its place in the hooks tuple.
Skip and mark stale, never raise.An unreachable endpoint skips gracefully, keeps the last-good dataset intact and stamps a machine-readable staleness marker. Consumers surface the marker and apply the freshness contract: stale beyond its bound degrades the read or policy axis to indeterminate, never a silent pass.
One store, one engine.Partitioned Parquet is canonical; DuckDB is the only compute, graph and vector engine. No separate graph, vector or dataframe engine returns, no dual store survives, and the performance claim stays honestly scoped: incremental re-materialization is the headline, cold-start is benchmarked, never promised.
Gates are fixtures, never credentials — and never weakened.Every wave's first deliverable is its own deterministic gate, frozen, non-credentialed, in the tracked test tree. The verify set grows and never shrinks. Credentialed runs are attended-only; attended boundary events are features, not friction.
Snapshots are advisory.Before acting, the recipe-authoring loop re-verifies live; no surface may position its datasets as a substitute for that check, and every payload that feeds an authoring decision carries its build timestamp.
The factory layer consumes; it never writes atlas data.Wiki and CMS components read pipeline outputs through the catalog and semantic layer and write only the wiki tree and the CMS. Staleness markers ride forward into compiled output, so republication never launders freshness.
Scope is closed at the committed source set.New external sources are candidate feeds — recorded, never committed — until measured evidence becomes a requirement and a story. Seeds, template trees, authoring-time fetches and user inputs are declared inputs, never pipeline products.

Enterprise and air-gap — the consumer profile is fully offline by design

CAP-2 · CAP-13 · CAP-16 · the Unity and Wasm satellites

Enterprise routing is runtime-driven and declarative. Every resolve_*_urls override point survives as dataset-level endpoint config through ${globals:…}, so an internal mirror substitutes without a code change. Credentials are a catalog fact — an entry either has a credentials: key or it does not — asserted against a fixed allowlist with a real suffix match on the hostname, so a non-JFrog host never receives the JFrog API header: the legacy global-injection defect was closed, not ported.

Tracked seeds. The Google AOSS free-tier list and the Anaconda Distribution package table live as git-tracked JSON under conf/base/seeds/ — the air-gap fetch mode. No pipeline writes them; re-acquire by running the pure parsers over the live docs and hand-commit under review.
Extensions from cache. vss and postgres are LOADed from the pre-provisioned extension cache; a missing one raises a clear error naming the one-time attended provisioning step — never a silent network INSTALL, never a silent wrong answer.
Static host, any host. The emitter writes chunked Parquet plus a byte-stable manifest.json with relative paths and checksums; the WASM page pulls footer and row groups by HTTP Range from whichever host serves it. Zero non-loopback requests is asserted by the gate.
Artifactory, mock-first. The download-intelligence pipeline answers what this organization pulls from its own Artifactory — built against an injectable AQL transport with no live instance named anywhere; the live transport is the attended operator's to plug in (Story 25.4).

The seed — where the map came from

Dream → Spec → epics → stories → this poster
The Dream. Chart the dependencies, map the world, define the floor — and make the map maintainable by agents, not heroes. The legacy orchestrator was a hand-rolled monolith whose lineage lived in one developer's head, each phase hand-rolling its own checkpointing and backoff, a coarse timeout able to silently drop a phase and still score the run green. The dream was its rebirth as declarative dataflow — a DAG small enough, pure enough and contract-guarded enough that an autonomous agent can add the next phase by writing a node and declaring its datasets, inheriting checkpointing, TTL, validation, lineage and scheduling for free.
Lineage. Atlas's stack descends directly from the Sentinel ancestor — Kedro, Dagster, the Boring Semantic Layer, OTel and OpenLineage, La Suite — which dreamed the stack; Atlas built it against the conda-forge domain. It also realized two long-standing roadmap wishes: the unified DAG orchestrator and the interactive dashboard.
The craft is general; the implementation is Python-scoped. "Chart the dependencies" names no ecosystem. Today Atlas maps PyPI and conda-forge, and the sealed pipelines are a Python-era allocation. The trajectory: lift the registry clients, the name-mapping bridge, the PEP 440 comparator and the channel qualifier into separate modules behind the declared-dataset seam, so a new ecosystem arrives as a pipeline plus a module — never a rewrite.

The creed

Declare the node. Inherit the rest. Chart the dependencies, map the world, define the floor — and let the map be redrawn by agents who write a node and a contract, never a checkpoint. Measure everything; judge nothing. When the world is unreachable, keep the last good map and say so. The real deliverable was never speed. It is a DAG an autonomous agent can extend without hand-wiring a single line of its machinery.
