pyforge-scribe · module pyforge.scribe · console script scribe · spec-pyforge-scribe CAP-1..4

A team that runs many agents at once knows a great deal and remembers almost none of it. The decisions were made — in a chat, a memlog, a commit message, one operator's private auto-memory — and every new session started from zero. Scribe is the inward voice: capture the decision the moment it happens into memory the whole team commits, graph compile the record nightly into a knowledge graph built from the tools the team already uses, and recall from it — one grounded, cited answer, identical for every operator and every worktree, or an explicit "no grounded answer found". Where Herald tells the world, Scribe tells the team. The graph is derived; the record is the truth; nothing is ever invented.

ACT I Knowledge everywhere, memory nowhere
The problem and the model
01

The problem

A disease diagnosed twice before it was given an owner. The Sentinel Dream found that knowledge is lossy; the graph is there; nobody writes it down. The team-memory Dream found its present-day instance: Claude Code's auto-memory is per-machine and per-operator — invisible to teammates and to every other agent session — and the only escape hatch was a hand edit of CLAUDE.md that people skipped. The dated, real case is the d43899c1cb duplication incident: work re-discovered because the record of it lived in one person's head. Accumulation alone is not the cure — a memory that only grows becomes a landfill that misleads; one that is curated, superseded and cited stays true enough to answer from.

117

31

926/972

Hallucination is a context problem, not a model problem. An agent that cannot see the decision will re-make it, differently; an agent handed a confident stale entry will trust it. This repo runs many BMAD projects and agent worktrees at once, so "what the team knows" has to survive across parallel sessions, not just across humans. The Chronicler's remedy is not a bigger store — it is capture at the source, a compiled graph every session can read, and a recall path structurally unable to answer without a citation. Charter § Scribe — the station is the post, not the person; what the team knows, every agent and every session knows.

The team-relevance test. Before anything lands in .claude/memory/ it passes one question: would a brand-new contributor to this repo, on their first session, without ever having talked to me, benefit from this rule? Passive is forbidden; retrospective is not. The Spec's original non-goal read as a blanket veto on mining transcripts. A scan an operator runs, read-only against its inputs, that never auto-promotes — that is retrospective, and it is Scribe's.
03

The topology — the tools the team already uses in, one graph out

Event-sourced capture with a derived, rebuildable read-model. Six named surfaces feed the compile; a storage port, not an engine, receives the nodes; every consumer reads through the CLI or the compiled projection — never the raw log, never a driver's client library.

Reproducibility is per-machine, not repo-wide, and the module docstring says so: five of the six surfaces are repo artifacts, the transcript surface is a per-user tree outside the repository. Two operators compiling the same commit get the same five-surface core plus whatever transcript nodes their own machine holds — by design; that local-only content is exactly the gap the transcript epic exists to close.
04

Four capabilities — the whole contract at a glance

Every capability carries a success criterion written to fail when the capability is absent, and every one carries a verified: line from a mechanical re-verification at a named HEAD — live --help output, live recall against gibberish and against a real topic, a fleet-wide grep for forbidden imports. The Spec reads shipped; the Dream reads realized.

CAP-1capture · promote
Capture at the moment, promote with review
scribe capture --type --text writes .claude/memory/<type>/*.md with frontmatter schema-identical to user-local auto-memory; --promote halts after a structured proposal and writes nothing until explicit confirmation; a promoted entry is rewritten in team voice, its source becomes a promoted: true pointer stub, never deleted; re-invoking skips what is already promoted; nothing is written outside .claude/memory/, Scribe's own paths and the one stub exception.
CAP-2compile
Nightly compile from the tools the team already uses
scribe graph compile --nightly reads the named surfaces — team memory, memlogs, git history, retros, CHANGELOGs, Dreams, transcripts, plus an optional graphify surface gated on SCRIBE_GRAPHIFY_EXTRA — and rebuilds the graph unattended. Every node traces to its source file or commit; a re-run with no new activity yields an unchanged graph; a superseding capture leaves the prior record queryable with ended validity; no prompt, no human present.
CAP-3recall
Grounded recall, identical for every caller
scribe recall <query> answers from the compiled graph with at least one citation resolvable to a real file or record, or returns the explicit "no grounded answer found" — never a fabricated or generic answer. Two callers querying the same repo state get the identical answer, because the graph is the single shared source, never per-session state. Verified live: gibberish yields the miss; a real topic yields a resolvable [source: …].
CAP-4the contract
An installable package whose CLI is the sole public contract
dist pyforge-scribe, module pyforge.scribe, console script scribe; capture, graph and recall as the independently invocable top-level commands. Other stations integrate through the CLI or a documented, versioned API — never by importing internals. Verified fleet-wide: the only two hits for an internal import are docstrings in Marshal's adapter and derived-context modules, each explicitly forbidding it.

The autonomy gradient — what Scribe may do on its own

Scribe runs unattended where the record is mechanical and stops dead where judgement enters. It appends what it is told, rebuilds the graph nightly without a human present, and flags staleness from timestamps — and every act that changes what the team believes is proposed, then confirmed, by a person.

Manual-only invocation
no Stop, SessionEnd or PreCompact hook triggers capture in any wave — every invocation is deliberate, permanently
Unattended where it is safe
graph compile --nightly never prompts; a degraded surface prints a warning and is skipped; an overlapping firing takes the lock, skips, exits zero
Proposal, then confirmation
promotion and transcript mining print the full proposal — target path, rewritten content, index line — and write nothing until confirmed; decline exits cleanly with zero files changed
Supersede, never delete
a wrong memory is corrected at the source, on the record: a superseding capture ends the prior record's validity and leaves it queryable — history survives

The shipped CLI — three top-level commands, one contract

Console script scribe, package pyforge-scribe 0.1.0, run from the repo root through the unified grammar pyforge scribe …. capture, graph and recall are the Spec's three independently invocable commands and its sole public contract; the index group carries the two ingest extras' explicit verbs. --version is top-level only. Subcommand additions are MINOR; a breaking flag or output change is MAJOR.

verb · the write path

scribe capture

--type <feedback|project|reference>
--text "<raw text>"

Appends a new record under .claude/memory/<type>/ — verbatim, no team-voice rewrite, no Why: structuring; direct capture is deliberately fast — and one index line to MEMORY.md. Prints captured: <path>. The type taxonomy is closed at three: a fourth would break byte-identical parity with user-local auto-memory (AD-3).

verb · the promotion boundary

scribe capture --promote

[--source PATH]

Scans the auto-detected user-local memory directory, classifies each entry — team-relevant · personal · already-promoted · stale — mechanically rewrites the team-relevant ones into team voice (no LLM, no network: first-person framing stripped, bare-hash asides dropped), prints the full proposal and writes nothing until you confirm. On confirmation the source becomes a promoted: true pointer stub; re-running skips it.

verb · one layer deeper

scribe capture --transcripts

[--source PATH]

Mines the raw *.jsonl session transcripts for un-curated decision and fact sentences — what a session said but nobody wrote down — and routes every candidate through the same proposal-then-confirm gate, with the session cited. Mutually exclusive with --promote and with --type/--text; the conflict exits two.

verb · the projection

scribe graph compile

[--nightly]

Full rebuild of the compiled graph from every named surface, through the port. Never prompts; a degraded surface warns and is skipped; a missing .claude/memory/ — the wrong directory — exits two. Prints compiled N node(s), N invalidated, N stale -> <store>. --nightly changes no behaviour; it exists so the trigger and its logs read plainly.

verb · the read path

scribe recall

<query> [--semantic] [--scope <project>]

Prints the answer plus [source: …] when grounded, else exactly no grounded answer found — exit zero either way; only an unreadable store is an error. Lexical token overlap by default; --semantic is opt-in and honest about what it is; --scope restricts candidates to one project's citation tree, because token overlap alone has no notion of project.

verb group · the ingest extras

scribe index

build | report | move-list | refresh
[--target PATH]

build ingests a folder through graphifyy and writes code-kind nodes through the same persist port; report writes a GRAPH_REPORT-style summary with God-node findings; move-list scans the foundry-cutover signals and needs no extra at all; refresh recomputes only what changed when the cocoindex extra is on. Missing extras exit two with a plain message.

The outputs are the contract, not the modules. Consumers bind to the CLI's exit codes and its printed lines — captured: …, compiled … -> …, [source: …], no grounded answer found, refreshed: …; skipped (unchanged): … — never to pyforge.scribe.* internals. The package's public __init__.py exports only its version; the eight public exports the SKF skill documents are all cli.py's own command functions, plus main.

The doctrine — six lines the code is tested against

Append-only is the single source of truth.
capture is the only mutation path for decisions; the compiled graph accepts no direct edits and is hundred-percent derived — re-computable from the records at any time, from scratch, with the same result. The graph is disposable; the record is not (AD-1).
Supersede, never delete.
A capture naming a prior record as superseded ends that record's validity in the graph; it is never deleted or overwritten. History survives, and a stale entry is visibly stale — bound at the projection builder, independent of the driver (AD-4).
Fix the port, not the engine.
The storage engine is an adapter behind a GraphStore protocol; no module outside a concrete adapter imports an engine's client library. Three drivers ship behind it and the port still fixes nothing beyond itself (AD-5).
Air-gapped by construction.
Zero outbound calls for capture, compile and recall by default. Anything that touches the network is opt-in, off by default, behind an explicit flag; recall's default path never needs reachability to return a grounded answer (AD-6).
The CLI is the sole public contract.
Herald, Marshal, Doctor and the Canopy integrate through the scribe CLI, the pyforge scribe grammar, or a documented, versioned API — never by importing pyforge.scribe internals. The fleet-wide grep is part of the verification (AD-7).
Recall never fabricates a citation.
Every response carries at least one citation resolvable to a real file or record, or is the explicit "no grounded answer found". No code path returns synthesized prose without one — the trust failure the PRD named as its top risk, closed by construction (AD-8).
Three more hold the edges: the promotion write-boundary (AD-2 — the pointer stub is the one write outside Scribe's own paths, and only after confirmation), frontmatter schema parity with user-local auto-memory (AD-3 — the type taxonomy is closed, so a moved entry is mechanical, never a translation), and the wave boundary (AD-9 — the compile reads the memory format as-is; anything it needs is additive, never a rewrite).

Escalation and the ledger — how a memory stays true

A memory nobody can correct is a liability. Scribe's records travel a fixed route from a session to the durable index and back through review, and every hop that changes what the team believes is owned by a person — which is the point.

1 · capture
the entry file
verbatim under .claude/memory/<type>/, frontmatter in the live auto-memory shape, one MEMORY.md line — reviewable in the PR that carries it.
2 · index
MEMORY.md
the checked-in index every session imports; kept short enough to load whole, pruned under standard git review rather than left to grow unbounded.
3 · compile
the graph
nightly, from every surface; a node whose source moved with no supersession is flagged stale, and recall refuses to serve it.
4 · supersede
the correction
a later capture names the wrong record; its validity ends in the graph and it stays queryable — corrected at the source, visibly, on the record.
5 · prune
a human's hands
obsolete rules leave by an edit to the index and an archived file, in git — no TTL, no decay, no tooling required, and never Scribe's own decision.

Why "no grounded answer found" is a success. An honest miss is the product working: the alternative — a plausible, uncited paragraph — is the failure mode the whole station exists to prevent. Enterprise and air-gap — a chronicler that phones no one

Air-gap is not a deployment mode Scribe supports; it is the construction. The default configuration performs zero outbound network calls for capture, compile and recall, and the two research reports behind the Spec single that out as the station's primary durable differentiator — git-native, capture-as-you-decide, repo-scoped — over any retrieval benchmark.

Everything it reads is operator-local. The checked-in .claude/memory/ of this checkout, this operator's per-user session transcripts, and the gitignored derived store under .claude/data/pyforge-scribe/. Nothing leaves the machine; nothing is fetched. Team memory reaches teammates the way code does — through git.
Why the nightly compile is never a GitHub Actions workflow. A hosted runner has none of the three surfaces — it checks out a fresh, transcript-free clone and throws it away — so a scheduled workflow would faithfully compile an empty machine every night and prove nothing. The trigger is checked in and installed on the machine that holds the surfaces; this is a hard boundary, recorded so the next pass does not re-propose the alternative.
Bounded on the unattended path. The transcript surface is per-user and unbounded in principle, so three bounds apply on every compile: a file-count cap and a byte budget allocated newest-first, a per-file timeout that keeps partial results with a warning, and an mtime-keyed scan cache so unchanged files are not re-read. A capped scan says how many files it skipped.
The durable driver is opt-in, and refuses cleanly. The flat-file default needs no service. Pointing a scheduled run at the PostgreSQL driver needs the local cluster up; the trigger starts it with the same idempotent command an operator runs by hand, and if that fails for any reason it prints why and exits zero rather than reporting a red run for a store it could not confirm. The owner setting is baked into the installed trigger, because scheduled runs inherit no interactive shell.
The transcript constraint, written as a rule. Provenance matters more here, not less: a fact recovered from a raw transcript cites which session it came from, the same way a committed source cites its file or commit. Raw content is never dumped into team memory — the same curation discipline the promote path already has applies one layer deeper, so the fix for "things discussed but never written down" cannot become a bigger, noisier version of the problem it solves.

Integration seams — every edge, and its direction

Scribe's boundaries are enforced by meta-tests and by the plugin contract, not by convention. Each seam below has a stated direction and a check that fails when the direction is violated.

CLAUDE.md → scribe (a human edit)

Root CLAUDE.md imports @.claude/memory/MEMORY.md so the index loads in every session. That wiring — and any de-duplication of the BMAD ↔ CFE sections — stays a human-driven edit; Scribe must not write to CLAUDE.md, .claude/skills/ beyond its own, .claude/scripts/ or .mcp.json (AD-2).

marshal → scribe (grammar only)

core/derived_context.py and adapters/scribe_cli.py call the CLI; their docstrings are the only fleet-wide hits for the internal import — and each forbids it. A retrieval that resolves to a stale: true node falls back to Marshal's own non-graph path; token-economy layers consume scribe index … by grammar.

steward → scribe (a driver, a cluster, a story)

PostgresGraphStore is owned by Steward and registers as a second plugin, not a fork; the per-user pgvector cluster the durable tests need starts with scribe-pg-up. The semantic-recall outcome is Steward's story calling Scribe's verb — the Charter's rule that the outcome's owner writes the story and the mechanism's owner owns the verb.

atlas → scribe (the plane driver)

PlaneGraphStore puts the node snapshot and HNSW-rankable embeddings on the CAP-19 query plane, owner atlas, refusing in-memory DuckDB and Chroma by construction. Under the operator's dual-write decision the plane is primary and scribe_schema stays the safety net; retiring it is a future explicit decision, never an implication.

scribe ← pyforge-core (the plugin contract)

All three drivers register on the shared pyforge.core.hooks contract — the same loader every station's plugins use — under scribe-graphstore-flatfile, -pg and -plane; open_graph_store(owner=…) is the one factory, and exactly one driver is open per run.

The Canopy → scribe

pyforge scribe … is the unified grammar; POST /stations/scribe/mcp the service face, identity tool station_face. The /stations/scribe/ portal's first job submits one recall and renders its cited result through the host's PortalClient only — no raw HTTP, no pyforge.* under src/platform/, asserted by a meta-test.
