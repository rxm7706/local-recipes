The operator's day, before

Eight terminals, eight mental models. Every station its own verbs, its own output shape, its own way of being asked.
No shared identity. Nothing to sign into; nothing that knows who you are across tools.
No shared vocabulary. A compliance finding, a package alert and a failed run cannot be related — the estate doesn't know they're about the same thing.
No signals. One station cannot tell another that something happened. The human is the message bus.
1/8
stations had a web portal — warden's, at /compliance/. The pattern worked; it was simply never repeated.
1/8
stations had a service face — atlas's MCP server. For the other seven, agents shelled out to CLIs and long work died with the connection.
PYFORGE UNIFYING STRATEGY05 / 28

The mandate riding on it

Auditable

Schema change flows through one authority an auditor can verify — enforced by database privilege, not convention.

Revocable

Identity derives from the IdP; revoking a role removes access on the next request. Secrets arrive by reference, never in a pod spec.

Contained

A failing dependency degrades its caller. A poisoned event quarantines. A restart reconciles instead of duplicating.

Five RFCs + eight blind-spot directives carry this — and the deployment gate is real: egress-blocked build and deploy is a failing CI check, not a warning.

The mechanics11 / 28

One chrome, eight portals · CAP-1 + CAP-3

django-pyforge — the chrome

App switcher, OIDC-aware base layout, Modernist theme, WhiteNoise assets, zero CDNs. Portals render identical chrome from one package — a test fails if one ships its own copy.

Registration, not configuration

The switcher derives its entries from each portal's AppConfig seam — owner station, backup, work_class, promotion date. The Guildhall refuses to tile 01/02 work as a station surface.

/stations/<name>/ — one rule

One rule beats eight exceptions. Warden moved off its shipped /compliance/ mount behind a permanent redirect. Adding or removing a portal changes no host code outside its own registration.

Reusable apps, by convention

Distribution django-<station>, module django_<station>_<app>, compound label — and a model never moves between apps; new concerns become siblings.

Every station has a service face · CAP-4

Era discipline
Accept five revisions — 2025-03-26 → 2026-07-28. The fleet is split; either end alone rejects real traffic.
Echo, never assert. A client aborts on an unknown revision even when it is newer.
Never sniff client names. Only the declared revision decides.
Disconnect survival
start / get over a durable store — SEP-2663's lifecycle without waiting for an SDK runtime that doesn't exist.
The handle is a capability — opaque, high-entropy, TTL'd.
Never: progress notifications, sticky sessions, stream replay. Keep-alives well under 30 s.
The test that matters: a multi-minute operation across a simulated ingress disconnect — result retrieved from a different replica.

Schema change, governed by construction · CAP-9

The literal directive was unimplementable. post_migrate is the only supported way to populate content types, permissions and sites — migrate cannot leave the deploy path, and the test runner has no path off Django migrations at all.
So enforcement moved to the role. platform_app holds DML only; a separate migration role holds CREATE/ALTER/DROP — the one control an auditor can verify and an agent cannot bypass by accident.
Authoring stays Django. sqlmigrate extraction lands as Liquibase changesets; a CI gate — no prior art existed; built here — fails the build when extraction is stale. Then the hook Job (weight −1, platform image) runs liquibase update, and migrate --fake reconciles.
It reopened shipped work. Two done stories had provisioned schemas through Django migrations. The correction was not optional.
Proven live · CRC 2026-08-26
CREATE on public — refused as platform_app
/api/health — 200 as that role
changesets :15–:19 — EXECUTED
Traps, named: never preserveSchemaCase (issue 7624 lands DDL silently in public); the Job creates schema liquibase; never an init container; no engine CREATE TABLE on import. Test databases are carved out entirely.
PYFORGE UNIFYING STRATEGY17 / 28

Failure is contained; stations talk · CAP-8 + 10 + 11

Thirteen directives, four rewritten by research
BS-4: PyBreaker's async support is Tornado-era — the circuit never trips on an httpx coroutine. We wrote the ~40-line async wrapper instead of adopting dormant code.
BS-1: the premise was false — Scribe was one JSON file, not SQLite. Rewritten as flat-file → pgvector behind the existing port.
BS-2: the SSE design was deprecated twice over; the 30-minute route annotation never raises the timeout that matters.
BS-8: reconcile on restart, yes; MinIO, no — a fourth backing kind fails design review.
The event backbone · CAP-8

CloudEvents on pyforge.events (redis-broker, never the cache) — consumer groups, XAUTOCLAIM harvest, DLQ quarantine, pyforgeloopdepth ≤ 8. Work identity travels as spec_id + git sha + SBOM purl.

The rule over all of it

An invariant with no test that fails in its absence is not implemented — each demonstrated individually, never as a suite.
