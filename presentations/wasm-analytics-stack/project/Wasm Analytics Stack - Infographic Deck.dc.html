The maturity verdict — the project's central scoping fact

Verified against primary sources on 2026-07-25: DuckDB's native engine has no WASI build and no WASI roadmap — a search of duckdb/duckdb for "WASI" returns zero issues, so the question has never been asked upstream. dlt's DuckDB destination and dbt-duckdb both inherit that blocker.

AD-1 · what crosses the WIT boundary

Primitives and records only. No host-shared-memory type, no Arrow buffers, no raw Excel bytes — parsing happens outside the sandbox, before the call.

AD-9 · synchronous, correlate-don't-poll

The request blocks through parse and validate and returns the full per-row report. The trace ID correlates; there is no v1 polling endpoint.

AD-7 · one writer, 1:1, never batched

DuckDB is single-writer: one upload triggers exactly one dlt load then exactly one dbt run — sequentially, from the same owning process.

AD-5 · one trace ID, one wire format

Always the bare 32-hex W3C trace-id — never the full traceparent, never a UUID, never dashed, and never conflated with OpenLineage's own runId.

04

The non-hollow gate

AD-4 · it must be able to fail

The Isolation-Verification Gate runs the compiled component under a Wasmtime host granted only its WIT-declared capabilities and fails on any host interaction beyond them.

It ships from version one with a meta-test: widening the declared capability surface without a matching WIT change must make the gate fail. A gate that always passes is not a gate.

AD-2 · the denylist is a build gate
# static import scan: source + resolved closure
pixi run build
✗ denylisted import: numpy · pandas · pyarrow · pydantic

Direct or transitive — it fails the build, not a later runtime error. Violating it means shipping a component that either will not build under componentize-py or depends on the unmaintained wheel project this project refuses to rely on.
