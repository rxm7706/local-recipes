The gap that remains

Restricted SCC gives process isolation, not code isolation. The Python process inside a hardened pod still has the whole language surface available to anything running inside it — and nothing separates the pipeline's own code from logic derived from an uploaded file.

AD-3 · the three-lane split

Sandbox the one place it is buildable

A smaller claim than the April 2026 gist made — and, per the research, the larger claim is not buildable with today's ecosystem.

Lane 1 · conventional
dlt · dbt · DuckDB

Restricted-SCC-hardened OS processes. No wasm32-wasi build target may be declared in either stage's runtime path without an ADR amendment citing new upstream evidence.

Lane 2 · the sandbox
upload validation

Pure Python only, compiled by componentize-py into a genuine WASI Preview 2 component under Wasmtime. The one place untrusted input first touches the system.

Lane 3 · deferred to v2
the read surface

DuckDB-WASM + Pyodide in the browser — Emscripten, a different target entirely. Already shipped by PyForge Atlas story G1; reused directly, not reinvented.

AD-1 · what crosses the WIT boundary

Primitives and records only — strings, numbers, booleans, lists. No shared memory, no Arrow buffers, no raw Excel bytes. Parsing happens outside the sandbox, before the call.

AD-9 · synchronous by design

The request blocks through parse, validate and the full per-row report. The returned trace ID correlates; it does not poll — there is no v1 polling endpoint.

AD-7 · one writer, 1:1, never batched

DuckDB is single-writer, so one upload triggers exactly one dlt load then exactly one dbt run — sequentially, from the same owning process.

Wasm Analytics Stack · sandboxed pipelines06 / 10
CAP-4 · FR-12 · FR-13

The gate must be able to fail

The isolation claim is mechanically verified, not asserted — and the proof that the verification is real is that it can be made to break on purpose.

AD-4 · the meta-test, from version one

The gate runs the compiled component under a Wasmtime host granted only its WIT-declared capabilities and fails on any host interaction beyond them.

Then it proves itself: widen the declared capability surface without a matching WIT change and the gate must fail. A gate that always passes is not a gate.

AD-2 · the denylist is a build gate
# static import scan over source + resolved closure
pixi run build
✗ denylisted import: numpy · pandas · pyarrow · pydantic

Direct or transitive. It fails the build, not a later runtime error — because violating it means shipping a component that either will not build under componentize-py or depends on the unmaintained wheel project this project refuses to rely on.

CAP-3 · one writer per contract

One trace ID. One security context.

AD-5 · minted once, one wire format
upload_trace_id

The bare 32-hex W3C trace-id — never the full traceparent, never a UUID, never dashed. Minted at ingress, carried into the dlt load package, passed to dbt as a var, attached as a custom OpenLineage facet.

Never conflated with OpenLineage's own runId. One trace-ID lookup reconstructs upload → Gold with no gaps — and only the Vector sidecar holds an external telemetry egress path.

AD-6 · one definition, two consumers
Helm chart · OCP

Restricted SCC, no elevated binding requested.

Podman compose · twin

--read-only --user 1001

Both consume one canonical definition authored under deploy/ through a generation step — neither hand-authors a copy. Two hand-maintained copies drifting apart is precisely what would silently defeat the parity claim.

CAP-5 · FR-14 … FR-17

One toolchain, three environments

Local dev
pixi install && pixi run build

Compiles the WASI component alongside everything else — no manual steps outside Pixi.

Podman digital twin
--read-only --user 1001

The same security context OCP enforces — so a Restricted-SCC-incompatible change is caught locally, not in production.

OpenShift · Restricted SCC
zero SCC exceptions

Non-root UID 1001, read-only rootfs, no privilege escalation — and no anyuid binding requested.

FR-17 · the mount contract never differs

DuckDB's Bronze/Silver/Gold state mounts at the same path from a ReadWriteOnce-shaped volume in all three. Only the backing implementation changes — bind mount, Podman volume, OCP PVC.

AD-8 · air-gap-routable by construction

Every build-time fetch — Pixi packages, DuckDB extensions, the componentize-py/Wasmtime toolchain — routes through the configured mirror. No build script hardcodes a public URL.
