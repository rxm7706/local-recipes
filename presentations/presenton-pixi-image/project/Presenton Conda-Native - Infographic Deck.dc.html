The problem

An analyst in a SCIF, a compliance officer at a regional bank, a program manager on a classified contract — all need to turn a 40-page internal document into a board-ready deck, and none can reach the cloud to do it with AI help. The tools that clear procurement (Marp, python-pptx + Jinja2) stamp templates; they do not summarize. The tool that would do the job is cloud-only. Today they build by hand.

One true port, three tiers

TierWhat the one env-var contract points at
Tier 1 — external proxyAn operator-supplied corporate endpoint; no in-cluster resource. All latency targets are measured here.
Tier 2 — in-cluster sidecarA llama.cpp Service in the same namespace, OpenAI-compatible over HTTP.
Tier 3 — init-container fetchThe same Service, whose Pod pulls the GGUF from an internal registry before the main container starts.

Presenton and the Helm chart set only CUSTOM_LLM_URL / CUSTOM_LLM_API_KEY; one values.llmProvider.tier enum selects a values sub-block. Three URLs, one contract, never a different code path. The chart defaults to restricted-v2: all capabilities dropped, seccompProfile: runtime/default, no privilege escalation, non-root arbitrary UID, no hardcoded UID/GID anywhere.

04

The two gates

Buyer gate — binary, procurement-visible

Recipes upstream-merged on conda-forge → landed on the customer's JFrog Artifactory mirror → image on their registry. Every build ships an SBOM (CycloneDX primary, SPDX secondary), a cosign attestation, and a versioned /metrics schema. He signs once and forgets it.

User gate — behavioral, renewal-driving

≥60% of piloted decks show edit-not-rewrite behavior · ≤30 min P95 prompt to first renderable slide · ≤10s P95 per refinement on Tier 1. Quality bar: better than writing it by hand at 2am — explicitly not M365-Copilot parity.

The two open Phase-0 calls

6(a) — the Redmond contingency

Microsoft's disconnected stack (Azure Local disconnected operations + Microsoft 365 Local + Foundry Local) went GA worldwide 2026-02-24. Its supported-services table lists infrastructure primitives only — no Copilot, no M365 apps, no AI service. Whether the deck-generation application layer is on is unconfirmed, and it decides whether Risk R3 is materialized. The standing Microsoft watch missed the announcement — Phase 0 backtests it too.

6(b) — five recipes, or seven

mem0ai + fastembed-vectorstore are unconditional Presenton dependencies and neither is on conda-forge. Add both (two more staged-recipes cycles, two more allowlist requests, two more drift surfaces), or feature-drop memory — which only holds if the import graph no-ops without a Presenton patch, not yet verified. Both branches pre-wired, default off, so build work is not blocked.

The claim

The buyer is paying for a deck generator they are allowed to install.

Copilot-class capability and survives security review — the intersection nothing else clears. Presenton is the repackaged app; deckcraft is the from-primitives pipeline. Complementary, not competing.
