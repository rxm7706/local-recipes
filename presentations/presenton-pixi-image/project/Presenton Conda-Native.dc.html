Without this

The customer integrates five unsigned upstream artifacts — a closed-source export bundle, a closed-source PyInstaller converter, a browser binary nobody ships on conda-forge — and owns that integration risk themselves.

With it

They integrate one signed image, one SBOM — and we own the integration risk. Five unsigned upstreams cannot pass an IL5 SBOM gate independently; one signed conda-forge image can.

Two planes

Build-time pipes and filters; run-time hexagon with exactly one true port. Nothing else in the running system branches on deployment topology.

Presenton, Conda-Native05 / 10
AD-2 · AD-8

One true port, three tiers

Tier 1 · external proxy

An operator-supplied corporate endpoint. No in-cluster resource. All latency targets are measured here.

Tier 2 · in-cluster sidecar

A llama.cpp Service in the same namespace, OpenAI-compatible over HTTP.

Tier 3 · init-container fetch

Same Service; its Pod pulls the GGUF from an internal registry before the main container starts.

restricted-v2 by default

All capabilities dropped · seccomp: runtime/default · no privilege escalation · non-root arbitrary UID · no hardcoded UID/GID anywhere.

Presenton, Conda-Native07 / 10
Phase-0 exit 6(a) · Risk R3, existential

The Redmond contingency

Microsoft's own disconnected stack — Azure Local disconnected operations + Microsoft 365 Local + Foundry Local — went GA worldwide 2026-02-24. Every infrastructure primitive needed to run a disconnected Copilot-equivalent is now shipped by Microsoft directly.

What is confirmed

The supported-services table lists infrastructure primitives only — portal, ARM, RBAC, Arc-enabled VMs/AKS, registry, Key Vault. No Copilot, no M365 apps, no AI service named.

What is unconfirmed

Whether the deck-generation application layer is turned on in the disconnected SKU today, or roadmapped. This determines whether R3 is materialized, partially materialized, or infrastructure-only.

What it cost us to learn

The standing Microsoft watch — yearly + gate-coupled + always-on RSS on the words disconnected, air-gap — missed it. Phase 0 backtests the watch, not just the question.

Treat the window as unknown and urgent — not the falsified 12–24-month runway. Resolve before further v1 build investment.

Phase-0 exit 6(b) · scope · AD-7 pre-wires both

Five recipes, or seven

mem0ai and fastembed-vectorstore are unconditional Presenton dependencies and neither is on conda-forge. The recipe count is genuinely open — not the fixed "six" the plan used to say.

Option A — add them
Recipes 6 & 7

Full upstream parity — chat memory and presentation memory kept. The price: two more staged-recipes review cycles, two more JFrog allowlist requests, two more drift-detection surfaces.

Option B — drop for v1
Documented feature-drop

Only stays a "drop" if the import graph no-ops cleanly via env var — not yet verified. If it needs a Presenton source patch, this becomes carrying a fork, with a maintenance burden the plan models for nothing else.

Build work is not blocked while it is open: the presenton-memory pixi feature and values.memory.enabled both default off, and either answer fits the same shape.
