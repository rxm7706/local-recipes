ACT IThe problem & the model
why a factory, and what shape it takes
01

The problem

Autonomous coding fails two ways: unattended agents ship plausible-but-wrong code, or humans review everything and the speed evaporates. Marshal's answer is structural: deterministic orchestration, spec gates before merge, scope checks on frozen surfaces, an outside supervisor the session cannot disable, and independent verification — gates are never weakened to raise the autonomy share. The Spec names the four prices of not having it: the gate disappears exactly when it matters, unattended runs fail silently and expensively, the paper trail evaporates, and operating the loop is a set of memorized rules written nowhere a machine can enforce them.

The thing that governs the agent cannot be a thing the agent authors. Marshal is a harness, never a Skill: no module makes a model call, loads a skill, or reads agent-authored prose as instruction — it consumes specs, feeds, journals, exit codes and path sets, and a test asserts no LLM client is importable from the package. That single constraint is what makes "unattended" and "trusted" compatible words.

06

Three ways work flows through Marshal

Flow A · one attended story

The judgment-heavy path. A human drives with bmad-build or approves each spec at the gate; the harness still owns verify + scope-check, and the review checkpoints still fire. Best for scaffolds, design-heavy work, parity checks, publishes — and a single story, where loop overhead is waste.

marshal preflight → marshal factory dispatch --story 2.1 (per-story gate)
Flow B · an epic, loop-gated

The workhorse that shipped Atlas and Warden. Approve once per story-spec or per epic; the loop dev→review→verify→merges the batch; deferrals land in the ledger, escalations pause the run and are resolved interactively with bmad-loop-resolve. Stage-boundary pushes mean no finished work sits unpushed.

marshal init <slug> → marshal factory spin --epic 3
Flow C · the unattended fleet

One loop home per station on one machine, gate_mode none — the review pass still standing, every escalation still pausing, story specs promoted before teardown. drain walks the backlog one story at a time until it is empty or a human is needed; a merged story with a stale backlog row cannot respawn forever. Wake to merged code and a paper trail.

marshal homes → marshal factory drain --project <slug> (fleet, overnight)

Two supervisors exist today — the loop sidecar and the dispatch supervisor — and both write truth to journals on the machine that ran them. The run-state publisher Dream (marshal-owned, specified this month) gives them one publisher, so a run is a fact the estate holds rather than a file a laptop holds.

The contract behind the commands

7934 tests collected in the station's own environment. Every finding a coded MRS-* envelope — agents always receive parseable output. Frozen exit-code domain {0,1,2,3,4,130}, one owner of the verdict lattice, no module minting its own exit code. Exactly one harness seam (FR-52), enforced by an import-linter contract that fails the build on any other reference. The journal is written before the act. Teardown interrogates git before touching anything: uncommitted or unmerged work refuses without an explicit --force. Idempotent re-runs converge. Wrap, never absorb — the engine stays upstream, the fork stays a bounded swap, and the recorded fork triggers are the only way that changes.

Console scripts: marshal and marshal-mcp — the station's own governed tool server, rendered PATH-relative into every loop home's .mcp.json by policy. The persona grammar is pyforge marshal …; the binary is not a second public grammar.

The execution doctrine · ratified 2026-07-31

Skills are the unit of execution · the harness is the unit of governance · station verdicts stay independent. The thing that governs the agent is deliberately not a skill — and Marshal sequences on verdicts it never authors: gating reads each station's durable verdict artifact, pinned to the revision it judged. Marshal never runs the judge. Allowlists narrow only; the governed agent never authors the allowlist it is judged against.

13

Escalation & the ledger

When it blocks

The loop defers with a ledger entry (deferred-work.md) or escalates to a named human — never a silent skip, never a quiet workaround. An escalation pauses the run so no story proceeds past it; a resume against an unresolved escalation is refused with a named finding. The supervisor's ladder — nudge → stop-and-retry → defer — fires well before any token or time cap.

What it writes

Run journals with weighted token spend, written incrementally and before the act; ATTENTION files at gates; labelled merge commits; promoted story specs that survive teardown; the sprint ledger promoted on landing — terminal states monotonic, so a write that un-finishes a story is refused and named. The line is auditable end-to-end from exit codes, journals and git alone.

What it still cannot see

Both supervisors write their truth to the home directory of the machine that ran them; a completed run's timing dies with the workstation, and two stations learn run state by scraping that directory. The run-state publisher Dream names one publisher for start, heartbeat, completion, per-story timing and per-layer savings — so a run only its laptop knows about stops being a run the estate cannot govern.

Journal before act
the single source of run truth; a killed run is reconstructible from what was already written
Escalation by pull
knowledge flows by pull, never by cross-boundary write; the resolving human reads the artifact the run named
Truth partitioned by domain
runtime state from journals, story status from the ledger, merges from git — never one file pretending to be all three
No destructive default
no force without the flag, no AI attribution in a commit, no teardown over unmerged work — refusal is the safe verb

Solo developer

A second shift. The loop ships the mechanical bulk overnight inside gates you set; your attention goes only where judgment matters. 926 of 966 fleet stories of proof, on one machine, one home per station.

Engineering manager

A board that cannot lie: sprint ledgers promoted by the landing verb, the detector registry patrolling the artifacts, per-story token spend journaled, velocity that captures hand-driven work too, deferrals durable instead of vanishing.

At enterprise scale — air-gapped, portable, policy-driven

Four policy layers, pure

Marshal defaults → repo defaults → project policy → invocation flags; last wins, per-key provenance, composed once and immutable for the run. Site-wide enterprise config is materialized at install time into the defaults layer — composition stays pure at runtime, and an invalid policy is rejected at preflight naming the layer that introduced each bad key.

Internal tooling mounts, never forks

Internal MCP servers (Jira, Confluence, knowledge bases) enter through the policy-declared tool surface, rendered per loop home into its own .mcp.json; the user registry is never touched. Proprietary agent CLIs enter as declarative adapter profiles with a dated conformance row. No factory fork required.

Local-first, offline by default

No hosted control plane, no telemetry, no account. Network use is never silent; the seed installer's egress counter asserts zero calls across init, adopt and check; journals and gate records are self-owned — vendor retention windows and transcript formats cannot orphan the audit trail.

Brownfield · seed adopt

Adopt in place without disturbing what runs: detect → plan → confirm → apply, dry-run by default, refusing on a hand-edited managed artifact or a dirty worktree.
