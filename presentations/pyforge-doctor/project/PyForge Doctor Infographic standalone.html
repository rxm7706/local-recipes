ACT I Instruments everywhere, physician nowhere
The problem and the model
01

The problem

The factory's health signal already existed — scattered. Warden knew whether its engines were present; Atlas knew who lagged upstream, who had a new advisory, whose feedstock was stuck; the sprint ledgers knew what was done. No shared vocabulary for severity, no pre-flight gate, no pulse, no prescription. A missing engine or an unconditionally injected credential surfaced mid-build instead of in the first five seconds; an operator reconciled five CLIs by hand to answer "what got worse this week"; findings piled up with nothing ranking them into "do this first".

A fault caught in triage costs seconds; the same fault in production costs an outage — or a shipped vulnerability. The Physician's mindset is preventive vigilance plus a continuous pulse: run the self-check before the factory spins so a broken config fails fast, never mid-build; and once packages ship, never be one-and-done. Charter § Doctor — the station is the post, not the person; the verdict outlives the being that rendered it.

Consolidation, not invention. Doctor adds exactly one detection capability — the credential/environment-hygiene check — and says so in its own non-goals. 03

The facade — instruments in, one report out

A facade over existing instruments, internally pipes-and-filters: gather → normalize → verdict or prescribe. Doctor's own code is coordination and ranking, never detection — it spawns no scan engine and runs no database query that Warden or cf_atlas does not already own. Exactly one narrow subprocess site exists (cli_bridge), and only for the CLI-fallback branch.

Filters are added by naming a new Source, never by widening an existing one's scope. The closed taxonomy has been extended repeatedly — adoption, marshal-durability, the ledger and board and chain verdicts, deferred-work, suite drift — and never opened to a stringly-typed source.
04

Nine capabilities — the whole contract at a glance

Every capability carries a success criterion written to fail when the capability is absent, and every one now carries a verified: line from a mechanical re-verification at a named HEAD — the CAP-effect discipline Doctor itself enforces on other Specs (Epic 21). The Spec reads shipped; the Dream reads realized.

Why CAP-9 is the one that changed the station. The Charter has said since late July that the Doctor holds the verdict on Marshal's conformance — "the one station that would otherwise grade itself" — but nothing implemented it until a single sprint-ledger-sync run destroyed done markers across four stations and printed success, and all three guards written in response lived in Marshal's own surface. The design point worth remembering: unlike the Warden source, this one imports no station package — a durability verdict assembled from the judged station's own code would fail exactly when that station's machinery is what broke.

07

Persona, grammar and the skills wielded

Skills are wielded, never worn: the Smith authors and upgrades them, and the harness that governs the agent is deliberately not a skill. Doctor's identity is a persona plus one content skill plus one utility skill it reaches for when a finding needs a cause.

Persona

bmad-agent-doctor

The addressable station persona. Acts only through pyforge doctor … grammar and POST /stations/doctor/mcp; never freelances against the filesystem, never makes an ad-hoc HTTP call. Greets, then dispatches — findings stay advisory in every sentence it speaks.

Content skill

pyforge-doctor (SKF)

Compiled from src/shared/packages/pyforge-doctor/ as an agentskills.io content skill — quick start, CLI grammar, key types, the exit-code projection — so an agent reads documented behaviour instead of training data. Consulted, never imported.

Utility skill wielded

bmad-os-root-cause-analysis

When a detector finding needs a cause, Doctor wields the RCA skill — advisory only, never to change a verdict. Routed by Epic 20 as the suite-lifecycle Spec's own relay, so root cause is a named step, not an improvisation.

Craft it never replaces

conda-forge-expert

Recipe work belongs to the CFE craft, at skill version 8.90.5 with gotchas numbered to 117. Doctor pre-flights the factory that wields it; it authors no recipe and edits no CLAUDE.md or AGENTS.md.

The two doors, and only two. Path B is the unified grammar — pyforge doctor check, pyforge doctor monitor --fleet, pyforge doctor diagnose --target … — dispatched from the repo root, never a hardcoded absolute path, never the bare doctor binary as a second public contract for personas. The service face is POST /stations/doctor/mcp on the Canopy host, identity tool station_face. A transcript of a completed station task shows only those two, plus the one permitted skill consult.
What the persona may never do. No direct filesystem against reports, recipes or source; no curl, requests, httpx or WebFetch; no second PR gate; no replacing conda-forge-expert. The forbidden list is the doctrine, written as a contract an agent can fail.

09

Pipes and filters — the way work flows

Three verbs compose the same filters differently: check gathers Doctor's own check catalog and projects a verdict; monitor gathers the atlas axes fleet-wide and may persist the surface; diagnose gathers one target and hands the findings to prescribe. Nothing downstream re-gathers.

10

The autonomy gradient — how far a finding may travel

Doctor's autonomy is graduated in the opposite direction from Marshal's: the further a finding travels, the less Doctor is allowed to decide. It observes freely, warns freely, fails an operability run — and stops. Beyond that line every rung belongs to another station or to the human.

Read-only, all verbs
no --fix, no PR-opening, no file mutation — the persistent surface is derived output, not a change to scanned state
Warn is free
a warn-status finding is information; it never flips the exit code, so a noisy detector can never fail a run by accident
Fail is operability
"a required engine is missing", "the ledger regressed" — a statement about whether the machine can run, never about whether the code may merge
The one governed actuator
flags kill-switch disables one feature flag and records the metric — an off-switch relayed from the platform's flag policy, not a remediation and not a gate

The shipped CLI — 6 subparsers, one envelope

Console script doctor, package pyforge-doctor 0.1.0, run through the unified grammar pyforge doctor …. Three clinical verbs carry the Spec; a backlog-intake scan and a governed flag actuator were relayed in by later chains. --version is top-level only, mirroring Warden.

verb · pre-flight

doctor check

[path] [--engines [NAME]] [--env [NAME]]
[--durability] [--bmad-core] [--sibling-dreams]
[--scope repo|runtime|all] [--list] [--json]

Tri-state, individually nameable checks. --list enumerates the catalog without running it; a named check in isolation matches its result inside the full suite; --scope reads each category's scope through the one canonical registry lookup. Stays within the five-second pre-flight budget — a benchmark guards it.

verb · pulse

doctor monitor

--fleet [--watch AXIS[,AXIS…]]
[--target MAINTAINER] [--source SOURCE]
[--json] [--surface PATH]

--fleet is required. Findings are equivalent to the underlying atlas call, source-tagged and filterable by --source. Default axes staleness and cve; adoption and abandonment widen on request. --surface writes the idempotent fleet-health file.

verb · triage

doctor diagnose

--target TARGET [--prescribe] [--json]

Gathers one target. Without --prescribe the findings are reported but not partitioned; with it, every finding lands in actionable, blocked or accepted-risk, the actionable set is ranked with its factors shown, and each Prescription names a root cause and — when confidently known — the single-hop next safe version.

verb · intake

doctor backlog-intake

<identifier> [path] [--json]

Scans every station's tracked deferred-work-ledger.md for entries naming an epic or story, fleet-wide, so a deferred item is surfaced as a candidate acceptance criterion the moment that story is drafted — instead of inert prose only a human happens to re-read.

verb · actuator (governed)

doctor flags kill-switch

--flag KEY --reason TEXT [--flags-path …]

Disables one file-resolved OpenFeature flag and records the kill-switch metric with the operator's reason. Relayed from the platform's flag policy; the one thing Doctor may switch off, and it is a feature flag, not a finding.

dispatcher · the registry

python -m pyforge.doctor.sources

<name> [--json] [--groundtruth]

Target-less by design — it judges the repo it is invoked from, by working directory rather than __file__, because the package ships installed. The pixi tasks that used to call scripts/*_check.py call this instead, one source at a time; bmad-drift-check is bmad-drift here.

One envelope, every verb. --json emits a DoctorReport — schema_version, verb, generated_at, findings, and prescriptions only when the verb is diagnose — validated against the committed data/report-schema.json and composed on pyforge-core's base envelope schema. Nothing in the human render is absent from the JSON. main always returns an integer; it never calls an exit primitive itself, and a component calling sys.exit inside a gather can never dictate the process exit.
14

The doctrine — six lines the code is tested against

Operability, not policy.
Doctor's exit code answers "can the machine run", never "may the code merge". The domain is closed and deliberately omits Warden's policy-gate rung; Warden's exit is consumed as data and never re-exposed.
Advisory, never a second PR gate.
Findings stay advisory or become Warden inputs. No finding, no detector and no dispatcher output is a competing PR verdict — the skill, the persona and the Spec each say it in their own words.
Never a false green.
A detector that cannot run reports unknown; a missing package degrades to unknown rows; an incomplete gather grades incomplete. The strip never claims green it did not measure.
Facade over instruments.
No new scanning engine, no new data source beyond the one hygiene check. Coordination and ranking are Doctor's craft; detection belongs to the instruments it wraps.
The hand that builds is never the gate that judges.
Every source judging a station's artifact is barred from importing that station. A durability verdict assembled from the judged station's own code would fail exactly when that station broke.
Derive, never declare.
The registry is the count; the roster is read from guild-roster.json; the detector list is discovered from disk and fails on its own gaps. A number written in prose is a second source of truth that goes stale.

Escalation and the ledger — how a finding becomes work

A finding that nobody can act on is noise. Doctor's findings travel a fixed route into the estate's durable records, and each hop is owned by someone other than Doctor — which is the point.

1 · report
DoctorReport
the schema-validated envelope, pinned to the tree it judged. Marshal reads it as a durable verdict artifact and sequences on it; it never re-derives it.
2 · defer
deferred-work ledger
work not taken now lands in the station's tracked deferred-work-ledger.md — never only in gitignored scratch; the deferred-work source fails it if it does.
3 · intake
backlog-intake
when the named epic or story is drafted, the entry surfaces as a candidate acceptance criterion; due-for-verification re-opens entries whose live re-check is overdue.
4 · cause
root-cause analysis
for a finding that needs a cause, the persona wields bmad-os-root-cause-analysis — advisory, never to change a verdict.
5 · remediate
someone else's hands
Steward for the estate, Mason for a recipe, Marshal for its own row — each station remediates its own row; the Doctor holds the verdict, never the fix.

Why the doctor domain has no rung for "findings". Warden's frozen domain carries a policy-gate rung between pass and fail; Doctor's is a strict subset that omits it permanently, because a caller — Marshal above all — must never misread a Doctor exit as "policy violation" when Doctor has no policy concept. A warn never changes the exit code. The two spaces are read-only inputs to each other, never merged.

And why the registry's is different again. The detectors aggregation answers a different question — did every patrol run, and did any of them find something — so it distinguishes findings from could-not-run. Two is not a softer zero: a detector that cannot run reports unknown, and unknown is never green.

What each leader gets

The operator at the keyboard

One pulse instead of a weekly habit of five CLIs. monitor --fleet answers "what got worse" in one source-tagged view; diagnose --prescribe hands back a worklist with the reasoning visible, so the judgement call is still yours — but it starts from a ranked list, not a pile.

Marshal — the machine consumer

An unattended pre-flight that fails in the first seconds rather than mid-build, on a closed exit domain that can never be mistaken for a policy verdict. And a set of standing verdicts on its own ledger, board and chain that it cannot weaken, re-threshold or disable — the guard it was never allowed to hold for itself.

The security lead

Exploited-in-the-wild first: KEV outranks everything at equal severity, EPSS breaks the next tie, upgrade lag the last. Every prescription shows its factors and names a root cause from its own evidence, and the one new detector — unconditional credential injection — catches the class of leak that already happened once.

Steward — platform and keys

A finding you can act on: which credential is attached without a host scope, which engine is missing before anyone's run needs it, which BMAD core or suite member has fallen behind. Remediation is Steward's; the verdict arrives already partitioned.

Mason and the release engineer

The shipped estate under continuous watch — staleness, red CI, stuck bots, silence, abandonment — and, when something moves, a single-hop next-safe-version suggestion sourced from upstream data, or a plain statement that none is confidently known.

The executive reader

A composite A–F grade per dependency and a persisted fleet-health surface that diffs only when something actually changed — derived output, never a fresh gather, never a timestamp churning the file. The board's status strip never claims green it did not measure.

19

Enterprise and air-gap — a physician that carries nothing in

Doctor adds no network path of its own. Every remote signal arrives through an instrument the estate already routes — the atlas MCP server, the atlas CLIs behind _http.py's truststore and JFrog/GitHub/.netrc chain — so an air-gapped deployment configures its mirrors once and Doctor inherits them.

Read-only in every verb. No module writes outside a tempfile-scoped path or mutates a scanned tree. The credential-hygiene scan is ast.parse only — never exec, eval or a dynamic import of the code it inspects — so pointing it at an untrusted tree is safe by construction.
One bounded subprocess site. When no MCP client is in-process, cli_bridge runs the equivalent atlas CLI: argv as a list, NO_COLOR, stdin=DEVNULL, a bounded timeout, and a typed fail Finding on error — never a shell string, never a raw traceback. Both paths normalize identically.
Runs where the runner can see. Repo-scope sources read tracked files and git history and run in CI (detectors-ci); runtime-scope sources read tmux, Tier-3 feeds and ~/.bmad-loops, which do not exist on a runner, and are excluded there rather than faked. The exclusion is the missing observation plane made visible, not a convenience.
Lean by environment. The pyforge-doctor pixi environment is no-default-feature: the built package, its conda run-dependencies and a test runner. The detectors workflow's locked environment carries the same package; when it is unimportable, the ported sources degrade to unknown rows — counted, never green.
The credential finding that named the station's one new instrument. An env-var read feeding an HTTP auth header with no host-scope conditional sends the key to every host — the JFROG_API_KEY pattern. A host-scoped attach must not fire. That boundary is written into the Spec so the detector can neither over-reach into a linter nor under-reach into silence; the remediation was Steward's, on a Doctor finding, and became the precedent for how the two stations divide health from operations.

Integration seams — every edge, and its direction

Doctor's boundaries are enforced by meta-tests, not by convention. Each seam below has a stated direction and a test that fails when the direction is violated.

doctor → warden (library)

sources.warden imports pyforge.warden.engines.run_doctor_checks directly — the only cross-package code edge, declared as the optional gate extra. No reverse import may ever exist; a meta-test asserts the source contains no subprocess call.

doctor → cf_atlas (MCP, then CLI)

sources.atlas is the sole sanctioned mcp import site. The MCP tool is asked first; the CLI fallback runs only through cli_bridge. The caller cannot tell which path produced a Finding except by its Source tag.

doctor ← pyforge-core

The verdict Lattice and the base envelope schema come from pyforge-core; the shared pyforge.core.hooks contract carries Doctor's doctor-gather and doctor-prescribe plugin entry points — one loader, not a second.

doctor → tracked artifacts only

The Marshal-judging sources read sprint-status-ledger.yaml, epics.md, Specs, Dreams and git — and import no station package. guild-roster.json is the constitutive read for the eight stations, the Dream statuses and types.

detectors.py → doctor.sources

The filesystem-derived registry threads Doctor's ported sources in-process, into the same results list and the same exit aggregation as a scanned detector; sources.REGISTRY is what --list catalogs.

The Canopy → doctor

pyforge doctor … is the unified grammar; POST /stations/doctor/mcp the service face, identity tool station_face. The /stations/doctor/ portal's first job is the last fleet-pulse summary, rendered through the host's PortalClient — no pyforge.* under src/platform/.
