ACT I The aspiration, and the machine that keeps it true
The problem and the model
01

The problem

Software is written from intentions nobody wrote down. The aspiration lives in a head, the plan in a wiki, the contract in a ticket, the code in a repo — four artifacts, four owners, and nothing that fails when they stop agreeing. Add agents to that and the failure mode does not change, it accelerates: a model happily produces plausible code against a plan it never read, and a build reports green because nothing in the pipeline is allowed to say no. The industry's answer has been "AI-assisted coding" — a faster hand on the same unguarded loop.

The insight is organizational, not technical. Autonomy does not fail on model capability; it fails on accountability. If no named post owns a stage, nothing can be asked to justify a green — and a system nobody can interrogate cannot be trusted with the keys. So the model starts by chartering an organization: eight stations, each a lifecycle stage plus its independent verdict, and one document that authorizes them all.
The one rule everything else is built to protect: the hand that builds is never the gate that judges. Mason's build does not pass because Mason says so; it passes when Warden's gate says so. Marshal runs the line but never authors the verdicts it sequences on. Doctor — and only Doctor — holds the verdict on Marshal's own conformance, because that is the one station that would otherwise grade itself.
02

Dream to Code — the pipeline, tier by tier

Each tier is a real directory with a real contract, and each one is derived from the tier above it rather than written beside it. The tiers are never crossed: a Dream is not a plan, a Spec is not a story, and execution output is never the record. Nothing enters the factory except through a Dream — gap-closure, realization work and fixes to efforts whose stories already exist included.

Tier 0 — the Dream
Plain markdown, tracked, framework-neutral. Frontmatter carries type, owner and status; owner: is the through-line propagated onto every downstream row, and a Dream naming no station is a dream-unowned finding rather than a blank cell.
Tier 2 — the Spec and its chain
The five-field contract distilled by bmad-spec, plus the PRD, architecture spine, epics and stories that decompose it. A plan without a Spec is a plan, not a contract: nothing holds the five fields still while the plan moves.
Tier 3 — execution output
Story runs, sprint YAMLs, retro scratch, loop worktrees — gitignored by design. Durable per-story intent contracts are promoted out of it into the tracked record once the story merges, because in a spec-driven build the spec is the contract.

The identity system is a constitutional model for autonomous delivery: each noun is a load-bearing separation of concerns, and the chain reads in both directions — forward as authorization, backward as audit. The discipline is the same one the architecture reviews enforce in code — sole ownership, one writer per contract, no dual homes — applied to the organization itself.

04

The Charter's doctrine — the lines that do not move

A constitution is only worth the claims it can back. Each line below is a standing rule with a named consequence — and where a claim outlived the machine that enforced it, the Charter says so rather than quietly keeping the sentence. That admission is itself the doctrine applied to our own copy: overstating our coverage is the one thing a never-false-green product cannot do in its own constitution.

The hand that builds is never the gate that judges.
Mason's build passes when Warden's gate says so. Marshal sequences on verdicts it never authors — reading another station's durable, revision-pinned verdict artifact, never invoking the judging station and never re-deriving its answer.
Execution has one owner.
Marshal alone runs the line. Skills are the unit of execution; the harness — gates, sandboxes, CI verify, no-LLM tools — is the unit of governance and is deliberately not a skill, so the thing that governs the agent is never a thing the agent authors.
Amendment, never silent edit.
A constitutional change lands as a dated Realization-log entry naming what it superseded and why, with the superseded text quoted rather than deleted. A reader can reconstruct every change from the log alone.
The station is the post, not the person.
Proven under fire: dev sessions were killed mid-story and the stations held — verdicts stayed valid, committed work was recoverable, the frozen contracts did not blink. Swapping the model swaps the being at the post; the obligations do not move.
Constants have exactly one home.
The membership, the constitutive Dream and the Dream vocabulary are declared once in docs/governance/guild-roster.json and read everywhere. A hardcoded copy is a finding on sight — after two mirrors agreed by luck until one drifted.
Every Dream is owned by exactly one station.
Ownership is not a label on Tier 0; it is the through-line carried onto every downstream row. An unowned Dream is work with no accountable post — precisely the condition the station model exists to make impossible.
Owning is becoming — at the planning tier, and only there. A Dream's planning chain lives in its owner's project, but that never renames the package: what ships is declared by the Spec's own surface:, independent of which planning tree hosts it. The earlier, superseded clause conflated planning home with package identity and forbade the first to protect the second; only the second needed protecting. Consequence: 8 Smiths, 8 projects, and no placeholder in the target state.
Outcome and mechanism — where a story lives. Because each Smith works one craft, work routinely spans two: the outcome belongs to one station, the mechanism that delivers it to another. The rule, written after four Specs stalled on the same unanswerable question: the owner of the outcome writes the story; the owner of the mechanism owns the verb it calls. Ownership follows what the work is for, not what it touches.
And the one place the constitution currently marks itself unbacked. The Charter's own Spec refuses to declare itself finished while two of its enforcement claims name machinery that no longer fails: the console that once gated on the ownership through-line has been retired with nothing put in its place, and one unguarded mirror of a constitutive constant still agrees with the roster by luck rather than by construction. Both are recorded in the open, routed to a station as ordinary work, and deliberately not rounded up. A gate that prints a warning and exits clean is the inversion this doctrine exists to catch — including when the document doing the catching is this one.
05

The constitutive contract at a glance

A Spec for a constitution looks circular — and the circularity is the point. The Charter governs the workers; its own Spec governs the one thing the Charter cannot do for itself: stay true. Each capability below is a property of the document, not a feature of a product, and each carries a standing that is stated rather than assumed. A charter nobody keeps current is not a constitution, it is a wall poster.

This is the never-false-green doctrine turned on its own constitution, and it is the single best evidence that the doctrine is real rather than decorative.

07

The topology — one body, eight posts, one hall

Not a hierarchy and not a swarm. The Charter authorizes a single body; the body seats eight posts, each holding one lifecycle stage and the verdict over it; and every verdict surfaces in one hall where a human can govern intent without reading a log. Marshal is the only post that may run the others' work, and it is also the only post that does not judge its own.

08

The branding law — one brand, three registers, four senses of one word

A naming convention looks like the least constitutional thing in a charter, right up to the moment two teams mean different things by the same word. The law below exists because each ambiguity it closes had already cost something: a register that drifted, a noun that named two artifacts, a technical form that a package index would have rejected outright.

The brand and the technical form are different strings. Written content — decks, docs, titles, dashboards — carries the brand case. Anything in a code context — distributions, modules, slugs, filenames, environments, branches, commands, URLs — carries the lowercase technical form. This is not a style preference: the packaging ecosystem normalizes names, which makes the split non-negotiable rather than tasteful.
Three registers, one being. Smith is the brand term a deck says; agent is the category the mission says; persona is the technical term a configuration says. Each audience needs a different word for the same accountable thing — and the moment the registers drift into different things, accountability blurs. There is deliberately no fourth register.

Products in prose take their full form once, then the persona name. The first mention in a document is the full brand form; every mention after it is the bare persona name; the package form appears only in code contexts. Small rule, large effect: it is what lets a reader of any one document know, unambiguously, whether a sentence is talking about a post, a person or a package.

Why two layers and not one roster. A sub-agent is disposable: spawn it, scope it, take its output, discard the context. A station is not — it carries a standing verdict that outlives every session. Collapsing them would make the verdict as disposable as the worker.

The armory — Skills are wielded, never worn

Skills are the unit of execution and they belong to the Guild, not to any one Smith. Three consequences follow, and all three are load-bearing. Governance survives — Smiths author skills, so if a Smith were its skills the agent would be authoring itself. The armory is shared — any Smith touching a craft wields that craft's skill without becoming that Smith, and a skill sharpened by one effort upgrades every future wielder. Blades version; beings do not — the Smith wielding the eighth major version of a craft is the same one who wielded the sixth.

One Dream's journey — from a paragraph to merged code

The same path every time, whether the work is a new station or a one-line fix. Each stage has an artifact that must exist at the end of it, a post accountable for that artifact, and a specific way it can be stopped. Gap-closure is not an exemption: "we already know what to do, let us just do it" is precisely the request that skips the place where the review loop fires.

Status names the act that completed, never the artifact that proves it. There is deliberately no "building" state: status declares what exists and the board derives what is happening from live build lines. Hand-maintained activity tracking rots — a station once read "in spec" while it had shipped every one of its stories.
Status is not a proxy for work remaining, in either direction. Two Dreams read as barely started while their epics were fully done and merged; the single largest block of unbuilt work in the fleet sits under a Dream that reads archived, because it was correctly consolidated elsewhere. For "what is left", read the ledger — never the status field.
12

Three ways work flows — and when each is the right one

The same contract, three different engines over it. Choosing wrongly is not a correctness failure — it is a waste failure: an unattended run costs setup, a worktree and a supervisor, and spending all of that on a single well-understood story is worse than doing it directly. The rule of thumb is the shape of the work, not its size.

One — the unattended line

What it is: a supervised loop that takes stories off the ledger in dependency order, runs a dev session and an independent review session per story, lands the ones that pass, and pauses on anything it may not decide.

Where it wins: a sequence — an epic, a wave, a whole chain — where the contract is settled and the value is in not being in the room.

What it costs: a run home, a worktree per loop, and a supervisor process; plus the discipline that a "killed" agent may still be alive.

Its safety property: escalation is non-destructive. Work in flight is preserved and restored as a patch — never re-implemented from scratch, which is what an unguarded re-arm would do.

Two — the attended single story

What it is: one story, implemented directly against its spec with a human present, reviewed the same way, landed the same way.

Where it wins: a single story whose shape is already understood, an urgent fix, or work where the human wants to see each step — the loop's overhead buys nothing here.

What it costs: attention. It does not scale past what one person can watch.

Its safety property: identical. The same gates, the same independent review, the same ledger discipline — the engine changes, the contract does not.

Three — the retro loop

What it is: the closeout pass. A finished effort is read back against its own evidence — diffs, failures, review findings — and the lessons are written into the skill, with a dated changelog entry and a version bump.

Where it wins: everywhere, and it is not optional: an effort is not done until the retro lands. Even a clean effort produces an entry recording that existing guidance held.

What it costs: one more pass at the end, every time.

Its safety property: it is the only flow that makes the next effort cheaper. Corrections, refinements and additions all land in the armory, where the next wielder picks them up for free.

A fourth path exists and is deliberately not a flow: course correction. When something material changes mid-sprint, the answer is not to quietly re-scope the stories — it is an impact assessment across the PRD, the epics, the architecture and the UX, landing as a written change proposal. Silent re-scoping is how a spec-driven build stops being spec-driven while every status field still reads green.

The autonomy gradient — how far the leash goes

Autonomy here is a gradient, never a leap of faith. The ladder is a governance taxonomy, not a capability boast: each rung says who decides, not how clever the model is. The production ceiling is the conditional rung — unattended work inside machine-readable boundaries, where anything the agent cannot safely decide escalates to a human instead of being guessed. The rungs above it are real destinations, and they are reached by moving the boundary, not by removing it.

Per-story, not per-org
autonomy is a property of the story. The level is set when the work is planned, so one epic can mix an attended story with a dozen unattended ones.
Escalation is a feature
a session that meets a contradiction the spec cannot settle stops and asks. The pause is the governance working, not the automation failing.
The harness holds the line
gates, sandboxes and permission boundaries live outside the agent, so raising the level never means trusting the agent to police itself.
Both extremes are governed
a tool-bounded remote surface and a sandboxed native terminal are both in production here — capability bounded by policy, at either end of the spectrum.

Never a green it did not earn

Three claims the model makes about itself, each with the incident that forced it to be written down. A constitution earns its authority by surviving contact with its own failures — and by recording them rather than rounding them off.

Claim one
We state our own coverage precisely, even when it flatters us less.

The Charter billed one station as a flat multi-axis auditor while the shipped product gated a subset of those axes, with the remainder named as vision-tier and not built. The correction was made in the constitution itself, in the open. Overstating our own coverage is the one thing a never-false-green product cannot do in its own founding document.

Claim two
A gate that prints a warning and exits clean is not a gate.

The console once failed publication on a rendering error but not on a governance hole: a cosmetic fault blocked the page while an unattributable row shipped silently. The answer computed the problem and threw it away. Visibility without consequence is decoration — so the hall was made to refuse the row, not merely to render it grey.

Claim three
Constants that agree by luck will eventually disagree in production.

Two files held the same constitutional constant. One was updated; the other was not; the board warned on a Dream the Charter explicitly permits. The fix was structural, not procedural — one declaration, every reader reading it. A hardcoded copy is now a finding on sight, not a maintenance obligation.

Every one of the three was found by this system, about this system, and recorded as a dated amendment with the superseded text quoted. Amendment, never silent edit.

Escalation and the ledgers — how a finding becomes work

Autonomy without a way to say "I do not know" is just confident guessing. Three mechanisms carry the unknowns: an escalation pauses a run and asks a human; a deferred-work entry records something real that this story may not do; and the sprint ledger is the single generated statement of what is done. None of the three is hand-edited, and that is the point.

MechanismFires whenResolved by
Escalationa session meets a contradiction or a gap its frozen contract cannot settlea human, in an interactive session that disambiguates the spec so the story can be re-driven
Deferred worka real finding surfaces that is outside this story's contract — recorded, never silently done and never silently droppeda triage pass that verifies every open entry against the actual code before anything is bundled into a new story
The sprint ledgeralways — it is the generated statement of every story's stateits own generator, from the feed; a status check then proves each claimed landing by ancestry
Course correctionsomething material changes mid-sprint and the plan no longer describes the worka written impact assessment across the PRD, epics, architecture and UX — a proposal, not a quiet re-scope
Escalation is non-destructive, fleet-wide. Work in flight is preserved and handed back as a patch to be reconciled — never re-implemented from scratch. An unguarded re-arm defaults to starting over, which is how an escalation turns a pause into a loss.
The ledger is read with its real parser, never a regex. A regex over a status file is how a fleet ends up reporting a number nobody can reproduce. Every count on this poster — including the fleet totals — comes through the parser that owns the format.
A merged story left un-promoted respawns forever. The loop takes work from the ledger; a row that still says "not started" for code that already merged will be picked up again on the next drain. The ledger is not documentation of the work — it is the work queue.

What each leader gets

The same architecture, read from five chairs. Note what is absent from all five: a promise about velocity. The model's claim is about traceability — and velocity is what traceability buys once nobody is re-litigating what was agreed.

The engineering leader

Every merged change walks backward to an aspiration a human wrote down, through a contract with machine-checkable criteria and an independent verdict. "Why is this in the codebase?" stops being an archaeology exercise.

One declarative registry produces every environment; one host carries every station portal; credentials are issued, scoped and rotated by a named post rather than accumulating in whoever set them up. Air-gap parity is a failing check, not a migration project.

31 declared environments, all from the same registry, all reproducible from the lock.

The security leader

Exactly one gate renders the merge verdict, over hygiene, security, license and currency; everything else that finds something feeds it as an input. There is no second opinion to shop for, and a warning cannot be mistaken for a pass.

Separately and continuously, the health post watches the shipped estate for advisories, lag and abandonment — and ranks the order of work.

The product leader

Scope is a contract with five fields and an explicit non-goals section, so "that was always in scope" is a question with a written answer. A mid-sprint change lands as an impact assessment, not as a quietly redefined story.

The engineer

The context you are given is the context the task needs — no more, which is what keeps the output on contract. Review is adversarial and blind, so a finding is signal rather than politics. And every lesson you pay for once is written into the armory, where it is free for everyone after you.

The craft skill alone carries gotchas numbered to 117 — each one a build failure somebody already ate.

The human, at the top of the chain

The role rises from writing software to architecting Dreams: write the aspiration, set each story's autonomy level, answer the escalations the agents are forbidden to guess at, and govern intent through a hall that will not publish a row it cannot attribute.

That is the whole job description — and it is exactly as much governance as an autonomous factory is safe to run on.

Enterprise and air-gap — the estate the Guild runs on

A model that only works with an open internet connection is a demo. The estate is built so the same eight stations run behind a corporate proxy, against an internal mirror, or with no egress at all — and so that the difference is a check that fails, not a document that says it should be fine.

Routing is runtime, never committed. Internal registries, mirrors and proxies are resolved at run time from the environment and the system trust store — an authentication chain, not a checked-in config. No host name and no credential belongs in the tree, which is also why an unconditionally injected credential is a finding rather than a convenience.
Read-side surfaces are offline-safe by construction. The intelligence layer's query commands answer from the local graph; a probe that cannot reach its source says so instead of reporting clean. The rule everywhere: an unauthenticated probe that fails open is worse than one that fails loudly, because it manufactures a green.
One host, eight portals. The station faces mount on a single platform rather than sprouting a process tree of public services. Deployment overlays carry the cluster shape; the same image runs locally and in the cluster, and the host is a mount rather than a ninth station — the roster stays at 8.
Air-gap parity is a failing check. The bundle installs, the environment resolves from the lock, and the tests run with no egress — or the check goes red. That is the only version of "supports air-gapped environments" that survives an auditor, and it is why the estate's dependency set is deliberately small and deliberately pinned.

The seed — the operating model, installed anywhere

The model this Charter constitutes is not only ours. It is three things at once: the master idea — the umbrella narrative of the personas, the setup and the vision; the alignment instrument — one deck that onboards anyone into the whole model in ten minutes; and the seed — the operating model as something that can be planted in a repository that does not have it yet.

Greenfield — born Dream-first

A new repository stood up with the tier layout from day zero: docs/dreams/, the governance roster, the cross-tool agent instructions, the multi-project planning wiring, the environment registry and the deck family — all before the first feature exists.

The point is ordering, not tooling. A repository that gains its Dream tier in month six has six months of untraceable work behind it; one that starts with it never has an artifact that cannot be walked back to an aspiration.

Brownfield — adopted in place

An existing repository gains the model without disturbing what already runs: Dreams and Specs are backfilled over the current surface, the chain is established from the code outward, and drift checks bind the two together from then on.

This repository was the first brownfield adoption — a working conda-forge recipe factory that acquired a constitution, eight stations and a planning tier while continuing to ship. Everything on this poster is measured from that patient.

The seed is what gets installed; the installer is what installs it — and they are different nouns. The record of the model is constitutive and lives with the Charter; the machine that stands a repository up is ordinary buildable work, owned by the post that already runs the line. Conflating the two produced a Dream doing two jobs, an owner field that flipped twice, and a constitutional clause that contradicted its own detector for weeks. The separation is the fix, and it is the reason this deck records a model rather than documenting a command.
