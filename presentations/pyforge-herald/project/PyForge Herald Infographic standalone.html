01

The problem — the work was real and nobody could see it

Eight stations shipped code, verdicts, maps and packages — and the story of it lived in commit logs and terminal scrollback. Decks drifted from the repos they described; the one bridge to a visual editing surface was a hand relay through an agent's context, which once silently corrupted a file in transit. And the posters that did exist were frozen at their authoring day: numbers quoted from memory, no source for any of them, so nothing could even detect that they had gone stale.

bytes may change between Design and git without the bridge refusing the write — the drift that a hand relay produced is the failure the bridge retired
The mandate riding on it is truth, not decoration. A poster that quotes last month's ledger is a claim the estate can no longer stand behind. So Herald's doctrine is the same as the factory's: derive, never declare — a count, version, status or date ships only when a tracked source can reproduce it, and the check that reads this page against its ledger is advisory by construction, never a second PR gate.

Herald's work is continuous, not a bookend. The early framing — "first to touch a Dream, last to touch a release" — was retired because it reads as two touchpoints with silence between them. 07

One deck's journey — from a Dream file to a byte-exact mirror

The loop the herald CLI wraps was first proven by hand across a family of decks in one day, then mechanized. Every hop carries an etag; a concurrent Design edit conflicts instead of being clobbered; only the prototype crosses the bridge, never a mirrored app tree.

The commit is always the operator's move (or an explicit --commit) — never implicit. The pull decodes the entity-escaped body and strips the contiguous serve-harness block the preview injects, then verifies the byte count against the listing. Nothing is hand-transcribed at any hop.

09

Three ways a proclamation reaches Herald

Moments II–IV shipped first as the CLI-triggered, locally stored v1 — records exist because an operator ran a verb. The live-service version adds the two other paths; its routes exist, its store exists, and the one story that makes a real ship record itself end to end still waits on a perimeter to host the listener.

Path 1 · the operator's verb — today

A human runs it, on purpose

herald progress <station> --update records the day's progress with cost and the unblock narrative; herald success create drafts a claim from evidence links, review shows the proof, publish needs the operator role; herald notice author drafts, --publish releases. Every write is a deliberate act with a name on it.

Path 2 · the webhook — wired

CI tells Herald a ship happened

Two routes on the station API seam — …/webhooks/on-ship and …/webhooks/on-pr-close — accept a signed, timestamped payload with an exact field set; anything unknown is refused with a client error, and delivery retries with backoff before it gives up loudly. The routes moved onto the seam so the Canopy hosts them, not a bespoke server.

Path 3 · the scheduler — composed

The weekly jobs run unconditionally

herald scheduler run composes two independent jobs every invocation: evidence re-validation over every published claim, then progress aggregation. Neither skips or early-returns for the other; a link that went dead is named, not silently kept. What was displayed is what gets enforced.

No silent shipping is the rule; the trigger is the frontier. Every completed project owes a Moment III claim with at least one evidence link. Today the claim exists because a human wrote it; the live backend exists so that an unrecorded ship stops being indistinguishable from no ship at all.

The doctrine — eight lines Herald does not cross

01
Invisible engineering is failed engineering
Nothing the factory does stays unseen. A ship nobody was told about is indistinguishable from no ship.
02
Derive, never declare
No count, version, status or date ships without a ledger row a tracked source can reproduce. Memory is not a source. A prior poster is not a source.
03
Etags, not hope
Every Design↔Code transfer carries one. A concurrent edit conflicts; it is never silently overwritten. Bytes never relay through a model's context.
04
Design edits; git archives
Design is the editing surface, git the record. Every Design session ends with a byte-exact pull and a commit; the README ledger tracks the etags.
05
Stations own verdicts; Herald owns the story
Herald renders no verdict of its own and never publishes a second PR gate. It reads the ledgers the console reads and proclaims from them.
06
Never restrict size at authoring
Lay everything out at full depth — six acts, inline diagrams, the long class. Cutting is a later, visual act, never a shortcut taken while writing.
07
No fabricated demos
Every screen recording in a Herald video is real. The studio receives real footage and real narration only — synthetic UI is a hard gate failure.
08
The rendered page is looked at
A render gate proves a page RUNS; only a full-page PNG a reviewer actually opens proves it LOOKS right. Both, every time.

What refuses, what records — escalation and the ledgers

Refusals — each one structural, none of them a log line
A stale etag. write_files with an if-match that no longer matches fails explicitly; the push refuses the whole set rather than clobber part of it.
An auth error mid-watch. The watcher halts and says so; it never retries a rejected credential.
An unknown webhook field. Both routes reject the payload outright instead of quietly dropping the field — a caller who can reach the route cannot smuggle state in.
A publish without the operator role. Progress updates, claim publishing, notice authoring and closing all refuse; reads never do.
A claim without evidence. A success claim needs at least one retrievable link; the weekly job re-validates every published link and names the dead ones.
A poster below a floor. Fewer than six act bands, fewer than eighteen sections, fewer than three inline diagrams, under the length class, or any fact without a ledger row — it is not marked current.
A fabricated demo. The video studio's gates fail the render; there is no override.

The check is advisory on purpose. deck-facts --check exits zero and reports unmarked, mismatch, drifted, unsourced and unshown rows. It becomes a PR verdict only if a later Spec promotes it — Warden stays the sole gate.

At enterprise scale — offline by construction, mounted under the Canopy

The deployment target is air-gapped and regulated, so every Herald artifact is built to work with the network off. This poster renders from disk; its only remote resource is the web-font link, and the system fallback stack is declared. Decks build to a static bundle that opens as file://. Exports are Marp and python-pptx, both local. The headless browser for QA and for this page's own full-page render ships in the station's pixi environment — no new browser dependency was ever added.

Inline SVG only. No raster images anywhere in a poster; diagrams are vector, in the Modernist tokens, and survive any bundle.
No external scripts. The standalone has no runtime wrapper and no support script — that wrapper belongs to the trio head and is re-derived in the lockstep slice.
Bytes never enter model context. Large uploads go server-side through DesignSync's local-path pipeline; large pulls come down the preview URL straight to disk, then the injected harness is stripped and the byte count verified against the listing.
The serve URL is never persisted. It is short-lived by design; nothing in git or in a README ever records one.

The seed — how a new station deck starts, and how a poster is rebuilt

1
Scaffold from a sibling on the Archivo system

Copy the deck engine and glue verbatim from pyforge-atlas or pyforge-warden — never from the origin deck on its own theme. Engine files stay byte-identical across every deck; an engine fix goes to all of them in one change.

2
Seed, register, design, pull

herald deck seed <slug> after a local proof; the README ## Design project section is the durable link; the human designs; herald deck pull lands it byte-exact and the derived set regenerates.

3
Facts first, then the poster, then the PNG

deck-facts <slug> derives the ledger; author to the standard — six acts, the full section set, inline SVG, every literal marked; --check until nothing is unmarked or mismatched; render full-page and look; record the measurements in the README ledger.

The standard has one home. The floors, the act arc, the section set, the diagram set, the authoring template and the README ledger entry live in spec-deck-family-currency/infographic-standard.md; the deck workflow spec points there and never restates them. Unifying Strategy is the structure, acts and length reference; Warden is the density and visual-form reference.
