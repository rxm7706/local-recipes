# In-browser DuckDB-WASM read surface (Story G1, FR-14)

This directory holds the **backend-free, client-side query artifact** for the atlas
intelligence read surface, plus the build step that produces it. It is the deliverable
behind the Wave-G `wasm-smoke` gate (AD-11 — the gate is the wave's first deliverable).

## What it does

A static HTML page (`index.html`) that, **with no application backend**:

1. instantiates a genuine **DuckDB-WASM** engine in the browser,
2. loads the parquet reader from a **locally-vendored** DuckDB extension (never from
   `extensions.duckdb.org`),
3. fetches a statically-hosted **Parquet** file (`core_feedstock_health.parquet`),
4. runs the Story-D1 `feedstock-health` query **client-side**
   (`ci_red = ci_status IN ('failure','error')`), and
5. renders the result to a stable DOM contract the `wasm-smoke` Playwright gate asserts on.

The only HTTP traffic at runtime is fetching static assets (wasm module, extension,
Parquet). There is no server that runs the query — the query runs in the browser.

## Two-step flow: build (online) → verify (offline)

```
pixi run -e local-recipes wasm-build    # BUILD-TIME network allowed (npm + ext host)
pixi run -e local-recipes wasm-smoke    # OFFLINE: headless Chromium load-and-query gate
```

- **`wasm-build`** (`build.py`) npm-installs the pinned deps, esbuild-bundles the browser
  ESM (inlining `apache-arrow` so the page needs no import-map / no CDN), copies the MVP
  wasm module + worker, vendors the matching `parquet` extension, and materializes the
  demo Parquet from `data/feedstock_health.csv`. Output → `build/` (**gitignored**).
- **`wasm-smoke`** serves `build/` over a loopback static host, drives the pre-provisioned
  headless Chromium, **blocks and asserts zero non-loopback requests** (the offline /
  no-backend proof), and asserts the client-side query result. An in-page error (blank
  page, failed wasm, empty result) **fails** the gate — it never passes trivially.

The heavy build output (`build/`, a ~40 MB `.wasm` + `node_modules/`) is gitignored and
reproducible from `build.py`. A fresh clone / CI must run `wasm-build` before `wasm-smoke`
(see DW-G1-2).

## Committed vs generated

| Committed (source) | Generated by `wasm-build` (gitignored) |
|---|---|
| `index.html`, `entry.mjs`, `package.json` | `build/duckdb/duckdb-bundle.mjs` |
| `data/feedstock_health.csv` (the seed dataset) | `build/duckdb/duckdb-mvp.wasm`, `…-mvp.worker.js` |
| `build.py`, `.gitignore`, this README | `build/ext/<ver>/wasm_mvp/parquet.duckdb_extension.wasm` |
| | `build/core_feedstock_health.parquet`, `build/index.html` |

## Version pins

`@duckdb/duckdb-wasm 1.33.1-dev57.0` (DuckDB engine `v1.5.4`) + `esbuild 0.28.1`, pinned in
`package.json`. `DUCKDB_VERSION` in `build.py` / `index.html` selects the vendored
extension path and must stay in lockstep with the duckdb-wasm pin (a drift makes the
build's extension fetch fail loudly).
