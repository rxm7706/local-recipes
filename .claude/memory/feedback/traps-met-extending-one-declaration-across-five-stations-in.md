Traps met extending one declaration across five stations in one change (2026-11-26, branch exit-domains-2026-11-26, PR #2396; steward 142.1, mason 43.1, herald 56.1, scribe 36.1, atlas 54.1): (1) docs-currency judges a page by the commit date of each source it lists, so detectors-ci is green before the commit and red after it: once a source file is committed, re-read every page that lists it, bump verified:, commit, then run docs-currency again, because a page that lists a re-stamped page goes stale in turn (fifteen pages here, one of them only by that second hop). (2) A new test module under steward's tests/ must be named by a row of spec-pyforge-steward/oracle-map.md or test_oracle_map reds in the live lane. (3) A memlog entry that is not worded 'Surface reconcile ...' counts as a decision: scribe's test_spec_not_behind_memlog reds until a later commit changes SPEC.md, so word a companion or bookkeeping note as a Surface reconcile, or render the Spec after it. (4) Each station's contract test reads its exit constants as integer literals (mason, steward by AST; scribe scans typer.Exit; atlas scans returns), so replacing a literal with a call into pyforge.core breaks that station's contract suite; bind with a meta-test instead. (5) A story spec of type feature needs a flag: block or flag-exempt: value or flag_gate_check reds. (6) Removing a word from a user-facing message can red a test that pins it (atlas test_admission pins 'FastMCP'); grep the tests for the old wording before editing a message. (7) A cross-station source edit is co-governed: spec-pyforge-core governs every station's src/, and spec-pyforge-unifying-strategy co-governs some atlas tests; append a Surface reconcile naming the path to each Spec spec-surface names. (8) Running several stations' same-named test modules in one pytest call fails collection with 'import file mismatch'; run each station's file in its own call.
