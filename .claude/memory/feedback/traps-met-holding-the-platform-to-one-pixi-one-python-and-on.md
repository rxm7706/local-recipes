Traps met holding the platform to one pixi, one Python and one nodejs (2026-11-27, PR #2417; steward Epic 149): (1) pixi lock re-solves a record only when the lock no longer satisfies its spec. The station packages' pixi-build host records kept Python 3.14.7, 3.14.8, 3.15.0 and 3.15.2 under a host spec of python >=3.14 after every environment moved to 3.14.10; neither a [workspace.build-variants] python nor a host spec of * moved them. Only an exact host pin (python = "3.14.10.*" in each [package.host-dependencies]) did. (2) The same rule left the cpython and python-gil metapackages at 3.14.7 beside python 3.14.10. Move a lagging package without pixi update by locking once with it pinned in a feature, then once with the pin removed: pixi keeps what it locked. target-version-check's message names this fix. (3) Read the lock's build records, not only its environments: '- conda_source: <pkg>[hash] @ <path>' records carry host_packages, and they install and run their own Python whenever an environment builds that package. (4) marp-cli 4.2.3 requires nodejs >=24.4.1,<25, so a single nodejs for every environment is on the 24 line (24.22.3) even though the operator's range allows 26. A 26.13.1 declaration fails to solve in pyforge-guild on osx-arm64. (5) A runtime re-solve drags in unrelated moves: the nodejs change took bmad-module-skill-forge 2.2.0 to 12.0.0 in bmad-suite-full, playwright to 1.65.1 in mcp-host (off the estate's <1.65 line) and pnpm to 12.24.0. Diff the lock per environment and platform after every solve, and hold each unrelated mover at its locked version for one lock, then release it. (6) An environment can carry nodejs (or Python) only because a package pulls it in, with no feature naming it; six did. When declaring a runtime once, give every environment that locks it the declaring feature, found from the lock, not the manifest. (7) The pixi-build cache in a checkout is .pixi/bld (25 GB here, with its own Python interpreters), plus .pixi/artifacts-v0 and .pixi/meta-v0; there is no .pixi/build. Old conda-build work directories collect under .pixi/envs/local-recipes/conda-bld/<recipe>_<timestamp> (2,924 of them, 982 MB) and hold the Python each recipe was built for; delete those, keep the noarch/ and linux-64/ channels. (8) conda-forge's gcloud wrapper exports CLOUDSDK_PYTHON as the environment's own python, so the Python bundled inside google-cloud-sdk is installed but never runs; gcloud info --format='value(basic.python_location)' shows which one does. (9) Tests that compare an environment's whole feature list (bmad-suite-full, pyforge-marshal) red when a runtime feature is added; and a herald test compared two copies of the nodejs pin, which became one declaration. (10) A memlog line on another station's Spec must cite spec-pyforge-steward:CAP-153 with the colon; ad_citation_check reds the space form as a bare CAP. (11) Regenerating docs/reference/environments.md also rewrites docs/map.yaml's derivation stamp, which needs its own memlog line and scoped stamp on spec-pyforge-doctor.
