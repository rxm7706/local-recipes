Traps met building the remaining test and CI levers in one change (2026-11-27, PR #2446; steward Stories 117.35 to 117.40): (1) A durations file written on a laptop does not balance CI shards: the runner took 1.6 times the laptop's seconds for steward's live half, 0.46 times a stale file's for its package half (274 tests were missing from it), and two to three times for herald's built-site tests. Write the files from the runner's own times: on a scratch branch that never merges, add --durations=0 --durations-min=0 to each sharded job's PYTEST_ADDOPTS, dispatch the workflow, sum each test id's setup, call and teardown lines, and dump with sort_keys=True, indent=4 and no trailing newline (tests/durations/README.md). A probe that prints only tests over a threshold cannot score a split, because every shorter test counts at the average. (2) Score a new file offline before trusting it: pytest-split's duration_based_chunks cuts contiguously in collection order, and each && pytest segment of a task splits on its own. Simulated that way, the probe's measured shards were reproduced to the second; on the runner a shard's wall time is about 0.71 s per summed second plus about 1.2 ms per test. (3) Sharding a suite renames its coverage reports, and the gate's pixi task must read the same glob as the CI gate job: the preflight selects lanes by matching the gate job's command to a pixi task, and steward's test_preflight_ci and test_preflight_selection and herald's test_preflight_pages_lane fail with "Extra items" until the two match. (4) A newly sharded station's pixi feature needs pytest-split. The local preflight runs every suite unsharded, so only CI sees the missing plugin: "unrecognized arguments: --splits --group --durations-path" (exit 4). pixi lock at the pinned 0.85.0 added only pytest-split to that environment, and environment.yaml did not move. (5) pytest refuses a mark on a fixture ("Marks cannot be applied to fixtures"); when a module fixture runs a CLI once for several tests, put the skipif on each test. (6) A test file that starts an interpreter per call (about 57 ms each) can run its script in-process: exec the compiled code in a fresh __main__ module with the call's cwd, environment, argv, stdin and sys.path swapped in, map SystemExit to the exit code, and restore sys.modules after. Keep a parity test that holds each kind of result to a real subprocess's exit code, stdout and stderr. (7) PyYAML's pure-Python loader dominated ci_surface_gates.py --check (109 parses, 2.68 s). Parsing each distinct text once with CSafeLoader under functools.lru_cache, and returning copy.deepcopy of it, took the check to 0.17 s; diff every output against the old code before trusting a cache. (8) The image jobs' disk step deleted 31 GB of toolchains in 136 to 163 s on a runner that had 87 GB free. Read the free space first (df --output=avail -BG /) and delete only below 50 GB. (9) In docs/governance/ci-surfaces.yaml a job's default dispatch fragment is dispatch || (pause && inner), which lets every manual run past the job's own input check: a bare manual Platform CI run ran both portability smokes (they fail at helm install with no image digest), air-gap-parity and build-platform-image. An opt-in job takes dispatch: pause-only, which renders (dispatch || pause) && inner. The render keeps one row per (workflow, job) and the last row wins, so mark every row of the job, then check with a bare gh workflow run. (10) Measure on the runner before claiming a saving: refreshed laptop durations barely changed steward's live split, and only the runner probe showed the imbalance.
