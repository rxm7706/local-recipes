Traps met rebalancing herald's live shards and fixing its Pagefind flake (2026-11-27, PR #2438; herald 63.1 and 64.1, steward 117.33): (1) Measure a job's setup before trimming its environment. Lint-types' 52 s pixi setup is 15 s downloading a 1.82 GB cache and 33 s untarring about 4.3 GiB in 105,000 files. pyforge-guild sits inside pyforge-foundry-full (hardlinked), so splitting it out saves nothing. The parts mypy does not need that come off cleanly (full Chromium, build) are about 13%, 5 to 8 s, and the job was not what PRs wait on, so it was left. (2) Laptop durations mislead. Herald's built-site tests cost two to three times on the runner: locally the three shards took 22, 23 and 25 s, on CI 45, 38 and 68 s. To get runner times, push a scratch branch that only adds --durations=0 --durations-min=0.3 to the job's PYTEST_ADDOPTS, start it with gh workflow run pyforge-station-tests.yml --ref <branch> (workflow_dispatch runs every station job; minutes are free on this public repo), and never merge it, so main's docs pages never see the flag come and go. (3) A shard's wall is its longest serial chain. A test that takes a builder module's module fixture for one check joins that fixture's xdist group, and a build of its own then runs after the group's build on the same worker. test_site_builders_share_a_worker.py's test_no_grouped_test_starts_a_build_of_its_own now reds that by AST; Story 60.1 had fixed two modules and missed test_site_shell.py. (4) Estimate a split offline from runner times. Collect the lane's items and their xdist_group marks with a trylast pytest_collection_modifyitems plugin passed to pytest.main, give grouped ids the @<group> suffix, run pytest-split's duration_based_chunks, then sum runner times per shard and per group. A shard's tests take about max(largest group, total / workers). (5) More shards help less than the sums suggest: each herald live job pays about 40 s before its tests (checkout, pixi setup, docs-site install). Four shards took the slowest job from 108-111 s to 94-97 s, with 53 to 59 s of tests where the sums said about 40. (6) Renaming a test means moving its durations-file key: run its module at the lane's worker count with --store-durations into an empty temp path, then move only those keys. Fix the done story specs that name it (Story 53.3's Verification did). (7) A flake that recurs is root-caused, not retried. Story 62.1's differences_report turned 'one path differs' into '68,024 bytes then 0'. Pagefind 1.5.2's service mode can answer writeFiles before its writes are on disk, and Starlight's close() then kills the child. A Node probe of createIndex, addDirectory, writeFiles and close, run 32 at a time with every core busy, left a file empty in 6 of 192 runs; 1.6.0 (fix PR #1272) wrote every file whole in 768 runs. npm update <pkg> moves an in-range transitive package in the lock and nothing else. (8) Load generators on Python 3.14: multiprocessing defaults to forkserver and fails without a __main__ guard. Use subprocess.Popen of python -c 'while 1: pass', and kill each by its handle. pkill -f '<pattern>' killed the shell running it (exit 144), because the pattern was in its own command line. (9) A broken && chain can run a later cd .. from the worktree root: git rev-parse --short A B fails with 'Needed a single revision'. Use absolute paths and subshells, (cd x && ...). (10) Copying a feed back: a filter like grep -v '63-1' also drops another station's older keys (steward's 63-1-...) and reads as a mismatch. Filter on the exact new keys. (11) pr-preflight -- --keep-going reports every red lane in one run instead of stopping at the first.
