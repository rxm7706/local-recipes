Traps met running doctor's speed-budget test alone in the preflight (2026-11-27, PR #2423; steward Story 117.30): (1) Find what the test lacks before choosing a fix. Doctor's budget test already judged CPU, not wall time, and already ran as its own pytest call after its lane's xdist segment; what it lacked was time away from the preflight's other lanes. Time a lane's parts alone before deciding what runs alone: the whole lane took 47 s, its last segment 12 s, so only the segment runs alone. (2) To run one segment of a task's cmd on its own, split the cmd at && and run each segment as pixi run --frozen -e <env> -- <argv> with the task's own env (its PYTHONPATH decides the paths the coverage JSON names). Refuse a segment that holds shell syntax or a $ expansion, since no shell reads it. Prove the quoting by collecting through the argv path and comparing counts with the task's own run (1,541 and 4 here). (3) A tail that starts only when admission leaves nothing in flight needs no guard against admission while it runs: only the tail can finish, so no lane can become ready. Mutation testing showed the guard was unreachable, so it was removed. Mutate each scheduler line you add and keep only lines a test catches. (4) A new steward test module must be named in planning-artifacts/specs/spec-pyforge-steward/oracle-map.md or test_oracle_map reds, and a bare CAP-n in its docstring reds test_cap_citations until an oracle-map row names the module (the error says to write spec-pyforge-steward CAP-n instead). Both are live-tree tests, so the package half and the new tests' own run stay green: only the full preflight's live half found them. (5) Older preflight tests inject run_lane (a runner that takes a Lane, not a part), and test_preflight_selection pins the --jobs 1 declared order against the real pixi.toml. A scheduling change has to define what a lane-level runner sees (here, one call at the head's turn) and where dependents move (doctor's coverage gate now runs last). (6) A scoped stamp from an earlier PR can leave a path its memlog never named: spec-surface warned drift-presumed on src/platform/compose/mcp-host/Containerfile (Story 148.2, PR #2415) only when this PR moved spec-pyforge-steward's memlog. Name that path in the new memlog line and stamp again. (7) In a fresh worktree, pixi run -e pyforge-guild ruff ... runs the ruff task (scripts/lint_types.py), which rejects file arguments; run .pixi/envs/pyforge-guild/bin/ruff check <file> instead.
