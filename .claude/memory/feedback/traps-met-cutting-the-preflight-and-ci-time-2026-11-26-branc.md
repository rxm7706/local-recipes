Traps met cutting the preflight and CI time (2026-11-26, branch preflight-ci-speed-2026-11-26, PR #2405; steward 117.14 to 117.18, doctor 66.1, herald 58.1, mason 48.1): (1) Measure a lane's work as the CPU seconds its processes used (cpu_seconds in .steward/preflight-runs.jsonl), never as seconds times workers: that product grows with every worker a lane cannot use (herald's site builds run in one xdist group) and hands it more workers on the next run. (2) The docs-site lanes share one mutex, so their chain ends the run: it needs the first turn and a slot as wide as its widest lane. With the turn held but one core in the slot, pyforge-herald-test waited 78 s for a second core. (3) Profile before tuning the scheduler: preflight_ci split every workflow step's command once per lane, about 220,000 shlex.split calls per selection; splitting each once took a herald test from 33 s to 7 s and pyforge-steward-test from 44 s to 33 s. cProfile overstates call-heavy code (it showed 47 of 72 s for a 26 s saving), so confirm with wall time. (4) A cached gate verdict needs more than the tree hash. An independent review of the first verdict-reuse cut found five false-green paths: the same tree under another commit (mason_cfe_surface_check judges commit subjects), no age limit (flag_gate_check reads date.today()), a later red run of the same state ignored, PYTEST_ADDOPTS outside the key, and state outside the tree (loop homes, refs, GitHub answers). Key on commit, tree, base, local day and gate variables, expire it, and let a later red run revoke it. (5) A new steward test module reds three live-tree meta-tests until it is declared: an oracle-map.md row (test_oracle_map and test_cap_citations), a contract.md row for any new environment variable (test_public_contract), and a ROOT_HANDOFF_INPUTS entry in test_station_tests_trigger_map.py for a live_tree test that hands the repo root to code. Run pyforge-steward-live-test before the full preflight. (6) A tests/scripts file runs in three environments. A new test there must skip through the file's existing guard helper: pyforge-ci has no yaml, and test_pyforge_ci_is_stdlib_only.py pins the exact list of libraries each file guards. (7) pyforge steward estate reconcile does more than check environment.yaml: it regenerates docs/how-to/pixi-tasks.md, docs/reference/environments.md and the environment matrix in the unifying-strategy Dream, appends a memlog line to doctor's Spec and scoped-stamps it. That stamp also baselined scripts/detectors.py, which the line did not name; add the memlog line that names it. (8) An apostrophe inside a single-quoted title in a story spec's frontmatter is invalid YAML, and flag-gate-check reports it as flag-missing; double the apostrophe. (9) Touching pixi.toml, pixi.lock, a workflow or a steward module a page cites reds docs-currency for every authored page whose verified date is earlier (nine pages here): re-verify each, set verified to today, name the pages in a memlog line on doctor's Spec, then scoped-stamp it. (10) A PR that changes pixi.lock misses every pixi cache in CI (Lint and types took 171 s against 88 s), so its CI time is not a warm reading.
