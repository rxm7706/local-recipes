Traps met making the guild image's secret scans pass and running doctor's live test on a dispatched run (2026-11-27, PR #2444; steward Story 118.10, doctor Story 71.1): (1) guild-container runs only on a push to main and on a dispatch, never on a pull request, so a pattern added to steward's secret table (Story 118.9's hetzner-api-token, PR #2425) reds main after the merge, on files no pull request touched. tests/scripts/test_guild_image_package_sources_scan_clean.py now runs the image's scan over the shipped package sources and their compiled code on every pull request; when a new pattern lands, run that test, and dispatch the workflow on the branch (gh workflow run pyforge-station-tests.yml --ref <branch>) before merging a change to anything the image ships. (2) PEM base64 wrapped at 64 characters makes every line its own 64-character run, and about one line in eight carries both cases and matches the Hetzner shape. A test key kept in source holds its base64 at 76 a line and wraps it at 64 when the module loads; the PEM bytes do not change. (3) The image scans twice: the build gate reads the sources, and the post-build scan reads __pycache__/ after the container has run. A clean source can still match once compiled: marshal writes a short string as a type byte and a length byte before its text, and for warden's 65-character token set those two bytes plus its 62 letters and digits made a 64-character alphanumeric run. Build such a set at run time (string.ascii_letters + string.digits + "._-"), never as one literal. (4) The compiler folds joined string literals ("-----BEGIN " + "PRIVATE KEY-----") into one constant, so splitting a literal does not hide it from a scan of .pyc files. Format it at load from a name (an f-string over a module variable). (5) A workflow_dispatch checkout of a branch holds only that branch: refs/remotes/origin/main is missing, and a test that runs git merge-base origin/main HEAD fails. Fetch main with --depth=1 and deepen both sides (25, 100, then 400) until git merge-base resolves.
