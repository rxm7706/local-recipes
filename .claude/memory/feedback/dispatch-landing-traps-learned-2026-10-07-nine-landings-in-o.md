Dispatch landing traps learned 2026-10-07 (nine landings in one day). (1) Launch every dispatch with pixi run -e pyforge-guild marshal ...: a bare .pixi/envs/pyforge-guild/bin/marshal leaves python, codegraph and caveman off PATH, the session runs to the end, then verification refuses at MRS-GATE-002 (marshal Story 22.16 fixes this). (2) Land one story at a time on a busy day: concurrent landings collided on scripts/.spec-surface-baseline.json, the flag registry (flags.json, flag-overlays.json, core test_flags.py, platform _SHIPPED_BOOLEANS) and platform-ci-local's fixed ports (marshal 22.18/22.19 and steward 63.7 have landed the heals and the lock). (3) A refused branch is recovered by merging origin/main into it, unioning memlogs and the team-memory index main-first, unioning the flag registry key by key, taking main's baseline, then re-running the land-only dispatch; a verification refusal needs the branch head to move before land-only engages. (4) A hand-landed PR (gh pr merge --merge --subject 'Merge <slug>/<key> into main') skips the bookkeeping: run python -m pyforge.marshal.dispatch_land_finalize <slug> <key> <worktree> --landing-subject ... for the ledger promotion, and add a retros/retro-<station>-<date>.md if the story touched the package pyproject.toml (chain-currency code->retro). (5) A ledger promotion copies every Tier-3 feed key onto main: keep a chain's new keys out of the feed until the chain PR merges, or the promotion lands ledger rows with no epics story (chain-completeness red). (6) A package dependency needs three places: pyproject.toml, root pixi.toml, and the package's own pixi.toml [package.run-dependencies] (pyforge-deps-test; herald boto3, #1915). (7) Until doctor 6.13 and marshal 22.15 landed, any landing whose spec was already done left its epics.md Status at backlog and reddened doctor's epics meta-test on main.
