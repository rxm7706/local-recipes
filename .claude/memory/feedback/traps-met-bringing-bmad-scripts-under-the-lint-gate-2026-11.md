Traps met bringing _bmad/scripts/ under the lint gate (2026-11-27, PR #2434; steward Story 93.2): (1) Five of _bmad/scripts/'s six scripts belong to the BMAD installer: _bmad/_config/files-manifest.csv lists them with their hashes, and an upgrade rewrites them. Never lint, format or edit them. Derive the repository's own set from the manifest (lint_types.bmad_scripts()), never from a hand list, so a new local script is checked and a new installer script is not. (2) Judge a file outside the packages by the estate's rules, not ruff's defaults. Run without a config from a worktree root, ruff reported EXE001, UP035 and ISC004. Under the rules the ten pyforge-* packages share (py314, E, F, W and I, E501 ignored), passed with --config, the TEA generator needed formatting alone. The ten tables are not identical: pyforge-testing-kit lacks the tests/** E402 per-file ignore, so compare target, line length, select and ignore. (3) Prove that a generator's reformat writes the same output: git show origin/main:<path> to a temp file, run it with --repo-root . after the new one, and check that no document moved. (4) Regenerating every TEA matrix also refreshes stations whose fingerprints had gone stale (mason and warden here); take them in the change. Run pixi run -e pyforge-guild docs-github-workflows in the same change. (6) Editing a pixi.toml task description is a shared-surface change. (7) A process started with & inside a foreground Bash call is not tracked, and no notice arrives when it ends.
