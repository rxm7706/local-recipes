Traps met declaring the estate's Python once and moving pixi to 0.85.0 (2026-11-27, PR #2415; steward Epic 148, warden 34.1): (1) An environment whose features name no python resolves whatever its packages allow: pyforge-marshal locked Python 3.15.0 while the other 35 locked 3.14.7, and its suite passed on 3.15 behaviour. Back on 3.14, a dataclass in a module loaded with spec_from_file_location fails ('NoneType' object has no attribute '__dict__') unless the loader sets sys.modules[spec.name] before exec_module. Python is now declared once, [feature.interpreter.dependencies], and target-version-check reds a second declaration, an environment without the interpreter feature, or a lock off the declared version. (2) Taking python out of a feature leaves its docs/governance/pin-policy.yaml hold dangling, and pin_policy_check reds it (dangling-hold). Move the hold to the declaring feature in the same change. (3) A re-solve for a new Python patch moves that build's own requirements (libsqlite, libexpat, zstd, icu) and, through icu, nodejs. An environment where a package pulls nodejs unpinned (bmad-eval-quality in pyforge-steward) took nodejs 22.23.5. Diff the lock per environment and platform before keeping it, and give such a feature the LTS pin >=24.19.0,<27.0,!=25.*. (4) Write the lock with the pixi CI will run. To move pixi: pixi exec --spec pixi=<new> --spec python=3.14 -- python scripts/bump_pixi_version.py <new>, then pixi exec --spec pixi=<new> -- pixi lock. requires-pixi then refuses an older local pixi, so run tasks, the preflight and the push under pixi exec --spec pixi=<new> -- until the machine is updated: the pre-push hook runs the pixi on PATH. (5) bump-pixi-version rewrites registered sites only. Not registered were mason's PIXI_VERSION_RANGE floor (registered now), warden's PIXI_VERSION_RANGE with its ceiling and its contract.md row, test fixtures that fake a pixi version, and the mason package pilot skill's stated pixi version (test_pilot_skills reads it from the lock). Only the full preflight finds them. (6) pixi 0.85.0 deprecates a named platform entry's platform key; write subdir. (7) actions/setup-python cannot read pixi.toml, so .github/actions/setup-estate-python reads the declaration with sed and passes it on, and target-version-check reds any other setup-python step and any step that starts python before its job has an interpreter. The recipe lanes' setup-miniconda python-version is a per-build choice and stays out of it. (8) docs-currency cascades: re-verifying a page moves its date, which stales every page that lists it as a source (enterprise-deployment.md, then air-gapped-mirror-setup.md); a pin-policy.yaml or contract.md edit stales the how-to that cites it. Run detectors-ci after each commit until it is clean; this change re-verified 19 pages. (9) Run the full preflight with -- --keep-going when many lanes may red: stop-on-red hid five red lanes behind the first detectors-ci red. (10) Mason's range test names the pixi its build+ship self-hosting proof last passed on, and that proof is slow-marked and in no lane. Run pixi run -e pyforge-mason pyforge-mason-test-slow (a dry run, no upload) to produce the new evidence before moving the floor. (11) The primary checkout's warden feed lacked Epics 28 to 33. A bare sprint-ledger-sync in the worktree repairs feed-behind-twin keys; copy the repaired feed back after the merge. (12) The session hook reads heredoc text: a capture or commit message that contains the words for an outward push is refused. Write such text with the file tool and pass it by path.
