Attended NKP bring-up on rootless Docker/kind (steward Story 118.1 AC2, 2026-10-31, nic 0.14.0, kind v1.36.1): (1) the rootless blocker is fs.inotify.max_user_instances, not ports -- at the default 128 (charged to the operator's uid for every container) cloudnative-pg, envoy-gateway and metallb-controller crash-loop with 'too many open files'; only the host sysctl counts (inside a privileged kind node sysctl -w is 'permission denied'); net.ipv4.ip_unprivileged_port_start=0 is NOT needed for nic 0.14.0 (kind publishes 6443 alone; the gateway is a MetalLB address on the kind Docker network, unreachable from the host under rootless Docker -- reach it with kubectl port-forward on 127.0.0.1:443 plus curl --resolve). (2) ArgoCD auto-sync never retries a revision whose sync failed (here on the webhooks of the crash-looping controllers); a hard refresh is not a sync -- patch operation.sync on the Application, and set status.operationState.phase=Terminating first when one is stuck Running. (3) Keycloak 26.5 is OOMKilled at 2Gi in its build phase because JDK 21 inside a rootless kind pod logs 'controller memory is not enabled' (host /proc/cgroups has no memory row) and sizes the heap from host RAM; JAVA_OPTS_KC_HEAP=-Xms256m -Xmx1280m as extraEnv in ~/.nic/gitops/<project>/values/keycloak/base.yaml, committed there, fixes it -- the durable fix is upstream NIC's (operator files it). (4) nic destroy prompts "Type 'yes' to confirm" and exits 1 with 'failed to read user input: EOF' under a subprocess; steward deploy nic down passes --auto-approve since Story 118.4. (5) Envoy lowercases response header names (read Location case-insensitively); the landing page's Keycloak client is nebari-system-nebari-landing-spa in realm nebari; gateway-config and httproutes stay OutOfSync-but-Healthy on server-side-apply drift. Full narrative: docs/how-to/host-nebari.md section 'What the attended run looked like'.
