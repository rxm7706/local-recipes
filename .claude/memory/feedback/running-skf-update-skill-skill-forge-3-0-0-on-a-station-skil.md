Running skf-update-skill (skill-forge 3.0.0) on a station skill, learned 2026-11-18 (steward Story 126.5, four skills rebuilt at 0.1.1): (1) _bmad/skf/config.yaml must define sidecar_path (_bmad/_memory/forger-sidecar) or the preflight halts SIDECAR_UNDEFINED; run skf-setup once per machine. (2) Run the workflow from the module copy _bmad/skf/skf-update-skill, not .claude/skills/skf-update-skill: the IDE copy calls skf-build-change-manifest.py baseline-gaps, which the installed helper lacks. (3) Forge data is gitignored, so seed forge-data/<skill>/<version>/provenance-map.json from the tracked package copy with each source_file made relative to source_repo, and add file_entries: [] (skf-hash-content.py refuses a map without the key though the schema calls it optional). (4) Keep scripts_intent: none and assets_intent: none in each station brief and pass --scripts-intent none --assets-intent none to skf-detect-scripts-assets.py in detect-changes Category D: the update stage ignores the brief and otherwise copies cli/, schemas/ and templates/ source into the skill. (5) The workflow writes the new provenance map only to forge data; the tracked package provenance-map.json is that map with source_repo prefixed to each source_file (station meta-tests read repo-root paths). (6) write.md leaves confidence_tier, tool_versions and source_commit stale in metadata.json; set them to the run's facts. (7) Follow with skf-export-skill (AGENTS.md block, .export-manifest.json, the result record via emit --result-dir .claude/skills). (8) Have an independent agent verify the rebuilt SKILL.md against live --help and the source; the tool checks citations, not CLI truth. (9) Three places pin the marshal skill's versioned path and move with its version: the scribe instruction-surface parity test, the station-tests trigger map in .github/workflows/pyforge-station-tests.yml, and marshal-policy.toml. Learned again 2026-11-26 (warden Story 33.3 and mason Story 46.3, both rebuilt at 0.1.2): (10) uv and ast-grep are not on PATH; put .pixi/envs/pyforge-guild/bin first before running any SKF helper. (11) A fresh worktree has neither the sidecar nor forge-data, and the primary checkout may have no sidecar either: run skf-setup's detect and write steps, and skip its ccc step, which edits .gitignore. (12) _bmad-output/.skf-run/ is not gitignored; remove the run folders before committing. (13) metadata.json's source_commit can be older than the tree the last run read; remap citations against the tree the skill was actually built from. (14) Each regeneration adds versioned files that spec-surface governs (under spec-pyforge-unifying-strategy): reconcile and stamp them. (15) Options a parser gains at build time (pyforge.core.cli_output's --json) are invisible to the extractor; document them in the preserved [MANUAL:additional-notes] block. (16) The provenance map holds the API exports only: prose citations are neither pinned by it nor re-checked by any tool when the source moves, so a hand fix to a prose citation is safe and survives a regeneration, but nothing will catch it going stale. (17) Verify a skill check's line-number finding before writing a row: DW-warden-33-3-1 reported two citations one line off that were right.
