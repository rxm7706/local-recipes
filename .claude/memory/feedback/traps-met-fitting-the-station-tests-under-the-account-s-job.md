Traps met fitting the station tests under the account's job limit and cutting three CI jobs' repeated work (2026-11-28, PR #2448; steward Stories 117.41 to 117.44): (1) pytest-split 0.11.0 fails at --splits 1: duration_based_chunks moves to the next group once a group's summed durations reach the per-group share, so with one group a zero-second test after the whole is summed raises IndexError (warden-test, dispatch 46144823146; four other one-shard jobs passed by float luck). Pass pytest-split options only when the job has more than one shard: PYTEST_ADDOPTS: ${{ strategy.job-total > 1 && format('--splits {0} --group {1} --durations-path ...', strategy.job-total, matrix.group) || '' }}. (2) The account runs at most 40 jobs at once across every workflow. Measure it from all runs of one head SHA (actions/runs?head_sha=...): 40 ran at the peak, and the other workflows start about 11 jobs beside a pull request that runs every station, so 29 is the station tests' budget. (3) A matrix read from the changes job (fromJSON(needs.changes.outputs.<x>_groups)) works with the local preflight's CI selection, which runs the changes job's filter step to expand it. Keep that job free of a step if: and of expressions other than github.*: compute in the same filter step by reading back $GITHUB_OUTPUT. A dispatch diffs against the empty tree, so every output is true. (4) The preflight selection understands only matrix.<key> == '<value>' as a step if:. Not every pixi task in a workflow step is a preflight lane (kedro-catalog-check is not); read the journal's selection before claiming a lane moves. When a step moves to another job, check that the new job's trigger paths hold the old one's. (5) Authored docs list workflow files as sources:, so any edit to platform-ci.yml or pyforge-station-tests.yml makes them stale in docs-currency. Read each, fix its text, move its verified: date, and reconcile spec-pyforge-doctor with a memlog line and a scoped stamp. docs-github-workflows with no trigger change rewrites only the stamps in docs/reference/github-workflows.md and docs/map.yaml; revert them. (6) A fixture that installs a pixi environment mid-suite under a lock holds every xdist worker that reaches it: find it from a pytest -v log, timing each [gwN] line against the worker's previous one. Install the environment at setup instead (setup-pixi environments: a b, with a cache-key of its own; a composite action takes them as inputs whose defaults keep the other callers unchanged). The cache entry is written only on a push to main, so the first branch run installs from scratch. (7) The runner's docker stores images in containerd and compresses every layer on export (167 s of the guild image's 345 s). An image that is only run on the runner can be built with --output type=image,name=<tag>,compression=uncompressed and still runs by its name; never do it to an image that is pushed or recorded by ID. (8) Estimate a job with one shard fewer from step times: its overhead (job time less its test step) plus the suite's summed test-step time over the new count. (9) Flip a story to done (epics Status, story spec frontmatter, feed and sprint-ledger-sync, TEA regen) in the last commit before asking to merge; finding it at merge time cost a CI rerun. (10) GitHub auto-merge is off on this repository and main has no required checks, so the app's set_auto_merge cannot wait for green: read the checks once and merge with the marshal subject. (11) The laptop's full preflight is at capacity: 8 cores and 16 threads, lanes holding 14.7 of 16 slots and using 80 % of them, and the same tests taking about 40 % more CPU time from one run to another. Compare runs by their summed lane CPU seconds before blaming code or the scheduler.
