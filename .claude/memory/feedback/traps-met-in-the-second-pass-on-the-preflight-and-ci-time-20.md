Traps met in the second pass on the preflight and CI time (2026-11-26, branch preflight-ci-phase2-2026-11-26, PR #2407; steward 117.19 to 117.22, herald 59.1, doctor 67.1): (1) Herald's site builds now run in a per-process copy of the repository (pages_astro.build_site_dir), so a test must read what its build wrote there (build_site_dir() / "public"), never DOCS_SITE / "public", "build" or ".astro". A fresh CI checkout has none of them, and on a laptop they hold an old build's output, so such a test passes locally while checking nothing; test_no_test_reads_a_build_output_of_the_real_tree now reds it. (2) A test module that imports pages_astro reads the repository through it: steward's trigger map derives reads through imports and asks for a ROOT_HANDOFF_INPUTS row, so keep such a module in the live-tree half. (3) Claude Code exports PYTHONDONTWRITEBYTECODE=1 and the operator's terminal does not. Every lane an agent starts used to compile every module again (marshal's collection 12.8 s, 3.4 s warm); the preflight now drops the variable for lanes, but a timing taken in an agent shell still differs from one taken in the operator's terminal, so say which one you measured. (4) A full run of all 50 lanes is CPU-bound: its floor is the lanes' cpu_seconds over 16 threads (about 3,900 CPU-s, 245 s). Read cpu_seconds from the journal before tuning the scheduler. An xdist lane admitted late gets only the cores free then: the docs-site slot holds the planned share of its widest lane, or herald's live half ran 350 s on 2 workers. (5) In _next_lane, keep the 'needed by a pending dependent' rule ahead of expected seconds and let the seconds only break its ties. Putting seconds first reorders two near-equal lanes by timing noise and reds test_preflight_docs_site_mutex.py::test_the_install_starts_before_herald_s_suite now and then. (6) PYTEST_ADDOPTS reaches every pytest segment of a task. A CI shard's --splits N also splits a small second segment (herald's five integration tests), and duration_based_chunks can leave a group empty, which exits 5; pass --splits 1 --group 1 on that segment. (7) Turning a CI job into a matrix with a step-level if: per part keeps its step list, so tests that read the steps still pass, but nothing then checks the routing. Doctor's test_preflight_mirrors_scripts_suite.py now reds a step whose if: names no declared part, or a part that does not install the step's environment. (8) Concurrency tests that start the second run on a fixed clock need a slow first run (8 s per stubbed call, 33 s a test). Start the second run on the first run's state (the lock's .holder record, or its services up) and the stub can sleep 2 s. The platform-ci-local stub had compared a stand-in's pid with its own, which always differ, so its cross-stop check could never fail; check that a test can fail before trusting it. (9) Mutation tests that derive whole-package facts on every case should cache the per-module analysis by (module, text): doctor's contract module went from 69 s to 16.5 s, with a test that the cache changes no fact. (10) Forcing all 50 lanes with uncommitted probe lines reds detectors-ci and test-ci-meta (spec-surface reads the dirty files) and disables verdict reuse. That is expected in a measurement and does not count against the change. (11) When regenerating docs/governance/preflight-budgets.toml from journals, a red lane has no median: keep its old [lanes] and [work] rows, and keep only comment lines in the header you carry over, or [defaults] is declared twice. (12) The auto-mode permission check refuses gh pr merge when the operator says only 'is green'; it passes once the operator says 'Merge it'.
