Trace, never count: a PRD requirement arrow (FR-n <- CAP-m) is derived from the cited capability's intent and success in the station Spec, never from position or sequence, and it names a defined capability only -- never a Spec Constraint, a Charter clause, an AD or a decision id (spec-one-chain-per-station CAP-5 as amended 2026-10-26; CHAIN-STANDARD section 12). Why: the 2026-09-16/17 folds wrote every arrow by counting (FR-n <- CAP-n on atlas, one CAP per section elsewhere, none on steward and marshal's seed installer), and the detector only checked that a cited number existed somewhere, so 140-odd wrong arrows survived five weeks (marshal 105.1 #2314, atlas 39.1 #2316, #2319, and the 2026-10-26 one-PR fix). How to apply: before writing or reviewing an arrow, open the CAP's block; a run of four or more FRs whose CAP number steps with the FR number while titles share no word is the counting fingerprint (doctor fr-counted-run); a Constraint reaches code through an AD, a visible guarantee becomes a CAP first.
