# Why one chain is a lock, and a fold is mop

This page explains why one Dream, one Spec, one PRD, one spine, and one epic chain per PyForge station is a **minting** rule: append on the living files, and fail an unexempted new folder with `chain-sprawl-check`. It is not a calendar of fleet-wide folds. The operator steps live in [`one-chain-station-ops.md`](../how-to/one-chain-station-ops.md). The checklist those steps obey is [`CHAIN-STANDARD.md`](../governance/spec-one-chain-per-station/CHAIN-STANDARD.md) §§ 3, 7, and 9 (Spec CAP-10).

Dreams and `docs/governance/` stay outside the Diátaxis map. These two pages point at that corpus; they do not replace it.

## Minting holds 1:1

Three of the five planning tiers were already one-per-station (PRD, architecture spine, epics and ledger). Dream and Spec sprawled **by rule**: Dream-first with no gap-closure exemption, `bmad-spec`'s one-folder-per-slug, and Spec → Story before code composed a new Dream plus Spec pair for every effort. Sixty-one Dreams were folded on 2026-08-08. Five weeks later the fleet was back at 171 Dreams and 172 Specs, with 30 Dreams and 33 Specs minted in the week of 2026-09-07 alone.

Consolidation without a minting rule is a treadmill. The 2026-09-17 lock records that fact as policy: 1:1 is kept by Dream-append-first plus `chain-sprawl-check`, every day, on every new effort. A dated section on `docs/dreams/pyforge-<s>.md` **is** a Dream seed under the 2026-09-12 gap-closure ruling, and it stays in that station file.

A second fleet-wide fold campaign would repeat 2026-08-08. The eight station folds (and Mason's living-tier flip) rebase each chain once onto CHAIN-STANDARD. After that, day-to-day is §3: analysis through implementation stays append → memlog → spec → FR ← CAP → story.

## A satellite file is the break

The living station files are `docs/dreams/pyforge-<s>.md` and `spec-pyforge-<s>`. An unexempted `docs/dreams/<other>.md` or `specs/spec-<topic>/` folder is a second chain: a second why, a second CAP namespace, and a second place stories can cite. That is the break `chain-sprawl-check` is built to fail.

On a still-open PR the repair is a rewrite. Move the work onto a dated station-Dream section and a station Spec CAP, then drop the extra file. Once that satellite has merged to `main`, rewrite-in-place is no longer enough; the station needs a mop PR so the living Spec remains the one open contract.

Two requirement namespaces (`FR-n` in PRDs, `CAP-n` in Specs) made the same kind of split inside a station that already had one PRD. The rule that closes it is the Charter's reading: the PRD is the Spec's decomposition, so every FR minted after the rule date cites its source CAP. Stories still cite both ids; they no longer invent FRs that have no CAP.

## The exemption list is closed

A new Dream or Spec folder is allowed only when frontmatter `fold-exemption:` is a value from `docs/governance/guild-roster.json` (`fold_exemptions`). The list is closed:

| Reason | What it names |
|--------|----------------|
| `different-owner` | Work that is not this station's to bind |
| `different-lifecycle` | A document whose life is not the station contract's life |
| `cross-station-seam` | Shared packages such as `spec-pyforge-core` and `spec-pyforge-testing-charter` (marshal-owned; imported by every station; regenerated by the foundry as their own leaves) |
| `governance` | Guild constitutive pages (this rule's own Dream and Spec; a Lexicon amendment cannot be a dated section of a station Dream) |

Adding a fifth string is a governance act on the roster. An ad-hoc exemption in a PR description does not pass the detector. The Guild chain (Charter plus `spec-pyforge-unifying-strategy`) is the ninth chain, not a home for shared code: it serves every Smith and judges none.

## Fold is mop after the lock failed

A fold PR is rebase-shaped cleanup for unexempted satellites that already reached `main`: one station, one PR, branch `fold/<s>`, checklist in CHAIN-STANDARD §7. You run it when minting and `chain-sprawl-check` did not hold. New work still starts as an append. A station that is already 1:1 does not need a "refresh" fold.

Another fleet-wide fold campaign is the 2026-08-08 treadmill again. The lock itself must not become a new `docs/dreams/*.md`, because that file would be a satellite of the Guild Dream that already holds CAP-10. Archived Dreams stay archived; absorbed Spec folders stay pointer plus memlog plus companions; station Dreams stay `specified`; station Specs stay `ready`; `done` ledger rows stay `done`. Precedence is evergreen standard over historical numbering. The record (memlogs, git, companions) survives; derived bodies do not have to.

| Verb | When it applies | What it is not |
|------|-----------------|----------------|
| **lock** | Every new effort | A fold campaign |
| **exemption** | The work cannot live on the station chain | A fifth roster reason invented in the PR |
| **mop** | Unexempted satellites already on `main` | A reset, an un-archive, or a weekly rhythm |

## Where the steps live

Run lock, rewrite, mop, parallel serialization, and the `pyforge-guild` environment from [`docs/how-to/one-chain-station-ops.md`](../how-to/one-chain-station-ops.md). CAP-10's success signal is harness-neutral: a new effort adds a section, a CAP, and a Story; an unexempted satellite file does not land; a mop PR's §7 checklist is green. The ritual can be run from the Guild Dream, this Spec, and CHAIN-STANDARD without a vendor store or a vendor dispatch path.
