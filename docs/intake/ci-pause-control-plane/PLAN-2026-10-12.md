# CI pause control plane

**The ask.** Every GitHub Actions surface (CI) and every local twin of one should carry a pause
switch the operator controls, with one place to see what is paused, since when, by whom, why,
and until when. Today the switches exist for a handful of jobs, were set by hand, are documented
only in workflow comments, are invisible to local tooling, and nothing judges them.

**The chain.** This drop is pre-triage. The work enters the repo the way every effort does:
a dated entry on each owning station Dream (`docs/dreams/pyforge-<station>.md`), `bmad-spec`
mints the CAPs, a numbered Story lands in that station's `epics.md` with its ledger row, and a
tracked story spec precedes code. Section 7 names the appends; nothing outside this drop changes
until they exist.

## 2. Gap analysis

**Control gaps**
- G1. Coverage: 2 pause variables cover 3 jobs; ~25 jobs across 13 active workflows have none.
- G2. No master switch: pausing all CI means disabling 20 workflows in the UI, one by one, leaving no trace in the repo.
- G3. Two mechanisms with different visibility: repo variables (readable via `gh`) and the UI's `disabled_manually` state (only in the Actions API; no reason, no owner).
- G4. Naming is inconsistent: `PAUSE_*` (pause) vs `PLATFORM_CI_*` (opt-in) vs `ACTIONS_ENABLED` (dead). Nothing reads a convention, so nothing can check one.
- G5. Local twins ignore CI pauses: `platform-ci-local` runs the container stage regardless; `pr-preflight` evaluates workflow `if:` rules but cannot resolve `vars.*` (its documented rule: "anything the reader cannot evaluate runs the lane and says so").

**Visibility gaps**
- G6. No single registry: the only documentation of a pause is a comment next to its `if:`.
- G7. No status view: no CLI, dossier tile, `fleet-picture` section or doctor source reports which surfaces are paused, since when, why, or until when.
- G8. No expiry: a pause set "to save runner time during the burn-down landings" (2026-10-04) has no review date; nothing nags.
- G9. Landing evidence is blind: a story merges with container builds paused and the PR body, landing journal and promotion record do not say so (steward Dream line ~1239: an image rot "nothing caught").
- G10. Stuck surfaces are invisible: a `waiting` deployment, a cancelled-run streak, a disabled workflow — none has a detector.

**Hygiene gaps**
- G11. `ACTIONS_ENABLED=false` is dead state that planning docs still cite as evidence.
- G12. Six workflows are disabled with no recorded reason, four of them (the staged-recipes-linter family) likely retirable, two (`test-all`, `kedro-viz-publish`) likely "paused until a decision".
- G13. Paused expensive surfaces (the two Containerfiles) never run, so they rot unnoticed until resume day.

## 3. Design principles

1. **One declared source.** A tracked registry in `docs/governance/` lists every pausable surface, its switch, owner, reason, `paused_since`, `review_by`, cost class and local twin. The same pattern as `guild-roster.json`'s `session_denials` and `rulesets/protected-refs.json`: governance declares, code renders and checks, a drift is a loud failure.
2. **Every surface is pausable, by the same mechanism.** Repo variables with a strict naming convention; generated `if:` fragments; the GitHub "disable workflow" button becomes drift except for rows marked `retired`.
3. **Pause is not delete.** Pausing a job leaves it `skipped`, which GitHub counts as passing for required checks; retiring a workflow deletes the file and the registry row records why.
4. **Manual runs ignore pauses.** `workflow_dispatch` already overrides the platform-ci pauses; the convention extends to every workflow — an explicit dispatch is operator intent.
5. **Local parity reports first, then honors.** Local twins print what CI would skip and why, honor it by default for parity lanes (`pr-preflight`), and never for explicit manual stages (`platform-ci-local`, `guild-image-build`), with a documented override either way.
6. **Outward writes stay operator-owned.** `gh variable set` on this repository is an outward write under § Policy; the write path demands `--yes`, journals, and captures to team memory. Agents read; the operator flips.
7. **Detectors judge; they never gate a gate silently.** The registry check is a repo-scope detector in `detectors-ci` (flag-exempt `detector-or-gate`); the drift/stuck view is an advisory doctor source.
8. **A paused expensive surface gets a canary.** Weekly, cost-bounded, so rot shows up before resume day.

## 4. Target architecture

### 4.1 Registry — `docs/governance/ci-surfaces.yaml`

One row per surface. Seeded with today's state. Schema (YAML; a JSON Schema ships beside it):

```yaml

conventions:
  pause_prefix: PAUSE_          # true => job skips on push/PR/schedule
  enable_prefix: ENABLE_        # true => job runs on push/PR/schedule (default off)
  master: PAUSE_ALL_CI          # true => every non-dispatch job skips
  dispatch_ignores_pauses: true
grandfathered_names:            # kept, mapped here; new switches follow the prefixes
  - PAUSE_CONTAINER_BUILDS
  - PAUSE_PLATFORM_CONTAINER_BUILDS
  - PLATFORM_CI_AIR_GAP_PARITY
  - PLATFORM_CI_GKE_PORTABILITY_SMOKE
  - PLATFORM_CI_OCP_PORTABILITY_SMOKE
  - PLATFORM_CI_PUSH_REGISTRY
surfaces:
  - id: station-tests.guild-container
    workflow: .github/workflows/pyforge-station-tests.yml
    job: guild-container
    kind: ci-job                 # ci-job | workflow | scheduled | local-stage
    cost: high                   # low | medium | high (high => canary required)
    gate: false                  # true => pausing removes a merge gate; the write path warns

    switch_class: pause
    state: paused                # live | paused | opt-in-off | paused-manually | retired
    paused_since: 2026-10-04
    paused_by: operator
    reason: save runner time during the burn-down landings

    local_twin: pyforge-steward-guild-image-build   # pixi task; never paused, prints banner
    canary: weekly
  - id: platform-ci.container
    workflow: .github/workflows/platform-ci.yml
    job: container
    kind: ci-job
    cost: high
    switch: PAUSE_PLATFORM_CONTAINER_BUILDS
    switch_class: pause
    state: paused
    paused_since: 2026-10-09
    reason: container builds paused while the mcp-host sidecar env settles
    review_by: 2026-11-01

    kind: ci-job
```

Every active workflow gets a `workflow`-kind row (`switch: PAUSE_<WORKFLOW_SLUG>`); every
`cost: high` job and every job that already has a switch gets a `ci-job` row. `workflow_call`
reusables inherit their caller's row. `workflow_dispatch`-only workflows get a row with
`switch: null` so the inventory is complete.

### 4.2 Switch convention and the generated gate

- `PAUSE_<WORKFLOW_SLUG>` — slug is the file stem, upper snake (`PAUSE_LINT_TYPES`, `PAUSE_SUBSTRATE_NIGHTLY`, `PAUSE_DETECTORS`).
- `PAUSE_<WORKFLOW_SLUG>_<JOB_SLUG>` — job-level, only where the registry has a `ci-job` row.
- `ENABLE_<...>` — opt-in surfaces (default off). Existing `PLATFORM_CI_*` names are grandfathered and mapped.
- `PAUSE_ALL_CI` — master. Evaluated first in every gate.

Each job's `if:` becomes the conjunction of the master, the workflow switch, the job switch (if
any) and the job's existing condition, with the `workflow_dispatch` carve-out:

```yaml
if: >-
  github.event_name == 'workflow_dispatch' ||
  (vars.PAUSE_ALL_CI != 'true' && vars.PAUSE_LINT_TYPES != 'true' && <existing condition>)
```

The fragment is rendered from the registry by a script (`scripts/ci_surface_gates.py --render`)
and checked by the same script in detectors-ci (`--check`): a job whose `if:` does not contain
its rendered fragment is a finding; a `vars.X` in any workflow that no registry row names is a
finding; a registry row whose job has no gate is a finding. GitHub Actions has no workflow-level
`if:` and no YAML anchors in workflow files, so the per-job fragment is the only shape that works;
the render/check pair is what keeps 25 hand-copied fragments honest.

Alternative considered and not recommended: one `gate` job per workflow reading a single JSON
variable `CI_PAUSES` (`{surface: {reason, since, review_by}}`) and every other job
`needs: gate`. It carries metadata in the switch itself and is one `gh variable get` to read, but
it adds a job to every workflow (runner minutes on every run), changes every `needs:` graph,
interacts badly with the existing `changes` jobs, and the metadata belongs in the tracked
registry anyway. Operator decision Q1.

### 4.3 Local twins

- `pyforge/steward/preflight_ci.py` gains a `vars` resolver. Source order: `.steward/ci-vars.json`
  (a snapshot written by `steward ci vars --refresh`, carrying `fetched_at`; stale after 24 h),
  else the registry's declared `state`, else today's rule (unknown ⇒ run, say so). A lane whose
  gate resolves to skip because of a pause is journaled as `skipped: paused in CI (PAUSE_X since
  DATE, review_by DATE)` — never silently.
- `pr-preflight` prints a banner listing paused lanes and honors them by default (parity with the
  CI that will judge the PR); `--ignore-ci-pauses` runs them anyway. The pre-push hook shows the
  same banner.
- `platform-ci-local` and `pyforge-steward-guild-image-build` are explicit manual runs: they print
  the banner and run every requested stage. They are the operator's way to exercise a paused
  surface on demand; the canary (4.6) is the scheduled way.

### 4.4 Visibility — `pyforge steward ci status`

Read duty; table and `--json`. Columns: surface, kind, cost, switch, declared state, live value,
`paused_since`, `review_by` (and days left / overdue), owner, last green run, verdict. Verdicts:
`live`, `paused`, `opt-in-off`, `paused-manually`, `retired`, `drift` (declared ≠ live),
`stuck` (waiting deployment > 24 h, or ≥ 5 consecutive cancelled runs), `overdue`
(`review_by` passed). Sources: the registry, `gh variable list --json`,
`gh api repos/<r>/actions/workflows` (state), `gh run list --workflow` (last runs),
`gh api .../runs/<id>/pending_deployments`. Unauthenticated probes fail open — the duty reads
`gh api rate_limit` first and refuses an `ok` at a 0/60 rate limit (known pitfall).

Consumers of the same JSON:
- Herald dossier: a "CI surfaces" tile (`docsite/content/dossier.yml`), one line per paused or stuck surface.
- `fleet-picture`: a "CI pauses" section pasted verbatim like the rest.
- Marshal landing: `dispatch_land` writes `ci_pauses_at_merge: [...]` into the landing journal and one PR-body line ("CI paused at merge: container, container-dbgpt, guild-container"); `landing_evidence` and `promotion.py` read it so a promotion record says which gates did not run.

### 4.5 The write path — `pyforge steward ci pause|resume`

```
pyforge steward ci pause <surface-id|switch> --reason "…" --review-by 2026-11-01 [--yes]
pyforge steward ci resume <surface-id|switch> [--yes]
```

Without `--yes`: a dry run that prints the `gh variable set` it would run, the registry diff and
the scribe capture text. With `--yes`: runs `gh variable set` (outward, operator-only per
§ Policy), updates the registry row (`state`, `paused_since`, `reason`, `review_by`, `paused_by`),
appends `.steward/ci-pauses.log`, and runs `scribe capture --type project`. Pausing a row with
`gate: true` (`detectors`, `lint-types`, station tests) prints a red warning naming the merge gate
it removes and requires `--i-am-removing-a-merge-gate`. The GitHub UI's disable button is not a
sanctioned path: a `disabled_manually` workflow without a `paused-manually` or `retired` row is a
`drift` finding.

### 4.6 Canary for paused expensive surfaces — `.github/workflows/ci-canary.yml`

Weekly (`schedule: 0 4 * * 0`) plus `workflow_dispatch`. Reads the registry, runs the pixi task
behind every `cost: high` row whose state is `paused` (today: the guild image build and the
platform container build, docker engine only), once. Gated by `PAUSE_CI_CANARY` like everything
else. Its last green run feeds the `stuck` verdict for paused rows (`canary_last_green > 14 d`).
Budget: two image builds a week instead of two on every PR.
