Install

Copy the folder skills/warden/scan into .agents/skills/warden-scan, .claude/skills/warden-scan. Claude Code's documented project skill path is .claude/skills/, and Round 0 (Claude Code 2.1.311, 2026-10-29) found it does not read .agents/skills/. Devin's is .agents/skills/; the tool matrix does not list .claude/skills/ for Devin. bmp install is not built; this page is not an install button.

The rolling pages-site release carries warden-scan.zip with warden-scan.zip.sha256 beside it while the marketplace flag is on for that deploy. The zip holds the warden-scan/ folder with SKILL.md, steps.md, listing.yaml and references/ when the skill has one. Check and unpack it where both files were downloaded: sha256sum -c warden-scan.zip.sha256 && unzip warden-scan.zip -d .claude/skills/, and the same with -d .agents/skills/.

For Claude Code, a plugin install exposes the skill (Round 0, 2026-10-29, run on @warden/scan with the claude plugin CLI at local scope, not in an interactive session): /plugin marketplace add <checkout>/docs/foundry/marketplace, then /plugin install warden-scan@pyforge-bmad-marketplace, lists it as warden-scan:warden-scan. Use the plugin or the folder copy in one project, not both; with both, the skill is likely listed twice (not tested). For Codex, .agents/plugins/marketplace.json stays a discovery pointer until its Round 0 row runs, and the folder copy above is the install.

Steps

Run these from the project you want to scan. Verified 2026-10-21 against warden scan --help and the tools on the verifying host. Each version below is what that tool's --version printed on that host on 2026-10-21.

Before you start. pyforge-warden 0.1.0 and pyforge-core returned HTTP 404 on PyPI, conda-forge, and SelfExplainML on 2026-10-21. Step 1 waits on those packages, and no published command produces the compliance report in its place. Steps 0 and 2 run today; they produce probes, not a report.

0. Install the published tools

  • deptry 0.25.1: pip install deptry (PyPI deptry) or conda install -c conda-forge deptry.
  • osv-scanner 2.4.0: conda install -c conda-forge osv-scanner, or the binary from the osv-scanner GitHub release page.

1. Scan with the station command (waits on pyforge-warden)

When pyforge-warden is on your PATH:

warden scan .

The same argv through dispatch:

pyforge warden scan .

Environment self-check, not a scan:

warden scan --doctor

--doctor exits 0 or 2, never 1. Verified: warden scan --help lists --doctor on scan.

2. Probe the engines, and stop there

deptry --version
osv-scanner --version

deptry and osv-scanner are not a warden verdict. The warden CLI calls deptry and osv-scanner scan --offline itself. Do not paste their output into a review as a warden verdict.

3. Stop

Nothing else runs from this runbook.
