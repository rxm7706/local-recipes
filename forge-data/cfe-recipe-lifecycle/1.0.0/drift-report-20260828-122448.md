undercounts due to its own known limitation, not because 28 real exports are missing or
divergent. Does not affect the CLEAN verdict — the decisive check (Script/Asset Drift, below)

## Design Notes: Non-Drift Findings From This Story's Own Regression Pass

Recorded here for completeness (the audit tool itself found none of these — they surfaced from
running the regression suite against the compiled package, described fully in `evidence-report.md`
and `SKILL.md`'s own Design Notes):

1. **`scripts/cross-shims/install_name_tool`** — a genuine Slice-2 functional asset
   (`local_builder.py` hardcodes its path at runtime), not named in slice-map.md or the brief.
   Ported and tracked as `file_type: "asset"` in `provenance-map.json`; included in the 28
   tracked files audited above (all unchanged/byte-identical).
2. **`scripts/github_updater.py` + `scripts/recipe-generator.py`** — Slice 1's own canonical
   scripts, ported byte-identical purely as cross-slice TEST-FIXTURE siblings so
   `test_recipe_updater_interpreter.py`'s repo-wide interpreter-resolution drift guard can run
   unmodified. Also tracked in `provenance-map.json` (28 total includes these); also
   unchanged/byte-identical in this audit, since they were copied from the same live source this
   audit compares against.
3. **Hardcoded `Path(__file__)` parent-hop-count path arithmetic** in `_path_guard.py`,
   `_paths.py`, `gen_yml_reference.py`, `mapping_manager.py`, `vulnerability_scanner.py` resolves
   one directory level short of the real repo root at this package's deeper nesting — a real
   BEHAVIORAL divergence risk (confirmed for relative-path invocation of `recipe_editor.py`), but
   NOT a file-content or export-signature difference, so it does not and should not appear as
   drift in this audit's structural/file-hash checks above (which correctly show those five files
   as byte-identical/unchanged — they genuinely are byte-identical; the divergence is in what the
   identical bytes DO when run from a different directory depth, which this audit's static
   comparison does not and cannot measure). Proven and documented in
   `test_slice2_equivalence.py`'s own module docstring and test suite; not patched (pre-existing,
   campaign-wide CFE debt per `_paths.py`'s own Story 5.5 docstring, out of this story's scope).
   `local_builder.py`'s own `_repo_root_candidate()` (walk up for `pixi.toml`, hardcoded
   parent-hop only as a last-resort fallback) is a working, depth-independent pattern already
   present in this same compiled package — the natural template for a future fix to the other
   5 scripts. **This is the finding that drove `campaign-state.yaml`'s `equivalence: "green" →
   "stale"` correction (patched post-review)** — this CLEAN static audit alone does not
   establish behavioral equivalence for every invocation pattern.
