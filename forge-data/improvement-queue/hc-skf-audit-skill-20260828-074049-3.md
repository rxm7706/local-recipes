## Finding
`skf-detect-docs.py compare-hashes` raises an uncaught `ValueError` (crashes, exit 1 with a
traceback) instead of a graceful `fetch_failed` record when a `doc_sources[].url` entry is not
a valid URL scheme (e.g. a local filesystem path).

## Expected
Per step-doc-drift.md's own Rules ("Graceful failure — if doc fetching fails for any URL, mark as
`fetch_failed`, do not block the audit"), a malformed URL should be caught and classified as
`fetch_failed` with a `reason`, not crash the script.

## Actual
`uv run skf-detect-docs.py compare-hashes metadata.json` against
`cfe-recipe-generation`'s metadata.json (whose one `doc_sources` entry is a local ephemeral-worktree
path recorded as `url`) raised: `ValueError: unknown url type: '/home/.../README.md'`, an
uncaught traceback from `urllib.request.Request()`.

## Evidence
- `src/skf-audit-skill/references/step-doc-drift.md:24` — "Graceful failure — if doc fetching
  fails for any URL, mark as `fetch_failed`, do not block the audit."
- `src/shared/scripts/skf-detect-docs.py:297` (`_fetch_and_hash_reason`) — constructs
  `urllib.request.Request(url, ...)` with no try/except around URL-scheme validation before the
  network-error handling begins.

## Impact
The step's documented graceful-failure contract could not be exercised as written; had to skip the
doc-drift check manually and note the crash in the audit report rather than getting a clean
`fetch_failed` row.

## Suggested Fix
In `skf-detect-docs.py`'s `_fetch_and_hash_reason`, catch `ValueError` from
`urllib.request.Request()`/`urlparse` (invalid scheme) alongside the existing network-error
handling and return a `fetch_failed` reason (e.g. `"invalid-url-scheme"`) instead of letting it
propagate.
