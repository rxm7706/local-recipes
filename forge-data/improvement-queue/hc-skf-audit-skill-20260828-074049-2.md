## Finding
structural-diff.md §1 always invokes `skf-structural-diff.py {provenanceMap} {extractionSnapshot}`
with no documented branch for degraded mode, where `{provenanceMap}` was never loaded.

## Expected
A degraded-mode-aware branch (e.g. "if degraded_mode, baseline is an empty export set / skip §1
export-diff and rely on §4b Script/Asset Drift only") so the step's own instructions cover the
mode init.md §4 explicitly supports.

## Actual
Running §1 with an empty `{"entries": []}` baseline (the only well-formed input available in
degraded mode) makes every currently-extracted export read as "added" — technically a real diff
result, but not meaningful drift, and the step has no guidance on how to present or caveat this.

## Evidence
- `src/skf-audit-skill/references/structural-diff.md:37-43` — "Run one comparison over the
  baseline provenance map (from step 1)..." assumes it exists.
- `src/skf-audit-skill/references/init.md:130-137` — degraded mode is a fully supported,
  documented outcome of step 1 §4, with no forward reference to how step 3 should adapt.

## Impact
Had to hand-derive a caveat (excluding the "added" bucket from severity scoring, documenting why in
the report) rather than following documented step guidance for this combination.

## Suggested Fix
Add a short degraded-mode note to structural-diff.md §1: skip (or clearly flag as
non-drift-scoring) the export-level diff when `degraded_mode` is true, since there is no
compile-time baseline to diff against; rely on §4b's file-hash comparison as the primary signal
when `file_entries` are available.
