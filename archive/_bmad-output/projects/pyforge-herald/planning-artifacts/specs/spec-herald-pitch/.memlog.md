# Decision Log

decision: Dream consolidates Herald's Four Moments framework (Pitch, Progress, Success, Operations) as Tier 0 Vision, Tier 1 reusable capabilities (Design-Code-Bridge, Deckcraft, Video-Scripts, Modernist-Identity), and Tier 2 Moment 1 Feature Orchestration across 9 pyforge stations.

decision: Use Layered Tier Model (Option 4) to separate Vision (overarching), Capabilities (reusable), and Features (orchestrations).

capability: CAP-1 — Design-Code-Bridge Framework — Automate round-trip between Claude Design and Code with etagged conflict detection. Seed Design projects, allow human visual iteration, pull etagged updates to Code, zero manual file transfers.

capability: CAP-2 — Deckcraft Framework — Generate editable PowerPoint from Markdown sources using python-pptx + design tokens. Decks are programmatically generated yet manually editable. Deliverable format: .pptx files tracked in src/pptx/.

capability: CAP-3 — Video-Scripts Framework — Extract narration scripts mechanically from Design speaker notes, feed to bmad-manticore. Four hard gates: Outline → Cut Plan → Graphics Beats → Final Render. No fabricated product demos.

capability: CAP-4 — Modernist-Identity Framework — One visual language across all PyForge surfaces (decks, dashboards, docs, exports, videos). Design system: Archivo typography, palette (light #f3f2f2, ink #201e1d, red #ec3013/#c22a10), grid, zero corner radius, flush-left labels.

capability: CAP-5 — Six-Act Deck Framework — Canonical structure for all 21 pitch decks. Acts: Cover (hook), I (friction), II (insight), III (solution/mechanics), IV (real-world location), V (future/vision), VI (action/CTA), Appendix (personas). ~28 slides per deck, 90KB+ class, inline SVGs, full depth.

capability: CAP-6 — Multi-Format Export — Single Design prototype → 6 artifact formats per station: Design protos (.dc.html), Markdown (marp), PPTX (editable), Narration scripts (.md), Infographics (SVG), Video scripts (.mp4 via manticore). Tracked + regenerable separation.

capability: CAP-7 — Station-Specific Customization — 9 pyforge-station content set (Marshal, Warden, Atlas, Mason, Steward, Scribe, Genesis, Doctor, Herald). Per-station: Thesis, pain point, solution pillars, ecosystem vision, personas. Framework stays constant; content changes.

constraint: Single Design prototype per station is the immutable source of truth (etagged, tracked in git as .dc.html). All code-side artifacts derive from it.

constraint: Aggressive optimization: Track 144 files (design protos 3-4 each, markdown 5-8, PPTX 2-4, narration 1-2, infographics 0-1). Gitignore intermediate build artifacts (fragments.json, dist/, assets/, .mp4) as regenerable.

constraint: No fabricated demos. All screen recordings in video output are real, never AI-generated UI. Manticore receives real footage + real narration only.

constraint: Etagged safety on all Design ↔ Code transfers. Conflicts detected, never silent overwrites. Design cloud + pull model, not live sync.

constraint: Narrator identity + voice bible derived from published transcripts (WPM, speech patterns). Blacklist enforced by script linter.

non-goal: New deck-authoring infrastructure. Design-code-bridge already proven on 7 decks.

non-goal: New export backends. Deckcraft handles PPTX; deck-export CLI handles HTML/others.

non-goal: New video pipeline. Manticore is upstream; this effort feeds narration scripts to it.

non-goal: Real-time collaboration. Design cloud handles iteration; pull model is explicit and conflict-safe.
