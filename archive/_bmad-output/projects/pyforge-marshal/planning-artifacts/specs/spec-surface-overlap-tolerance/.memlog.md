- (capability) CAP-1 -- a file governed by multiple specs is drift-presumed/drift only when NONE of its co-governing specs' memlogs name the change, not when any single one doesn't. Success: a synthetic fixture with two specs governing the same file, one with a memlog explicitly naming it, produces zero finding against EITHER spec for that file.
- (capability) CAP-2 -- a genuinely unreconciled change (no co-governing spec's memlog names it) is still caught exactly as today. Success: the existing spec-surface-check test suite's single-owner drift/drift-presumed fixtures all still pass unchanged; a new multi-owner fixture where NEITHER spec's memlog names the file still produces a finding.
- (constraint) Never weakens the coverage half (ungoverned check) -- only the drift half's per-spec independence changes.
- (constraint) pyforge-doctor owns the code (pyforge.doctor.sources.chain), pyforge-marshal owns the contract (spec-regenerable-factory CAP-3) -- cross-station surface claim, doctor records the incoming claim in its own memlog before code lands, per established convention.

- (non-goal) Not a redesign of spec-surface-check's coverage half or its allowlist mechanism.
